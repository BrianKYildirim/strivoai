<objective>
Ship UI-SPEC Surface A: the pre-bundle browser gate that turns today's white screen into a controlled, readable message (XDEV-01).

Purpose: every other capability check in this phase runs inside the bundle. If the bundle fails to parse or fails to evaluate — which is exactly what the confirmed `localStorage` module-scope throw and the `getOrInsertComputed` incident both produce — nothing inside it can speak. D-08 requires a guard that runs first and depends on nothing.
Output: an ES5 inline guard with two distinct fallbacks, a static supported-browsers page, a boot handshake in `main.tsx`, a syntax guard test, and a five-project Playwright proof.

Scope guard: the styled in-app capability gate (Surface B, D-08b) is plan 03-11. This plan owns only what must run before the bundle.

Shared-file ordering (`src/main.tsx`): plan **03-09** is in the SAME wave (4) and also declares `src/main.tsx`. The two edits target **disjoint regions** and are safe in either order — this plan appends a boot handshake immediately AFTER the `createRoot(...).render(...)` call at the bottom of the file; 03-09 rewrites the polyfill import block at the TOP of the file. Neither may reformat, reorder, or reflow the other's region. `execute-phase`'s intra-wave `files_modified` overlap check will force these two plans to run sequentially rather than in parallel, so the wave-4 parallelism implied by the wave number does not apply to this pair. If you are executing this plan and find 03-09's polyfill barrel import already present at the top of `src/main.tsx`, that is expected — leave it untouched.
</objective>

<threat_model>
- **The guard becoming the failure.** An inline script that itself uses modern syntax throws a SyntaxError in the very browser it exists to serve, producing the identical white screen with extra steps. Mitigation: a static-source syntax guard test that rejects `const`, `let`, arrow functions, template literals, optional chaining, nullish coalescing, `class`, spread, destructuring, `for...of`, shorthand properties and any `import` inside the inline block. This is enforced by a test, not by review.
- **Misdiagnosis as a trust failure.** Showing "your browser is unsupported" to a user on a slow connection is worse than showing nothing — it drives them away permanently over a transient condition. Mitigation: two strictly separate triggers with distinct copy and distinct testids; A2's copy explicitly names a slow connection or a recent update as the likely cause and offers reload, not an upgrade demand.
- **A guard that fights the app.** If the guard paints over `#root` or is never removed, a successfully booted app renders behind a permanent overlay. Mitigation: `#browser-gate` is a SIBLING of `#root` so React never clears it and it can be removed deterministically; `main.tsx` removes it immediately after render; a Playwright MutationObserver assertion proves it never had a paint on a successful boot.
- **Privacy and fingerprinting at the gate.** A pre-bundle script is the perfect place to accidentally beacon device data before any consent or auth exists. D-08 rule 4 forbids it. Mitigation: no network request, no storage read or write, no cookie — asserted by the source guard (no `fetch`, no `XMLHttpRequest`, no `sendBeacon`, no `localStorage`, no `sessionStorage`, no `document.cookie`, no `navigator.sendBeacon`).
- **Clickjacking / injection surface.** The guard writes into the DOM. If any of its copy were interpolated from `location` or a query parameter it would be an XSS sink in the one place with no framework escaping. Mitigation: all copy is static literal text set via `textContent`-equivalent means; no `innerHTML` with interpolation, no value read from `location`, and the source guard asserts it.
- **SPA route shadowing the static page.** `vercel.json`'s catch-all rewrite would serve `index.html` for `/supported-browsers.html` if the file were missing, producing a bundle-dependent page for a bundle failure. Mitigation: the file lives in `public/` (static files win over rewrites on Vercel) and a Playwright assertion confirms the served document is the static page, not the SPA shell.
- **Regression to the current white screen.** If `main.tsx` ever stops setting the boot flag, A2 fires on every successful load after 8 seconds. Mitigation: the OT-3 Playwright assertion (no guard element ever painted on success) runs on all five projects inside the gate.
</threat_model>
