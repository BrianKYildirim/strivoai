# Phase 03 — UI Design Contract

> Visual and interaction contract for cross-device reliability and compatibility. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase is a reliability phase, but it defines real, novel user-facing surfaces. It does **not** redesign any feature. It owns six contract areas:

1. **Unsupported-browser experience** (XDEV-01) — an ES5 pre-bundle guard plus a styled in-app capability gate.
2. **User-facing error taxonomy** (XRUN-06) — client-side categories layered on the existing frozen 13-code server taxonomy.
3. **Extended-wait and recovery states** (XRUN-03, XRUN-04, XRUN-05) — honest lifecycle stage, no fabricated progress.
4. **Stale-bundle recovery** (XDEV-07) — a silent happy path plus one visible loop-guard fallback.
5. **Responsive and touch correctness** (XDEV-05, XDEV-09) across all 11 audit surfaces.
6. **Stripe checkout open latency** (operator requirement) — lock and extend the shipped instant-open behaviour.

Everything else — feature layouts, result views, navigation structure, billing surfaces, marketing pages — is preserved byte-for-byte unless a reproduced device-specific defect (D-23) requires a change.

**Scope guard.** Phase 01, 01.1 and 02 artifacts are read-only. No contract here may be satisfied by editing `ai_call_telemetry`, its migration, or any Phase 02 in-flight file.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui, existing project installation |
| Preset | `style: default`, `base: radix`, `baseColor: slate`, `cssVariables: true`, `prefix: ""`; no generated preset code (legacy `components.json`) |
| Component library | Radix primitives through `@/components/ui` (49 components installed) |
| Icon library | Lucide React |
| Font | Inter through `font-sans`; `system-ui, -apple-system, BlinkMacSystemFont, Segoe UI, sans-serif` fallback |
| Motion | Framer Motion; `tailwindcss-animate` |
| Theme | `next-themes`; dark is the default (`:root, .dark`), light is `.light` — both defined in `src/index.css` |

Implementation rules:

- Reuse existing `Button`, `Card`, `Dialog`, `Alert`, `Badge`, `Progress`, `Skeleton`, `Textarea`, `Input`, `Select`, `Label`, and Sonner toast. **Install no new component and no new registry block.**
- Use semantic Tailwind tokens only: `bg-background`, `bg-card`, `bg-secondary`, `bg-muted`, `text-foreground`, `text-muted-foreground`, `text-primary`, `text-destructive`, `border-border`, `border-input`, `ring-ring`. No hardcoded hex or named Tailwind palette colors in any Phase-3 surface.
- Preserve the existing dark/light token mappings, `--radius: 0.75rem` (12px), and shadcn focus-ring and disabled treatments.
- Every Phase-3 surface must render correctly in **both** themes. Contract acceptance is per-theme.

### The one hardcoded-color exemption

The ES5 pre-bundle guard in `index.html` (§ *Surface A*) is the **only** place hardcoded colors are permitted, because it must survive a total stylesheet or font failure and runs before any token is guaranteed to exist. Its palette is a frozen mirror of the dark-theme tokens and may not drift:

| Guard value | Mirrors token | Hex |
|-------------|---------------|-----|
| Background | `--background` dark `0 0% 0%` | `#000000` |
| Foreground | `--foreground` dark `0 0% 100%` | `#FFFFFF` |
| Muted text | `--muted-foreground` dark `0 0% 60%` | `#999999` |
| Accent / link | `--primary` dark `357 100% 68%` | `#FF5C64` |
| Border | `--border` dark `0 0% 15%` | `#262626` |

No other Phase-3 surface may hardcode a color for any reason.

## Spacing Scale

Declared values (must be multiples of 4). Matches the Phase 01.1 scale — do not introduce a parallel scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, inline badge padding |
| sm | 8px | Stage-row internal gap, minimum gap between adjacent tap targets |
| md | 16px | Mobile card padding, banner padding, ES5 guard body rhythm |
| lg | 24px | Blocked-capability card padding, stage-list vertical rhythm, mobile page gutter at ≥640px |
| xl | 32px | Desktop card padding, full-page fallback vertical rhythm |
| 2xl | 48px | Major section breaks inside the waiting surface |
| 3xl | 64px | Full-page fallback top/bottom breathing room at ≥768px |

Exceptions:

- **44px minimum tap target** (height and width) on every interactive element inside AI flows, checkout, auth, onboarding, dashboard and navigation. Not a multiple of 4 by design — it is the WCAG 2.5.5 / Apple HIG floor and the repo already encodes it as `min-h-11`.
- **Safe-area insets** use `env(safe-area-inset-*)`, which is device-supplied and therefore exempt from the scale.
- The ES5 guard uses only 16px, 24px and 32px (hand-authored inline styles; no scale utilities available).
- Existing `--radius: 0.75rem` (12px) is unchanged.

## Typography

Exactly four phase-scoped sizes and two weights. Existing headings on surfaces this phase does not edit are **not** normalized.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Meta / stage label / helper | 14px | 400 | 1.4 |
| Body / explanation | 16px | 400 | 1.65 |
| Card heading | 20px | 600 | 1.2 |
| Full-page fallback heading | 28px | 600 | 1.2 |

Typography rules:

- Weight 400 for all explanatory copy, stage labels, and helper lines. Weight 600 for headings and CTA labels only.
- The 28px display size is reserved for the two full-page controlled-failure surfaces (ES5 guard, stale-bundle loop-guard fallback). It must not compete with marketing display type and must never be used inside a card.
- The ES5 guard uses `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif` — Inter may not have loaded and must not be assumed.
- **iOS input-zoom rule (XDEV-05):** every `input`, `textarea` and `select` trigger renders at **≥16px below the `md` breakpoint**. iOS Safari auto-zooms and reflows the page when a focused form control is under 16px. Confirmed live defects at HEAD:
  - `src/components/ui/input.tsx` — already correct (`text-base ... md:text-sm`). **Preserve.**
  - `src/components/ui/textarea.tsx` — bare `text-sm` (14px). **Must become `text-base md:text-sm`.**
  - `src/components/ui/select.tsx` `SelectTrigger` — bare `text-sm` (14px). **Must become `text-base md:text-sm`.**
- Numeric readouts use `tabular-nums` so width does not jump.
- Locked copy strings preserve punctuation, capitalization and character-for-character content, including the U+2026 ellipsis where specified.

## Color

The 60/30/10 split uses existing semantic tokens and must hold in both themes.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `background` — dark `hsl(0 0% 0%)`, light `hsl(0 0% 100%)` | Page background, waiting-overlay scrim base, full-page fallback background |
| Secondary (30%) | `card` — dark `hsl(0 0% 5%)`, light `hsl(0 0% 98%)`; `secondary` — dark `hsl(0 0% 10%)`, light `hsl(0 0% 94%)`; `muted` — dark `hsl(0 0% 15%)`, light `hsl(0 0% 92%)` | Blocked-capability cards, degraded banner, stage rows, restore notes, skeletons |
| Accent (10%) | `primary` — dark `hsl(357 100% 68%)`, light `hsl(357 100% 55%)` | See reserved list below |
| Destructive | `destructive` — dark `hsl(0 84.2% 60.2%)`, light `hsl(0 84.2% 50%)` | Terminal failure only |

Accent reserved for — and nothing else:

1. The **single** currently-active lifecycle stage indicator and its label.
2. The indeterminate activity indicator on the waiting surface.
3. The primary recovery CTA fill (`Reload Strivo`, `Try again`, `Retry now`, `Sign in`).
4. Keyboard focus rings (`ring-ring`).

**Destructive is reserved for terminal failure only.** These states are explicitly **not** destructive and must never use `destructive` color, a red icon, or an `alert` role:

- unsupported / degraded browser (a limitation, not a failure)
- extended wait past any threshold
- client transport timeout that degraded to polling
- realtime-to-polling fallback
- stale-bundle detection and the silent auto-reload
- run-not-found after a stale run id

Destructive is permitted **only** for: lifecycle state `failed`, lifecycle state `refunded`, a failed payment, and the stale-bundle loop-guard fallback (the app genuinely cannot render).

**No emerald.** `UniversalAnalyzing` currently hardcodes `emerald-500` / `emerald-400` for completed steps. Within Phase-3-owned surfaces, a completed stage uses `text-muted-foreground` plus a `CheckCircle2` icon at `text-muted-foreground` — completed work recedes so the accent stays on the one active thing. This removes the hardcoded palette color from this phase's surfaces. Emerald usage on surfaces this phase does not edit is out of scope.

**Color is never the sole cue.** Every degraded, blocked, waiting and failed state pairs its color with (a) text and (b) a Lucide icon.

Contrast floor: all Phase-3 copy meets 4.5:1 in both themes. `text-muted-foreground` verifies at 8.6:1 (dark) and 5.7:1 (light) against `background`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Reload Strivo` (stale-bundle fallback) · `Try again` (retryable failure) · `Retry now` (offline) · `Sign in` (session expired) · `See supported browsers` (capability gate, secondary) |
| Empty state heading | `We couldn't find that analysis` |
| Empty state body | `That link may have expired. Start a new analysis when you're ready.` |
| Error state | Server failures use the frozen 13-code table in `src/lib/analysisError.ts` — unchanged. Client failures use the 9-code table in § *Client Error Taxonomy* below. |
| Destructive confirmation | None. This phase introduces no destructive action and no confirmation dialog. It explicitly **forbids** adding a cancel affordance that would abandon a Merit-charged run without a refund path. |

### Forbidden copy

The following must never appear in any Phase-3 surface:

- Bare `Something went wrong.` or `An error occurred.` with no next step. Every message states what happened **and** what the user can do.
- Any estimated time remaining, any countdown, any `%` complete, any `usually takes N seconds`.
- The words `crash`, `exception`, `stack`, `null`, `undefined`, `token`, `payload`, `500`, `502`, `529`.
- Any provider or infrastructure name: `Anthropic`, `Claude`, `Supabase`, `Postgres`, `Deno`, `Vercel`, `Stripe` (except where Stripe is the user-meaningful subject, e.g. `secure checkout`).

### Leak guard (XRUN-06 — machine-checkable)

Rendered user-facing text on every Phase-3 surface must not match:

```
/\b(TypeError|ReferenceError|SyntaxError|RangeError|Cannot read|is not a function|is not defined|undefined|NaN|PGRST\d*|22P02|23505|42501|ECONN|ETIMEDOUT|Deno|node_modules|chunk-[A-Za-z0-9]+\.js|at\s+\S+:\d+:\d+)\b/i
```

This assertion runs against `document.body.innerText` on each blocked, degraded, waiting and failed state, in every Playwright project. Any new user-facing string must originate from a frozen exported table — never from `error.message`, never from a response body, never from a stack.

## Surface A — ES5 Pre-Bundle Guard (XDEV-01, D-08a)

Inline in `index.html`, before `<script type="module" src="/src/main.tsx">`. ES5 only, no dependency, no Tailwind, no token, no icon font, no `const`/`let`/arrow/template-literal/optional-chaining. Inline styles only.

Renders into a `<div id="browser-gate">` that is a **sibling of** `#root`, so React never clears it and it can be removed deterministically on successful boot.

### Two distinct fallbacks

The guard has two triggers with two different messages. Conflating them is a contract violation — telling a user on a slow connection that their browser is unsupported is wrong.

**A1 — Capability failure (deterministic, immediate).** The required-API probe fails.

| Field | Copy |
|-------|------|
| Heading | `Strivo can't run in this browser` |
| Body | `Your browser is missing features Strivo needs. Update it to the latest version, or open Strivo in the current Chrome, Safari, Firefox or Edge.` |
| Link | `See supported browsers` → `/supported-browsers.html` |
| Footer line | `Already up to date? Reload the page.` — `Reload the page` is an `<a href="/">` |
| testid | `browser-gate-unsupported` |

**A2 — Boot watchdog (heuristic, 8000ms).** `window.__strivoBooted` was never set within 8000ms of `DOMContentLoaded`. This is the white-screen-on-parse-failure case.

| Field | Copy |
|-------|------|
| Heading | `Strivo didn't finish loading` |
| Body | `This can happen on a slow connection or just after an update. Reload to try again.` |
| Link | `Reload` → `<a href="/">` |
| Footer line | `Still stuck? See supported browsers.` → `/supported-browsers.html` |
| testid | `browser-gate-boot-timeout` |

### Guard rules

1. `/supported-browsers.html` is a **static file in `public/`**. It must not be an SPA route — the bundle is the thing that failed.
2. `src/main.tsx` sets `window.__strivoBooted = true` and removes `#browser-gate` immediately after `createRoot(...).render(...)`. Neither fallback may be visible for any frame after a successful boot.
3. Neither fallback may render if the app booted. Neither may render simultaneously.
4. The guard performs no network request, reads no storage, and sets no cookie.
5. `#browser-gate` carries `role="alert"`. Do not also set `aria-live` (redundant with `role="alert"`).
6. The guard must not suppress `#root`; if the app later boots successfully the guard removes itself rather than fighting for the viewport.

### Guard layout

| Property | Value |
|----------|-------|
| Container | `position: fixed; inset: 0; display: flex; align-items: center; justify-content: center; padding: 24px; background: #000000; color: #FFFFFF; font-family: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif; z-index: 2147483647` |
| Inner | `max-width: 512px; text-align: center` |
| Heading | `font-size: 28px; line-height: 1.2; font-weight: 600; margin: 0 0 16px` |
| Body | `font-size: 16px; line-height: 1.65; color: #FFFFFF; margin: 0 0 24px` |
| Link | `color: #FF5C64; text-decoration: underline; display: inline-block; min-height: 44px; line-height: 44px` |
| Footer line | `font-size: 14px; line-height: 1.4; color: #999999; margin: 24px 0 0` |

No animation, no spinner, no logo image (assets may also be unreachable). Text only.

## Surface B — In-App Capability Gate (XDEV-01, D-07, D-08b)

Runs after boot, using the design system. Produces one of three tiers.

| Tier | Meaning | UI |
|------|---------|-----|
| `supported` | All required capabilities present | No UI. Zero visual difference. |
| `degraded` | App boots; one or more capabilities required by AI flows or checkout are missing | Marketing, auth, dashboard, history, billing **read** all remain fully usable. AI and checkout entry points are blocked in context. Session banner shown once. |
| `unbootable` | Handled entirely by Surface A | — |

The exact required-API set is planner-owned (CONTEXT § *Claude's Discretion*). This contract fixes only the **tier mapping** the UI keys off:

| Capability group | Blocks | Example probes |
|------------------|--------|----------------|
| Core language + module support | everything (Surface A) | dynamic `import()`, `Promise`, `Object.fromEntries` |
| Document extraction | AI flows only | `Worker`, `structuredClone`, `Map.prototype.getOrInsertComputed` (or its polyfill), `ArrayBuffer.prototype.transfer` |
| Streaming + realtime | AI flows only | `ReadableStream`, `TextDecoderStream`, `WebSocket`, `EventSource` |
| Payment embedding | checkout only | third-party iframe + storage access sufficient for the embedded payment element |
| Persistent session | auth degraded warning | `localStorage` write-read round trip inside a `try/catch` |

**Degraded is never a full-page takeover.** The user keeps navigation, keeps their results, keeps their plan.

### B1 — Session banner

Appears once per browser session, on the first authenticated page load in `degraded` tier. Rendered inside the app shell directly under the navbar, in normal document flow (never `position: fixed` — it must not eat mobile viewport).

| Field | Value |
|-------|-------|
| Copy | `Some Strivo features are turned off in this browser.` |
| Link | `See what's affected` → opens B4 detail |
| Surface | `bg-secondary`, `border-border`, 16px padding, 14px/1.4 copy at `text-foreground` |
| Icon | Lucide `Info` at `text-muted-foreground`, 16px |
| Dismiss | Icon-only `X` button, 44×44 hit area, `aria-label="Dismiss"`; dismissal persists for the session only |
| Role | `role="status"` (polite — not an interruption) |
| testid | `capability-degraded-banner` |

Never `destructive`. Never a toast (a toast would auto-dismiss before it is read).

### B2 — Blocked AI entry point

Replaces the behaviour, not the layout, of every AI start CTA (Resume Analysis, LinkedIn Grader, Career Compass, Recruiting Lens, Interview Prep).

The CTA renders as a real `<button aria-disabled="true">`, **not** `disabled`. A `disabled` button is removed from the tab order and announces nothing, so the user gets a dead control with no explanation. `aria-disabled` keeps it focusable and announced.

| Field | Value |
|-------|-------|
| CTA appearance | Existing label, existing size, `opacity-60`, `cursor-not-allowed` |
| CTA behaviour | Click/Enter/Space returns early. **No run created, no Merit reserved, no request issued.** Focus moves to the explanation card heading. |
| CTA wiring | `aria-describedby` points at the explanation card |
| Explanation heading | `Analysis isn't available in this browser` |
| Explanation body | `This browser is missing features Strivo needs to run an analysis. Update your browser, or open Strivo in the current Chrome, Safari, Firefox or Edge. Your saved results are still available here.` |
| Explanation action | `See supported browsers` — `Button variant="outline"`, min 44px height |
| Surface | `Card` with `bg-card border-border`, 24px padding, `role="note"` |
| Icon | Lucide `MonitorX`, 20px, `text-muted-foreground` |
| testid | `capability-blocked-analysis` |

### B3 — Blocked checkout entry point

Same mechanics on Pricing CTAs, `PricingTable` subscribe, and the top-up trigger.

| Field | Value |
|-------|-------|
| Explanation heading | `Checkout isn't available in this browser` |
| Explanation body | `This browser is missing features our payment provider requires. Update your browser, or open Strivo in the current Chrome, Safari, Firefox or Edge to change your plan. Your current plan is unchanged.` |
| Explanation action | `See supported browsers` — `Button variant="outline"` |
| testid | `capability-blocked-checkout` |

**Hard rule:** in `degraded` tier no Stripe session, PaymentIntent, or checkout dialog may be created. The block happens before any network call.

### B4 — Capability detail

A `Dialog` listing, per affected area, what is unavailable in plain language. No API names, no probe names, no version strings in the user-visible list.

| Field | Value |
|-------|-------|
| Title | `What's affected in this browser` |
| Body intro | `Strivo checked what this browser supports. These areas need a newer browser:` |
| List item shape | `{Area} — {one plain sentence}` e.g. `Resume Analysis — this browser can't read documents the way Strivo needs.` |
| Footer | `Everything else, including your account, your saved results and your billing, works normally.` |
| Close | `Close` |
| testid | `capability-detail-dialog` |

## Surface C — Client Error Taxonomy (XRUN-06)

The server taxonomy is **frozen and unchanged**: the 13 codes in `src/lib/analysisError.ts`, mirrored byte-identically from `supabase/functions/_shared/analysis-error-taxonomy.ts`, plus the `getSafeStreamErrorMessage()` chokepoint. Phase 3 adds **no** server code and rewrites **no** server copy.

Phase 3 adds a sibling closed set of nine **client-side transport and platform** categories that never reach the server taxonomy. These live in a new frozen table alongside the existing one.

| Code | User-facing copy | Retryable | Recovery affordance | Visual |
|------|------------------|-----------|---------------------|--------|
| `CLIENT_OFFLINE` | `You're offline. We'll keep trying — your analysis is safe.` | yes (automatic) | Auto-retry on `online` event; secondary `Retry now` | `bg-secondary`, `WifiOff` icon, **not** destructive |
| `CLIENT_REALTIME_DEGRADED` | `Live updates aren't available right now. We're checking for your result every few seconds.` | n/a (informational) | none — the system already recovered | 14px `text-muted-foreground` inline note. **Never a toast. Never an error.** |
| `CLIENT_CHUNK_LOAD_FAILED` | `Couldn't finish updating Strivo. Reload once more, or close this tab and open strivoai.net again.` | yes (user) | Primary `Reload Strivo` (cache-busting) | Full-page fallback, `destructive` icon permitted |
| `CLIENT_STORAGE_BLOCKED` | `Strivo can't save your session in this browser. Turn off private browsing or allow site data for strivoai.net, then sign in again.` | no (user must act) | Primary `Sign in`; link `See supported browsers` | `Card`, `ShieldAlert` icon, **not** destructive |
| `CLIENT_BROWSER_UNSUPPORTED` | Uses Surface B copy verbatim (B2 / B3) | no | `See supported browsers` | Surface B |
| `CLIENT_SESSION_EXPIRED` | `Your session expired. Please sign in and try again.` *(existing locked string — reuse, do not restate)* | no | Primary `Sign in` | `Card`, `LogIn` icon |
| `CLIENT_UPLOAD_FAILED` | `We couldn't upload your file. Check your connection and try again — no credits were used.` | yes (user) | Primary `Try again` | Inline error under the upload control, `destructive` text |
| `CLIENT_RENDER_FAILED` | `We couldn't display this analysis` / `Something went wrong showing your results. Your analysis may still be safe — refresh to reload it.` *(existing `AnalysisErrorBoundary` copy — locked, unchanged)* | yes | Existing `Try again` + `Refresh page` | Existing boundary fallback |
| `CLIENT_UNEXPECTED` | `Something didn't load correctly. Reload the page to continue — your saved work is unaffected.` | yes (user) | Primary `Reload Strivo` | `Card`, `AlertTriangle` icon, `destructive` icon permitted |

Taxonomy rules:

1. **Fail closed.** Any unrecognized client condition maps to `CLIENT_UNEXPECTED`. It never falls through to raw text.
2. **Retryable is a property of the code, not the caller.** A `Try again` primary CTA renders **only** when `retryable === true`. Terminal codes must not offer a retry that will deterministically fail again.
3. **One error surface at a time.** A client code and a server code must never render simultaneously. Server terminal state wins.
4. **`CLIENT_REALTIME_DEGRADED` is not an error.** It must not set an error state, must not colour anything destructive, must not fire a toast, and must not block the waiting surface. It is a muted informational line only.
5. **Merit truth in copy.** Any client-side failure that occurred before a Merit reservation says `no credits were used`. A failure after reservation says nothing about credits — the server refund path owns that message. Never guess.
6. Every string above is exported from a frozen table with an exhaustive unit test, in the same shape as `ANALYSIS_ERROR_CODES`.

## Surface D — Waiting, Extended Wait and Recovery (XRUN-03, XRUN-04, XRUN-05, D-20, D-21)

`src/components/UniversalAnalyzing.tsx` is the shared waiting overlay for all five AI features. At HEAD it violates D-21 in four ways and must be corrected.

### D0 — Confirmed contract violations at HEAD

| Violation | Location | Required change |
|-----------|----------|-----------------|
| Fabricated progress bar — `95 * (1 - exp(-elapsed / tau))`, driven by wall clock | `UniversalAnalyzing.tsx` L83-128 | **Delete.** Replace with an indeterminate indicator carrying no completion semantics. |
| Fabricated numeric readout — `{Math.round(progressPercent)}%` | L400-411 | **Delete.** No percentage may be shown. |
| Fabricated ETA — default subtitle `This usually takes about 20 seconds` | L33 | **Delete.** No estimated time, ever. |
| Timer-derived step advancement — `currentStep` from the progress curve | L112-116 | **Delete.** Steps advance only from server lifecycle state or observed stream content. |

### D1 — The Honest Progress Rule

> A stage may be marked `active` or `done` **only** from (a) the server's lifecycle state for the run, or (b) content actually observed on the stream. **Never** from elapsed time, and never from a client-side guess.

When neither source is available, render a single indeterminate row reading `Working on your analysis` with no checklist and no progress indicator. Do not guess. Do not show a step list you cannot substantiate.

### D2 — Lifecycle stage → copy

Derived from the 11-state ledger (`analysis_jobs.state`, mirrored in `useAnalysisRun.LifecycleState`). `{subject}` is per-feature.

| `generating` | `Analyzing with AI` | yes |
| `validating_output` | `Checking the results` | yes |
| `saving` | `Saving your analysis` | yes |
| `completed` | `Analysis complete` | brief, then the result |
| `retryable_failed` | — | error surface, `Try again` offered |
| `failed` | — | error surface, no retry |
| `refunded` | — | error surface + `Your credits were returned.` |

`{subject}` per feature:

| Feature | `{subject}` |
|---------|-------------|

### D4 — Extended-wait thresholds

Measured from run start. A client timeout may **never** declare failure (D-20).

| Threshold | Behaviour | Copy added |
|-----------|-----------|------------|
| 0–45,000ms | Normal waiting surface | — |
| ≥ 45,000ms | Append reassurance + reveal background affordance | `Still working. You can leave this page — we'll save your result when it's done.` |
| ≥ 120,000ms (client transport timeout) | Client abandons the direct request and **degrades to polling `get-analysis-run-status` at 2,500ms** until a terminal state. The surface must not change to an error, must not turn destructive, must not offer retry as primary. | `Taking longer than expected. Your analysis is still running on our servers and we're checking on it.` |
| Terminal server state | Only now may failure be shown | Server taxonomy copy |

At the 45,000ms threshold, reveal a secondary `Button variant="ghost"` labelled **`Continue in the background`**. Activating it dismisses the overlay, restores body scroll, returns the user to the app, and leaves the run active — recovery restores it via the stored run id. This is required at ≥45,000ms and must **not** appear before it.

`Continue in the background` is **not** a cancel. No affordance may abandon a Merit-charged run.

### D5 — Realtime → polling fallback (XRUN-04)

When the realtime channel fails or drops and the hook falls back to polling, show `CLIENT_REALTIME_DEGRADED` as a 14px `text-muted-foreground` line beneath the stage list. The waiting surface is otherwise unchanged. No toast, no colour change, no interruption. If realtime later recovers, the line is removed silently.

### D6 — Recovery states (XRUN-03)

| State | Trigger | Contract |
|-------|---------|----------|
| **R0 — Restoring** | Route mounts with a stored or URL run id, resolution pending | Show a neutral skeleton with `Restoring your analysis` at 16px `text-muted-foreground`. Never a blank screen, never an error, never a "not found". Must resolve into R1/R2/R3 within **2,000ms**. |
| **R1 — Active run restored** | Server reports a non-terminal state | Waiting surface mounts **at the server's current stage** — never restarted at step 1. A one-time `role="status"` note above the stage list: `Picked up where you left off.` It clears on the next stage change. |
| **R2 — Completed result restored** | Server reports `completed` and completion happened while unmounted | Render the result directly. **No re-analysis, no Merit charge.** A muted note above the result: `This analysis finished while you were away.` Persists until navigation; no dismiss control. |
| **R3 — Run not found** | Server returns 404 / `FILE_NOT_FOUND` for the stored id | Clear the stored id, return to the feature's input state, show the empty-state copy: heading `We couldn't find that analysis`, body `That link may have expired. Start a new analysis when you're ready.` **Muted, not destructive** — this is almost always a stale key, not a failure. |
| **R4 — Reconnect** | `online` fires after `CLIENT_OFFLINE` | `role="status"` banner `Back online. Checking your analysis…` then resolves into R1/R2/R3. Banner auto-clears on resolution. |

**One-click integrity, visible (XRUN-01, XRUN-02).** While a run is in flight, every start CTA for that feature is `aria-disabled="true"` with `aria-busy="true"` on the form. A rapid second click must produce **no visible second surface** — no second overlay, no second toast, no flicker. A deliberate Elite re-run remains available **only** from the explicit re-run control after a terminal state, never from the disabled start CTA.

## Surface E — Stale-Bundle Recovery (XDEV-07, D-18, D-19)

### E1 — Happy path: what the user must NOT see

The silent single auto-reload is defined by absence. On build-ID mismatch or chunk-load failure:

- **No** toast, **no** modal, **no** banner, **no** "Updating…" splash, **no** progress indicator.
- **No** frame of any error boundary fallback. The chunk-load classifier runs **before** the boundary renders — a `ChunkLoadError` must trigger the reload path, not the fallback UI.
- Reload initiated within **250ms** of detection.
- Route preserved exactly: `pathname` + `search` + `hash`.
- Active run id preserved under `ANALYSIS_RUN_STORAGE_KEY` (`strivio.analysis.run_id`) so R1 restores in-flight work.
- After reload the user lands on the same screen. The only acceptable trace is the R1 `Picked up where you left off.` note if a run was active.

Assertable as: during a simulated redeploy with a stalled chunk, `document.body.innerText` never contains any Phase-3 error string, and no element matching `[role="alert"]` is ever attached.

### E2 — Loop-guard fallback: the one visible state

Shown only when the `sessionStorage` guard proves a reload already happened and the bundle is still broken. This **is** a full-page takeover — the app genuinely cannot render.

| Field | Value |
|-------|-------|
| Heading | `Couldn't finish updating Strivo` |
| Body | `A new version was released while this tab was open, and this tab couldn't load it. Reload once more, or close the tab and open strivoai.net again.` |
| Conditional line | When a run id is stored: `Your analysis is still running and will be here when you get back.` |
| Primary CTA | `Reload Strivo` — performs a cache-busting navigation to `/?_v={buildId}` |
| Footer line | `If this keeps happening, clear your browser cache for strivoai.net and sign in again.` — 14px `text-muted-foreground` |
| Surface | `bg-background`, centered, `max-w-xl`, 32px padding, 64px vertical breathing at `md` |
| Icon | Lucide `RefreshCcw`, 24px, `text-destructive` (destructive is permitted here) |
| Role | `role="alert"`; on mount, focus moves to the heading (`tabIndex={-1}`, `.focus()`) |
| Type | Heading 28px / 600 / 1.2 · body 16px / 400 / 1.65 |
| testid | `stale-bundle-fallback` |

Uses design tokens — React has rendered, so tokens are available. This is **not** the ES5 guard.

## Surface F — Responsive and Touch Contract (XDEV-05, XDEV-09)

Applies to all 11 audit surfaces: Resume Analysis · LinkedIn Grader · Career Compass · Recruiting Lens · onboarding · dashboard · authentication · uploads and PDF extraction · Stripe checkout · Free and Elite flows · admin isolation.

### F1 — Breakpoints

Tailwind defaults, declared explicitly. No new breakpoint is introduced.

| Range | Token | Contract |
|-------|-------|----------|
| 320–639px | base | Single column. Page gutter 16px. Primary CTAs full width, ≥44px high. All copy wraps; no horizontal scroll. |
| 640–767px | `sm` | Two-up field grids permitted. Page gutter 24px. CTAs stay full width where already full width. |
| 768–1023px | `md` | Existing multi-column layouts engage. Card padding 32px. Form controls may drop to 14px. |
| 1024–1279px | `lg` | Existing desktop layout preserved. |
| ≥1280px | `xl` | Existing desktop layout preserved; container caps at 1400px (`2xl` container setting). |

### F2 — Playwright projects (XTEST-01, D-01, D-02)

Five projects. Descriptors verified present in `@playwright/test` at HEAD.

| Project | Descriptor | Engine | Viewport | DPR |
|---------|-----------|--------|----------|-----|
| `chromium` | `Desktop Chrome` | chromium | 1280×720 | 1 |
| `firefox` | `Desktop Firefox` | firefox | 1280×720 | 1 |
| `webkit` | `Desktop Safari` | webkit | 1280×720 | 1 |
| `mobile-webkit` | `iPhone 14` | webkit | 390×664 | 3 |
| `mobile-chromium` | `Pixel 7` | chromium | 412×839 | 2.625 |

Additional widths asserted within the tagged cross-device subset: **320, 375, 414, 640, 767, 768, 1024, 1280**.

### F3 — No-horizontal-overflow rule (the assertable one)

> At every tested width, on every audit surface, in both themes:
> `document.documentElement.scrollWidth <= document.documentElement.clientWidth + 1`

Exemption is opt-in only: an element that is *intentionally* a horizontal scroller must carry `data-allow-overflow-x="true"` **and** must be operable by touch drag and by keyboard. Nothing else may produce horizontal scroll.

Supporting rules:

- No fixed pixel width greater than 320px on any container at the base breakpoint.
- Any user-supplied string (filename, job title, company, email, URL) uses `break-words` or truncates with the full value available to assistive technology. Never allow a long token to widen the page.
- `overflow-wrap: break-word` currently applies to `p, li` in `src/index.css`. Extend to `h1–h6` on Phase-3 surfaces.

### F4 — Touch targets

- Minimum **44×44 CSS px** hit area for every interactive element on the audit surfaces. Where the visual is smaller, expand the hit area with padding or an `::before` overlay — do not inflate the visual.
- Minimum **8px** gap between adjacent tap targets.
- Icon-only controls (dismiss, close, dropdown triggers) get an explicit `aria-label` and the full 44×44.
- `touch-action: manipulation` on primary CTAs to remove the 300ms double-tap delay on legacy WebKit.
- No hover-only affordance. Every action reachable by hover is reachable by tap and by keyboard.

### F5 — iOS Safari viewport

- **Meta tag:** `<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover" />`. `viewport-fit=cover` is required for `env(safe-area-inset-*)` to resolve.
- **Never add** `maximum-scale`, `minimum-scale` or `user-scalable=no`. Pinch-zoom is a WCAG 1.4.4 requirement.
- **Dynamic viewport units:** every full-viewport container (fixed overlays and page shells) declares the fallback first, then the dynamic unit, so engines without `dvh` still get a usable height:
  - `min-h-screen` → `min-h-screen min-h-[100dvh]`
  - `h-screen` → `h-screen h-[100dvh]`
  - There are 29 `100vh` / `min-h-screen` / `h-screen` occurrences at HEAD. Every one on an audit surface is in scope; the `sidebar.tsx` `100svh` usage is already correct and is left alone.
- **Safe-area insets:** any element anchored to a viewport edge (navbar, bottom-anchored CTA, fixed dialog footer) pads with `env(safe-area-inset-top/bottom/left/right)` so it clears the notch and the home indicator.
- **Form controls ≥16px below `md`** — see § *Typography*. `textarea.tsx` and `select.tsx` are confirmed non-compliant at HEAD.
- **Body scroll lock:** the waiting overlay locks `document.body.style.overflow`. It must restore the previous value on unmount **and** on `Continue in the background`, and must not leave iOS Safari in a scroll-stuck state after the overlay closes.

### F6 — Low-memory / slow-CPU (XDEV-09)

- At most **2** concurrent infinite animations on any single screen.
- Under `prefers-reduced-motion: reduce`, **zero** infinite animations across every Phase-3 surface.
- No `blur-3xl` on an animated element (compositor cost). Static blurs are permitted.
- Backdrop blur is capped at one layer per screen.
- Degradation is silent — a slow device shows a simpler screen, never a warning and never a false failure.

## Surface G — Stripe Checkout Open (operator requirement)

Quick task `260727-0s6` shipped instant-open. This contract **locks** it, makes it device-assertable, and closes the remaining gap.

### G1 — Open budget

> The checkout dialog must be in the DOM and visible **on the same tick as the click, before any network request is issued.**

Assertable deterministically and device-independently: stall the `create-checkout-session` (and `create-payment-intent`) route indefinitely, click the CTA, and assert the dialog is visible. Wall-clock budget: **visible within 500ms** on all five projects, including `mobile-webkit`.

No `await` may precede `setOpen(true)`.

### G2 — Locked states and testids

| State | testid | Copy |
|-------|--------|------|
| Dialog shell open | `checkout-modal` | — |
| Pending (open, no client secret yet) | `checkout-preparing` | `Preparing secure checkout…` *(locked, U+2026 ellipsis)* |
| Top-up pending | `payment-loading` | `Preparing secure checkout…` *(locked)* |
| Unavailable | `checkout-unavailable` / `payment-unavailable` | existing copy, unchanged |
| Embedded | `embedded-checkout` | — |

### G3 — Must-nots

1. **No blank modal.** An open dialog always has a visible body — pending, unavailable, or embedded. Never an empty frame.
2. **No double-open, no double-session.** One click produces exactly one Stripe session / PaymentIntent. The existing in-flight refs (`checkoutInFlightRef`, `inFlightPackRef`) are the mechanism; rapid taps on a mobile emulator must not create a second object.
3. **Never stuck in pending.** Every non-success outcome closes the dialog and surfaces a toast. **New:** if no client secret arrives within **15,000ms**, close the dialog and show `We couldn't start checkout. Please try again.` The pending state must not spin forever.
4. **No capability-gated open.** In `degraded` tier, B3 blocks the CTA before any session is created.

### G4 — Mobile checkout

- Dialog content: `max-h-[100dvh]` with a `100vh` fallback, internal `overflow-y-auto`, safe-area bottom padding. The embedded payment element must not be clipped by the iOS URL bar or the home indicator.
- Focus: Radix moves focus into the dialog on open and returns it to the triggering CTA on close. **Preserve both.**
- Dismissal must not leave body scroll locked.

## Accessibility Contract

### Focus handling for new blocking states

### Announcements

- Exactly **one** `aria-live="polite"` region per waiting surface, containing **only** the current stage line. The step list must not be inside it — re-announcing the whole checklist on each transition is screen-reader spam.
- `role="status"` for informational states (degraded banner, restore notes, reconnect, realtime fallback). `role="alert"` **only** for the two full-page controlled failures.
- Every state change that a sighted user perceives has a corresponding announcement.

### General

- No positive `tabindex` anywhere. DOM order is tab order.
- Every icon-only control has an `aria-label`.
- Color is never the sole cue: text + icon accompany every state.
- `prefers-reduced-motion: reduce` honoured on every Phase-3 surface — zero infinite animations, no parallax, no auto-playing transform.
- 2px `focus-visible` rings with sufficient contrast in both themes, inherited from shadcn. Do not remove or override.
- All Phase-3 copy meets 4.5:1 contrast in both themes.
- Pinch-zoom must remain enabled (no `user-scalable=no`, no `maximum-scale`).
