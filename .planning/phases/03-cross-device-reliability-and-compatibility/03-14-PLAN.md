<objective>
Make realtime failure observable and recoverable on the LIVE path (XRUN-04), and add the network/visibility seam that refresh-and-reconnect recovery depends on (XRUN-03).

Purpose: `useAnalysisRun` already implements subscribe-first with poll-fallback — but it is dormant behind `VITE_FEATURE_ANALYSIS_LIFECYCLE`, and the live path in `Results.tsx` is a different mechanism. Both `.subscribe()` calls are bare, so `CHANNEL_ERROR` / `TIMED_OUT` / `CLOSED` are never observed: the UI can never say polling is in use, the poll cadence never adapts, and a blocked-WebSocket environment produces a silent infinite reconnect loop. Separately, `src/` contains zero `online`, `offline` or `visibilitychange` handlers, so an iOS user who backgrounds the tab mid-analysis returns to a severed socket and a throttled timer.
Output: a network-status seam, status callbacks at both subscribe sites, a muted informational degraded line, and a five-project proof.

Scope guard: D-27 is binding — do NOT flip `VITE_FEATURE_ANALYSIS_LIFECYCLE`. The dormant site is fixed identically so the two implementations cannot diverge, but the live path is what ships behavior.
</objective>

<threat_model>
- **Turning a recovery into an error (the contract inversion).** If the status callback sets an error state, a transient socket drop — which is common on mobile — becomes a visible failure on a run the server is completing normally. That is precisely the "false failure on slow devices and networks" the brief forbids. Mitigation: `CLIENT_REALTIME_DEGRADED` is marked informational in the frozen taxonomy; the component renders it as a muted 14px line beneath the stage list; no toast, no colour change, no error state, no blocking; the line clears silently if realtime recovers.
- **Self-inflicted load / poll storm.** Reacting to every `CHANNEL_ERROR` with an immediate poll, while realtime-js retries unboundedly in the background, can produce a request storm against `get-analysis-job-status` from every affected tab simultaneously. Mitigation: one immediate catch-up poll per transition into a degraded state (not per event), a bounded polling cadence, and coalescing so a `visibilitychange` and an `online` event arriving together produce one poll, not two.
- **Duplicate channels / cross-run leakage.** Adding a callback is a natural moment to accidentally reuse a channel topic, which would deliver another run's updates into this component. Mitigation: preserve the existing per-instance unique topic discipline (`analysisRunChannelSeq`) exactly; assert channel creation and teardown are still symmetric.
- **Listener leaks.** Global `online` / `offline` / `visibilitychange` handlers added inside a component that mounts on many routes will accumulate. Mitigation: the seam owns a single registration with reference counting and returns an unsubscribe; the unit test asserts that after all subscribers detach, zero listeners remain.
- **Information disclosure in the degraded line.** The realtime error object carries transport detail (URLs, socket codes). Rendering it would violate XRUN-06. Mitigation: the rendered string comes from the frozen taxonomy only; the raw status and error go to diagnostics under the closed `realtime_degraded` category, never to the DOM.
- **Flipping the lifecycle flag by accident.** Enabling `VITE_FEATURE_ANALYSIS_LIFECYCLE` would activate the Merit ledger path, which Preview structurally cannot validate because the merit system is off there. Mitigation: an explicit acceptance criterion that the flag's value and `feature-flags.ts` are unchanged, and that the dormant hook still early-returns.
- **A vacuously green fallback test.** Aborting the realtime socket in a test where realtime was never going to be used proves nothing. Mitigation: the spec asserts the run actually resolves via polling (a status request count greater than zero) AND that the muted line rendered AND that no `[role="alert"]` and no destructive colour appeared.
</threat_model>
