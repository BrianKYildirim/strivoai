Run the full verification the phase has been building toward, deploy to Preview, and execute the nine-item scripted operator production pass that D-24 requires planning to schedule explicitly (XTEST-04, XDEV-02).

<threat_model>
- **Assuming Preview proves more than it does (the central risk).** Preview runs `AI_TEST_MODE` fixtures and never calls Anthropic; `MERIT_SYSTEM_ENABLED` is false there; and the Vercel Git link is disconnected so merging deploys nothing. A verification that treats Preview as production-equivalent would sign off a phase whose money-path contract was never actually tested. Mitigation: the environment-capability split is stated up front, and the ledger, AI-output, real-device, real-extension and real-redeploy checks are all scheduled onto the operator pass with explicit reasons.
- **Silent non-deployment.** The Preview frontend must be built by hand because the Git link is disconnected, and a new edge function that is missing from `scripts/deploy.ps1 $Functions` is never deployed at all — silently. Either failure produces a "verified" Preview that does not contain the code under test. Mitigation: the deploy step explicitly confirms the hand-built frontend carries this phase's build ID and that `log-client-diagnostic` responds on the deployed Preview.
- **CORS fail-closed lockout.** Preview's CORS is an exact-match allowlist and fails closed; a frontend served from an unexpected alias gets a 200 preflight with no allow-origin header, which presents as a silent, total functional failure. Mitigation: use the stable Preview alias and verify one authenticated request succeeds before running any other assertion.
- **Production write by accident.** The single most dangerous action available in this plan is a migration or function deploy against production. Mitigation: Task 3 is a blocking human-action checkpoint; every production step is written as an instruction to the operator; Claude performs no production mutation and the acceptance criteria say so.
- **Real money and real data in the production pass.** Item P-1 reads a real Merit ledger on real accounts and P-8 opens real checkout over cellular. Careless execution could charge a real card or leave a test artifact in a real account. Mitigation: the step list names the exact accounts (one real Free, one real Elite), states that checkout is opened and dismissed rather than completed, and requires the operator to record the ledger delta rather than screenshot account contents.
- **Evidence that cannot be audited.** A pass recorded as "looked fine" is not evidence. Mitigation: every item requires a concrete recorded value — a ledger delta, a device and OS version string, a diagnostics row count, a pass/fail verdict — and an item left blank is treated as a NOT READY signal in plan 03-20.
- **Diagnostics soak taking longer than the phase.** P-9 needs 24-72 hours of real traffic. Mitigation: it is explicitly a time-boxed post-deploy soak whose partial result is acceptable, recorded as such, rather than a blocker that stalls the phase.
</threat_model>
