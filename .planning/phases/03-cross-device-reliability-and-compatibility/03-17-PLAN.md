<objective>
Prove one-click integrity across five engines and devices by extending the two specs that already target it (D-17), and schedule the one assertion Preview structurally cannot make.

Purpose: XRUN-01 and XRUN-02 are the requirements with real money attached. Plan 03-16 built the mechanism; this plan is the evidence. D-17 chose extension over new specs deliberately — `e2e/two-tab-concurrency.spec.ts` and `e2e/elite-rerun-merit.spec.ts` already own the fixtures, the account setup and the ledger-reading helpers for exactly this behavior.
Output: rapid-click cases on both specs, `@xdev` tagging so they run on all five projects, a reconciled quarantine entry, and an honest statement of what Preview cannot prove.

Scope guard: no product code changes here. If a case fails, the fix belongs to plan 03-16 and is recorded in the defect register.
</objective>

<threat_model>
- **Proving only half the contract.** A suite that asserts duplicate clicks collapse, without also asserting a deliberate Elite re-run still creates a new attempt, will pass on an implementation that silently swallows paid re-runs. That is a revenue defect that looks like a green test. Mitigation: both cases are required in this plan, on the same run, and the acceptance criteria name both.
- **Claiming a Merit guarantee Preview cannot support.** `MERIT_SYSTEM_ENABLED` is false on Preview, so "one click equals exactly one Merit debit" is structurally unprovable there. Asserting it anyway — or worse, writing a test that passes because the ledger is inert — would put a false claim into the completion report. Mitigation: the ledger-delta assertion is explicitly deferred to operator production pass item P-1, recorded in the residual register, and this plan asserts only what Preview can honestly prove: one job, one overlay, one request.
- **Real money spent by the test itself.** Any spec that starts real analyses on a real account consumes Merits. Mitigation: these specs run under `playwright.config.ts` against the local preview build with the test project's fixtures — NOT under `playwright.prod.config.ts`, which deliberately runs at `workers: 1, retries: 0` to keep one-job-one-charge unambiguous. An explicit acceptance criterion asserts `playwright.prod.config.ts` is unchanged.
- **Flake on a money-path gate.** Rapid-click timing across five engines is exactly the kind of assertion that flakes, and a flaky blocking gate gets bypassed with `-SkipVerify`, disabling the whole seven-layer precondition. Mitigation: assert on structural outcomes — request counts, overlay element counts, toast counts — not on timing windows; no retries are added; any flake is fixed or the case is cut and recorded, never retried away.
- **Silently re-enabling a quarantined case.** `e2e/two-tab-concurrency.spec.ts` carries a quarantined, environment-gated case tied to lifecycle dormancy. Re-enabling it while `VITE_FEATURE_ANALYSIS_LIFECYCLE` is still off (D-27) would produce a red gate for a reason unrelated to this phase. Mitigation: the entry stays quarantined; its register text is updated to cite D-27 and its expiry is reconciled rather than extended by default.
- **Budget breach.** Adding cases across five projects on the two heaviest specs is the most likely place the +3 min budget breaks. Mitigation: re-measure, and if over, cut cases (recording them in the residual register) rather than dropping a project.
</threat_model>
