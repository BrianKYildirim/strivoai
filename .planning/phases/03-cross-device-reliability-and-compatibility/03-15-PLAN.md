<objective>
Rewrite the shared waiting overlay to tell the truth (UI-SPEC Surface D): delete the four fabrications, drive stages from real signals, and make a slow backend structurally incapable of producing a false failure (XRUN-05, XRUN-03, D-20, D-21).

Purpose: `UniversalAnalyzing.tsx` is the waiting surface for all five AI features, and at HEAD it lies in four independent ways — a wall-clock progress curve, a percent readout derived from it, a hardcoded 20-second estimate, and step advancement driven by the same curve. On a slow device the curve races ahead of reality and the user watches a bar reach 95% while nothing has happened; on a fast one it lags. Meanwhile the surface runs roughly ten concurrent animations, which is a measurable cost on low-memory devices.
Output: a frozen stage-copy module, the rewritten component, a static guard that the fabrications cannot return, and a five-project proof over a 150-second stalled run.

Scope guard: D-27 is binding. The live driver is `useResumeStream.STAGE_LABELS`. The 11-state map is wired but dormant and the lifecycle flag is NOT flipped.
</objective>

<threat_model>
- **False failure on a healthy run (the requirement itself).** If any client timeout renders an error, a user on a slow connection is told their paid analysis failed while the server is still producing it — and may re-run, spending Merits twice. Mitigation: D-20 is implemented structurally, not by convention: the component has NO code path from an elapsed-time threshold to an error state. The 120000ms threshold changes copy and switches to polling; only a terminal server state may render failure. The 150-second Playwright assertion proves no `[role="alert"]` ever attaches.
- **Abandoning a charged run.** Adding a cancel affordance to a long wait is the obvious product instinct and is explicitly forbidden — it would strand a Merit charge with no refund path. Mitigation: `Continue in the background` dismisses the overlay and leaves the run active; it is not a cancel; the UI-SPEC forbids any abandon affordance and the acceptance criteria assert no cancel control exists.
- **Fabrications returning by accident.** A future contributor will reasonably want to "add a progress bar back". Mitigation: a static-source guard test that fails on a percent readout, an elapsed-time-driven progress value, an ETA string, or a timer-derived step — proven able to fail by mutation.
- **Focus trap and scroll-lock hazards.** The overlay is `role="dialog" aria-modal="true"` but nothing currently focuses it, and it mutates `document.body.style.overflow`. A broken restore leaves iOS Safari scroll-stuck after the overlay closes — a device-specific defect of exactly the class this phase exists to remove. Mitigation: a real focus trap with initial focus on mount and focus returned to the trigger on unmount AND on `Continue in the background`; the previous `overflow` value is captured and restored on both paths.
- **Screen-reader spam.** Announcing the whole checklist on every transition is hostile. Mitigation: exactly one `aria-live="polite"` region containing only the current stage line; the step list sits outside it.
- **Two error surfaces at once.** A client informational line and a server terminal error rendering together give contradictory instructions. Mitigation: taxonomy rule 3 — server terminal state wins; the component renders at most one error surface.
- **Performance regression on low-memory devices.** Removing animations is the fix, but replacing them with an expensive indeterminate indicator or a backdrop-blur stack would undo it. Mitigation: at most 2 concurrent infinite animations, zero under reduced motion, one backdrop-blur layer, and no `blur-3xl` on an animated element.
</threat_model>
