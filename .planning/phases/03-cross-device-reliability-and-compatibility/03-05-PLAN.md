<objective>
Use the matrix to find real defects (D-22) and triage them honestly (D-23), producing the fix backlog that waves 3-5 execute against.

Purpose: the operator's complaint is "works on my device, fails on theirs" with no reproductions. Everything after this plan is only as good as the evidence produced here. Front-loading the suite is also what makes each later fix testable — XTEST-03 requires a regression test per confirmed issue, and you cannot write one without a reproduction.
Output: five `@xdev` discovery specs, a defect register of reproduced issues mapped to owning plans, and a residual register of everything that could not be reproduced, each with a severity.

Scope guard: this plan FINDS. It does not FIX. No file under `src/` or `supabase/` may be modified.
</objective>

<threat_model>
- **Discovery theatre.** Specs that assert something trivially true on every engine produce a green matrix and zero findings, which reads as "no cross-device problems" and is the most damaging possible outcome. Mitigation: every spec must be engine- or device-dependent, and each must be mutation-proved able to fail; the session-storage spec in particular is expected to FAIL at HEAD because the `localStorage` override is a confirmed defect — a green result there means the injection is wrong, not that the bug is absent.
- **Test-injected credential exposure.** These specs override storage, abort routes and inject init scripts against an authenticated session. A careless `console.log` of a storage value or a request header would print a session token into a CI artifact. Mitigation: never log storage contents, never log request headers, never screenshot a page in an authenticated state without need; assert on shapes and booleans.
- **Real money movement.** Any discovery spec that actually starts an AI run consumes Merits on the account the storageState belongs to. Mitigation: discovery specs assert layout, storage, network and upload-validation behavior only; they must not click a start-analysis CTA. Concurrency and rerun behavior belong to plan 03-17, which extends the two existing specs deliberately built for it.
- **Chromium-only emulation lying.** CDP `Network.emulateNetworkConditions` silently does nothing on firefox/webkit, so a "slow network" assertion would pass vacuously on two of five projects. Mitigation: use `page.route()` with an artificial delay before `route.continue()`, which behaves identically on all five projects; `context.setOffline(true)` is fine everywhere and may be used.
- **Assertions that cannot see the real thing.** `env(safe-area-inset-*)` resolves to `0px` under emulation and `getComputedStyle` returns the resolved value, so a computed-style safe-area assertion is meaningless. Similarly `document.getAnimations()` cannot see framer-motion's RAF-driven transforms. Mitigation: these two go to the residual register as manual-only (XTEST-04) with a stated reason, and are covered by static-source guards in later plans instead of a false browser assertion.
- **Budget breach turning the gate into a bypass.** Adding many `@xdev` specs is exactly how the +3 min budget is blown, and a blown budget produces `-SkipVerify`, which disables the whole seven-layer precondition. Mitigation: re-measure after authoring; if over budget, cut discovery cases (recording the cut in the residual register) and never drop a project.
- **Register rot.** A defect register that is not the input to later plans becomes a document nobody reads. Mitigation: every entry names the owning plan number and the regression-test slot, and plan 03-20's traceability table is asserted against this file.
</threat_model>
