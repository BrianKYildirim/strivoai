<objective>
Generalize the resume-analysis-only error log into the shared client-diagnostics seam D-10 requires, wire it to the plan 03-04 endpoint, and install the global error capture that `src/` has never had.

Purpose: partial coverage guarantees the next unknown-device failure lands somewhere unlogged. D-25 puts diagnostics first precisely so it starts producing the data that validates everything after it.
Output: `src/lib/diagnostics/` with a frozen category set, a never-throws emitter, global handlers, and the XLOG-02 PII guard test.

Scope guard: adopting the seam at each of the 11 surfaces happens inside the plans that own those surfaces. This plan builds the seam, installs the global capture, and makes `analysis-error-log.ts` delegate.
</objective>

<threat_model>
- **Diagnostics failing the flow it is diagnosing.** The single worst outcome: an emit that throws, awaits, or blocks turns a recoverable UI hiccup into a broken user flow — the exact failure class this phase exists to remove. Mitigation is four independent guarantees, each individually asserted by a test: never awaited, swallowing try/catch around the whole body, a per-session cap of 20, and a single in-flight slot that drops rather than queues.
- **PII exfiltration to a new endpoint.** This plan creates the first path from arbitrary client error state to a database. An unguarded `error.message` or `event.filename` would carry resume text, a signed storage URL, or a user's email. Mitigation: the record builder projects from a frozen `DIAGNOSTIC_ALLOWED_KEYS` list and NEVER copies `error.message`, `error.stack`, `event.filename`, or any DOM/file value. Only `error.constructor.name` is recorded. The vitest guard stuffs a record with forbidden content and asserts it does not survive the builder, and asserts the same key list matches the server's `ALLOWED_FIELDS`.
- **Self-amplifying failure loop.** A global `error` handler that emits, where the emit itself throws or renders, produces an unbounded loop that DoSes both the browser and the ingest endpoint. Mitigation: the handler never touches React state; the emitter is re-entrancy guarded; the per-session cap is enforced before any network work; and a failed emit is never retried.
- **Extension noise poisoning the signal.** Grammarly-class injectors and ad blockers throw inside the page constantly. Reporting them as app failures would bury real defects and inflate volume. Mitigation: classify `script_origin` as first-party / browser-extension / third-party / unknown using the existing scheme detection in `analysis-error-log.ts`, set `is_extension`, and treat extension-origin errors as recorded-but-isolated (XDEV-08) rather than as app failures.
- **Unload-time data loss versus preflight cost.** A plain `fetch` on unload is cancelled; adding an `Authorization` header forces an OPTIONS preflight. Mitigation: `sendBeacon` with a `text/plain` Blob is the primary path (simple request, no preflight, survives unload) and carries no auth; the authenticated variant uses `fetch` with `keepalive` and accepts the preflight. A client-asserted `user_id` is never sent — the server derives it or stores NULL.
- **Breaking existing callers.** `AnalysisErrorBoundary` imports from `analysis-error-log.ts`. Changing its shape while refactoring would break the one error surface that already works. Mitigation: every existing export is preserved with its existing signature; only the transport is delegated.
- **Environment fail-open.** If the endpoint URL is misresolved the emitter must degrade to a silent no-op, never to a console error storm or a thrown import. Mitigation: the URL is derived from the same Supabase functions base the app already uses, and resolution failure is treated as "diagnostics disabled".
</threat_model>
