<objective>
Ship UI-SPEC Surface E: recover silently from a redeploy that deleted the chunk the open tab was about to load, and show exactly one honest fallback when recovery itself cannot work (XDEV-07, D-18, D-19).

Purpose: this repo turns a deleted chunk into a `200 text/html` response because `vercel.json` rewrites everything to `index.html`. The result is an engine-specific MIME-type module error rather than a clean failure — which is why the symptom presents as "users who just need to hard-refresh" and "sporadic blank pages after a deploy". Vite 8.0.16 emits a cancelable `vite:preloadError` for every failing dynamic import, which is the engine-independent detector this needs.
Output: a detection-and-reload module, boundary suppression, the E2 fallback, the `vercel.json` exclusion, and a five-project proof that observes absence.

Scope guard: the build ID and `version.json` already exist from plan 03-02. This plan consumes them.
</objective>

<threat_model>
- **Reload loop (the failure that makes things worse).** An unguarded auto-reload against a genuinely broken deploy spins the user's browser forever and can hammer the origin. Mitigation: a `sessionStorage` guard keyed on build id with a 60s window; on the second detection for the same build the E2 fallback renders instead of reloading. Because `sessionStorage` itself throws in restricted-storage contexts — the exact browsers this phase serves — the guard read is try/catch'd and falls back to a `_v` URL marker.
- **The fallback-frame race (non-obvious and mandatory).** `preventDefault()` on `vite:preloadError` suppresses Vite's re-throw, so `__vitePreload` resolves `undefined` and `React.lazy` throws a DIFFERENT error on the next microtask — potentially painting one frame of an error-boundary fallback before the navigation commits. UI-SPEC E1 forbids that frame. Mitigation: every boundary reads `isStaleReloading()` and renders `null` when set. Relying on the reload winning the race is not acceptable; this is the deterministic construction.
- **Losing a paid, in-flight run.** A reload during an active analysis must not orphan a Merit-charged run. Mitigation: the run id already persists under `ANALYSIS_RUN_STORAGE_KEY`; the reload preserves `pathname`, `search` and `hash` for free; and the E2 fallback shows the conditional line about the run still running when an id is stored. No affordance in this plan may abandon a charged run.
- **Open-redirect / injection via the cache-busting CTA.** The E2 primary CTA navigates to `/?_v={buildId}`. If the build id were attacker-influenced or the target were read from `location`, this becomes an open redirect or a script-injection vector. Mitigation: the target is a hardcoded same-origin path; the build id comes from the compiled `__STRIVO_BUILD_ID__` define, never from a query parameter or storage.
- **Breaking SPA routing with the rewrite exclusion.** The `vercel.json` catch-all is what makes deep links work. A malformed exclusion could 404 every route. RESEARCH flags the exact syntax as LOW confidence (Open Question 3). Mitigation: verify the syntax against current Vercel documentation before editing; keep the change to `/assets/*` only; assert in the acceptance criteria that a deep SPA route still resolves; and note that `vite:preloadError` detects regardless, so this edit is an improvement rather than a dependency — if the syntax cannot be confirmed, skip it and record the decision in the residual register.
- **A vacuous absence assertion.** "No error appeared" is trivially true on a page that never rendered. Mitigation: the spec installs a `MutationObserver` before navigation, proves the route was reached, proves the reload occurred, and only then asserts no `[role="alert"]` node was ever attached and no Phase-3 error string ever appeared.
- **Detection firing on a healthy deploy.** A false positive reloads users mid-task for no reason. Mitigation: the version poll is throttled to at most once per 60s and only runs on `visibilitychange -> visible` and route change; a `null` fetch result (network failure, malformed JSON) is treated as "no information", never as a mismatch.
</threat_model>
