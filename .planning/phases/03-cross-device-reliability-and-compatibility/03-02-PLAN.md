<objective>
Produce the single build identity this phase depends on: a build ID stamped into the bundle at build time, a `version.json` manifest emitted alongside it, and a cache header that keeps the manifest honest.

Purpose: D-18 chose "both a stamp and a chunk-load catch" precisely because the stamp is needed anyway for XLOG-01's `app_version` field — once it exists, active version detection is nearly free. This plan builds the shared foundation so plans 03-06 (diagnostics) and 03-13 (stale-bundle recovery) can both consume it.
Output: `__STRIVO_BUILD_ID__` in the bundle, `dist/version.json` in the build output, `Cache-Control: no-store` on it, and a small fail-closed accessor module.

This plan ships no user-visible behavior. Detection and reload live in plan 03-13.
</objective>

<threat_model>
- **Silent empty identity.** If the build ID resolves to an empty string on some surface, `app_version` becomes useless in diagnostics and the version comparison in 03-13 always matches, disabling stale-bundle recovery without any test going red. This is the realistic failure because the Vercel Git link is disconnected and Preview frontends are hand-built. Mitigation: a four-step resolution chain ending in `String(Date.now())`, plus a unit test asserting non-empty, plus a build-output assertion that `dist/version.json` parses and carries a non-empty `buildId`.
- **Stale manifest defeats the mechanism.** A CDN-cached `/version.json` would report the old build forever, so a genuinely stale tab would never be told to reload. Mitigation: explicit `Cache-Control: no-store` header in `vercel.json` plus `cache: 'no-store'` on the fetch — belt and braces, because either alone can be overridden.
- **Information disclosure.** The build ID appears in the client bundle and in every diagnostics row. A full commit SHA is not a secret in a private repo but is unnecessary detail. Mitigation: truncate `VERCEL_GIT_COMMIT_SHA` to 12 chars and use `git rev-parse --short HEAD`; never embed a branch name, an author, or a path.
- **Build-time command injection / build failure.** `execSync('git rev-parse --short HEAD')` runs during config evaluation. In a container without git, or in a detached/empty repo, an unguarded call fails the entire build. Mitigation: the call is wrapped in try/catch with `stdio` set so a git error cannot pollute output, and the timestamp fallback is unconditional.
- **Poller as a leak vector.** A version poll that runs unthrottled on every route change adds a request per navigation and can be turned into a self-inflicted load source. Mitigation: at most one fetch per 60s, only on `visibilitychange -> visible` and route change, and the whole body wrapped in a swallowing try/catch.
- **Config regression blast radius.** `vite.config.ts` already carries the Rolldown-compatible function-form `manualChunks`; a careless edit there breaks every build in the repo. Mitigation: additive edits only, and `npm run build` is the task verify.
</threat_model>
