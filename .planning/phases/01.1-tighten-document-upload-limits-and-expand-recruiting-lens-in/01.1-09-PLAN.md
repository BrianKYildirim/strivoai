<objective>
Create the shared browser fast-feedback precheck for resume documents and prove its local page boundaries plus the LinkedIn exemption.

Purpose: Users should get immediate feedback, but the helper must remain explicitly non-authoritative and must not collapse the separate resume and LinkedIn document contracts.
Output: one reusable precheck and deterministic boundary/non-regression tests.
</objective>

<threat_model>
- **False client authority.** The helper performs no persistence or billing decision; Plan 10 must still call the authenticated seam before storage. Tests and comments name it fast feedback only.
- **Client/server disagreement.** This plan proves the browser side against deterministic 1/2/3-page fixtures. Plan 11, after both Plan 08 and this plan exist, owns the cross-runtime identical-byte pdfjs/pdf-lib parity proof.
- **LinkedIn breakage.** The helper requires a `documentType`; `resume` uses 2, `linkedin_profile` uses 12. No file-extension-only cap is permitted.
- **Parser failure UX.** Unreadable PDF/DOCX does not silently pass. It returns the exact validation-unavailable message and leaves clearing/focus behavior to the calling control.
- **History regression.** Existing extraction behavior and `PAGE_LIMITS` OCR render budgets remain unchanged; this helper is additive.
</threat_model>
