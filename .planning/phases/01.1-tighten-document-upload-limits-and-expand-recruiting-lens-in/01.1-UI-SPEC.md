# Phase 01.1 — UI Design Contract

> Visual and interaction contract for tightening resume upload limits and expanding the Recruiting Lens job-description input. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase is a constraint-communication update, not a feature redesign. Preserve the existing upload cards, Recruiting Lens two-column layout, navigation, billing/Merit surfaces, and result views. New UI work is limited to communicating PDF/DOCX-only support, the two-page resume limit, the 6,000-character Recruiting Lens limit, and validation states.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui, existing project installation |
| Preset | `style: default`, `base: radix`, `baseColor: slate`, CSS variables enabled; shadcn CLI reports no generated preset code |
| Component library | Radix primitives through `@/components/ui` |
| Icon library | Lucide React |
| Font | Inter through `font-sans`; system-ui fallback |

Implementation rules:

- Reuse existing `Button`, `Card`, `Textarea`, `Input`, `Label`, `Badge`, and Sonner toast components. Do not install a new block or component library.
- Use semantic Tailwind tokens (`bg-background`, `bg-card`, `text-foreground`, `text-muted-foreground`, `text-primary`, `text-destructive`, `border-border`, `border-input`, `ring-ring`). Do not add hardcoded phase-specific colors.
- Preserve the existing default and light theme mappings from `src/index.css`.
- Preserve current focus rings and disabled-state treatment from the shadcn components.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Character-counter offset, compact inline gaps |
| sm | 8px | Label-to-field gap, icon-to-label gap, helper-copy offset |
| md | 16px | Mobile card padding, control groups, toast content gap |
| lg | 24px | Mobile drop-zone padding, form-section separation |
| xl | 32px | Desktop card padding, primary layout gaps |
| 2xl | 48px | Desktop drop-zone padding, major section breaks |
| 3xl | 64px | Existing large upload icon footprint and page-level breathing room |

Exceptions:

- Primary buttons and file-picker buttons have a minimum 44px height/touch target (`h-11` or equivalent).
- Recruiting Lens textarea stays `min-height: 200px` below `md` and `280px` at `md` and above; both are multiples of 4.
- Existing 12px border radius (`--radius: 0.75rem`) remains unchanged.

## Typography

Use exactly these four phase-specific sizes and two weights. Existing legacy headings outside the edited limit surfaces are not normalized by this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Helper / counter | 14px | 400 | 1.4 |
| Body / validation guidance | 16px | 400 | 1.65 |
| Section heading | 20px | 600 | 1.2 |
| Page display heading | 36px | 600 | 1.2 |

Typography rules:

- Use weight 400 for explanatory copy and counters. Labels use the same 14px size at weight 600; headings, filenames, and CTA labels also use weight 600.
- Character counters use tabular numerals when available (`tabular-nums`) so the width does not jump while typing.
- Error copy may wrap naturally; never reduce it below 14px to keep it on one line.
- Locked messages preserve punctuation, capitalization, numerals, and comma formatting exactly.

## Color

The 60/30/10 split uses existing semantic tokens and must work in both themes.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `background` — dark `hsl(0 0% 0%)`, light `hsl(0 0% 100%)` | Page background and textarea field background |
| Secondary (30%) | `card` — dark `hsl(0 0% 5%)`, light `hsl(0 0% 98%)`; `secondary` — dark `hsl(0 0% 10%)`, light `hsl(0 0% 94%)` | Upload cards, drop zones, supporting panels, disabled/secondary controls |
| Accent (10%) | `primary` — dark `hsl(357 100% 68%)`, light `hsl(357 100% 55%)` | Primary CTA fill, focus ring, selected-file icon, active drag border only |
| Destructive | `destructive` — dark `hsl(0 84.2% 60.2%)`, light `hsl(0 84.2% 50%)` | Validation errors and the Recruiting Lens counter after 5,400 characters |

Accent reserved for:

- `Analyze Resume` and `Analyze Job` primary CTAs.
- Keyboard focus rings.
- The accepted/selected resume icon.
- The active drag-over border/background.

Do not use the accent for helper copy, inactive borders, every icon, or the normal character counter. Do not use destructive styling for the valid selected-file state.

## Interaction Contract

### Resume-class file selection

1. The native picker exposes `accept=".pdf,.docx"` through the shared constant. Drag-and-drop uses the same shared allowlist.
2. On browse or drop, run the client precheck immediately:
   - Unsupported/renamed content: reject with the exact unsupported-type message.
   - PDF or DOCX over two pages: reject with the exact page-limit message.
   - Valid file: show the existing selected-file state with filename and `Choose Different File`.
3. A rejected selection must:
   - Clear the native input value so choosing the same corrected/re-exported file triggers `change` again.
   - Leave the upload card in its empty state.
   - Make no upload, database write, analysis request, or Merit change.
   - Return focus to the browse/select control after the toast is announced.
4. Drag-over uses `border-primary bg-primary/10`; drag-leave and drop restore the default border.
5. The upload card must never claim that `.txt` or `.md` is accepted.

### Authoritative validation and submission

1. `Analyze Resume` remains enabled only when a locally accepted file is selected and existing Merit/paywall rules allow submission.
2. On activation:
   - Disable the CTA and file-change controls.
   - Set `aria-busy="true"` on the upload form/card.
   - Use the existing spinner treatment with transient label `Validating...`.
3. The authoritative server validation completes before storage upload, row creation, analysis invocation, or Merit deduction.
4. On success, transition into the existing upload/analyzing flow and existing loading copy.
5. On failure:
   - Remove the busy state and re-enable selection.
   - Show the exact server-provided locked message.
   - Keep the user on the same surface.
   - Clear an invalid file; preserve other form inputs.
6. Do not expose internal parser, MIME, storage, or edge-function details in user-facing copy.
7. Onboarding, Profile, Career Compass, and hero flows keep their existing submit/continue CTA labels. Apply the same disabled/busy/error behavior without renaming those controls.

### LinkedIn PDF exemption

- LinkedIn profile PDF controls keep their existing `.pdf` accept contract, existing helper copy, and existing 12-page processing allowance.
- A LinkedIn PDF longer than two pages must not display the resume page-limit error.
- Do not reuse a resume-specific page-limit badge or helper line inside LinkedIn Grader or the LinkedIn source section of Recruiting Lens.

### Recruiting Lens job description

1. The `Textarea` has `maxLength={6000}`, stays resizable vertically, and preserves the existing `min-h-[200px] md:min-h-[280px]`.
2. Visible guidance directly below or associated with the field reads exactly: `Job descriptions may contain up to 6,000 characters.`
3. The right-aligned counter is `{current}/6,000`:
   - 0–5,400 characters: `text-muted-foreground`.
   - More than 5,400 through 6,000: `text-destructive`.
   - The threshold and denominator derive from the shared constants; no inline `5400` or `6000` literal in the page component.
4. The counter is informational and must not be the only accessible limit cue. Associate both helper text and counter with the textarea using `aria-describedby`.
5. The counter must not announce every keystroke. Server rejection copy is announced once through the existing error/toast mechanism.
6. A server `invalid_input` response above 6,000 displays the exact locked message and leaves company name, role title, job description, resume source, and optional LinkedIn source intact.
7. No submitted job-description text between 3,001 and 6,000 characters is visually marked invalid or silently shortened.

## State Contract

| State | Resume upload UI | Recruiting Lens UI |
|-------|------------------|--------------------|
| Empty | Dashed drop zone, `Upload` icon, empty-state heading/body, `Browse Files` | Empty textarea, muted helper, `0/6,000` |
| Drag over | Primary border and subtle `primary/10` background | Not applicable |
| Local validation | CTA/input disabled only for the short validation operation; existing spinner treatment | Native typing remains responsive |
| Valid selection/input | Filename + `FileText` primary icon; existing CTA available subject to Merit/paywall rules | Normal border and muted counter through 5,400 |
| Near limit | Not applicable | Counter changes to destructive after 5,400; no blocking before 6,000 |
| Authoritative validation | Disabled CTA, spinner, `aria-busy`; no persistence yet | Existing analyze loading state after client readiness checks |
| Rejected | Exact toast, invalid selection cleared, empty state restored, no partial state | Exact message, inputs preserved, focus remains in or returns to job-description field |
| Network/validator unavailable | Operational retry message; no upload or Merit change | Existing retry/error treatment; inputs preserved |
| Success | Existing upload/analyzing sequence unchanged | Existing result view unchanged |

## Responsive Contract

| Breakpoint | Contract |
|------------|----------|
| 320–639px | Single-column forms; page gutter 16px; upload card padding 16px; drop-zone padding 24px; primary/file-picker buttons full width and at least 44px high; helper/error copy wraps without horizontal scroll |
| 640–767px | Existing two-field company/role grid may use two columns; upload card may use 32px padding; CTAs remain full width where already full width |
| 768px and above | Preserve Recruiting Lens `3fr / 2fr` two-column layout with 32px gap; textarea minimum height 280px; upload page remains centered at `max-w-3xl` with 48px drop-zone padding |

Additional responsive rules:

- Counter remains directly below the textarea and right-aligned at every width.
- Long filenames truncate visually with an ellipsis where needed; the full filename remains available to assistive technology and may use the existing tooltip/title pattern.
- Toasts may wrap; do not shorten locked messages for mobile.
- No fixed-height container may clip the two-page helper or validation message.

---

## Accessibility Contract

- All file inputs retain an explicit accessible name through the associated `label`/button.
- The visible browse button is keyboard reachable. Drag-and-drop is an enhancement, never the only path.
- Use `aria-describedby` for supported formats/page limit on resume inputs and for helper/counter text on the Recruiting Lens textarea.
- Validation failures use the existing toast/error announcement and never rely on color alone.
- Preserve 2px focus-visible rings with sufficient contrast in dark and light themes.
- Loading controls expose `aria-busy` and remain disabled against duplicate submission.
- Error handling does not move focus to the toast. Return focus to the originating control when a file is rejected.
- The destructive counter color is supplemented by the numeric count and persistent 6,000-character guidance.
- New motion is limited to the existing spinner and color transitions; honor `prefers-reduced-motion`.

## Plan Ownership and Executable Coverage

- **Plan 10 implements this contract.** Its tasks explicitly own semantic drag-over styling and restoration; accessible long-filename ellipsis; 320-639px and 640-767px single/full-width upload behavior; 44px controls; complete toast wrapping with no copy truncation; and content-driven helper/error containers with no fixed-height clipping, in addition to copy, clearing, focus, busy, disabled, and description behavior.
- **Plan 11 proves the contract before deployment.** Its secret-free local/mock Playwright suite measures widths 320, 639, 640, 767, and desktop; asserts drag restoration, accessible full filenames, full-width controls, full locked toast text, no horizontal overflow, and no clipped helper/error content.
- **Plan 12 repeats the critical browser assertions after preview deployment.** Its separately configured `*.live.ts` suite runs only after D-30(b) bundle/boot succeeds; it cannot be auto-discovered by the pre-deploy baseline. Production remains operator-gated.

No plan may claim this UI contract from source inspection alone when the obligation is measurable in a rendered browser.
