<threat_model>
- **Pre-deploy test cycle.** Ordinary `*.spec.ts` live tests would be auto-discovered by the deploy script's baseline before the route exists. Mitigation: only `*.live.ts` plus a separate explicit config; default discovery must find none of them.
- **Wrong project.** The deploy script links explicitly after the baseline. Every checkpoint records the target ref and stops if it differs from preview/production as appropriate.
- **Vacuous remote proof.** Direct HTTP tests record real statuses and fixture digests; no-state tests include live control reads and unique run scoping.
- **Secret/PII leakage.** Evidence contains project ref, sanitized command/status/count/digest/version/timestamp only; never JWTs, access tokens, emails, user IDs, or document contents.
- **Accidental production adversarial traffic.** Spoof, oversize, and row-delta tests stay on preview. Production receives only OPTIONS, unauthenticated 401, and one authenticated synthetic one-page no-state smoke.
- **Optimistic evidence.** `nyquist_compliant` and checked boxes change only when a cited command actually ran. Any skip, red gate, unavailable environment, or missing operator action remains an explicit gap.
</threat_model>
