# Phase 01.1 Brief: Tighten Document Upload Limits and Expand Recruiting Lens Input

## Objective

Update Strivo's file-upload restrictions and Recruiting Lens input limits:

1. PDF and DOCX files may contain no more than two pages.
2. Markdown (`.md`) and plain-text (`.txt`) uploads are no longer supported.
3. Recruiting Lens job descriptions may contain up to 6,000 characters instead of 3,000.

> **Revision (2026-07-23, `/gsd-discuss-phase 01.1`):** the Recruiting Lens limit was
> originally written as 8,000 and was revised to **6,000** by operator decision during
> phase discussion. All figures below reflect 6,000. See `01.1-CONTEXT.md` D-15.

This phase must be completed before Phase 02, AI Token & Cost Optimization, resumes.

## Product Requirements

### Two-page PDF and DOCX limit

- Enforce the limit anywhere Strivo accepts PDF or DOCX resumes, cover letters, or other documents.
- Enforce during actual file processing, not only through frontend copy or picker constraints.
- Accept one-page and two-page PDF files.
- Accept one-page and two-page DOCX files.
- Reject PDF or DOCX files containing more than two pages.
- Use a clear, consistent message:

  > Your document is longer than the 2-page limit. Please upload a PDF or DOCX file containing no more than 2 pages.

- Reject before Merit deduction, AI analysis, or completed-analysis persistence.
- Do not leave incomplete uploads or processing records after validation failure.

### Remove Markdown and plain-text upload support

- Remove `.md` and `.txt` from file-picker `accept` attributes and frontend allowlists.
- Remove them from backend validation schemas and MIME-type allowlists.
- Remove parsing or processing paths used exclusively for Markdown or plain-text uploads.
- Preserve shared parsing utilities still used internally by supported workflows.
- Update upload instructions, helper text, tooltips, error messages, and documentation.
- Reject direct API/server-action bypass attempts, including renamed or MIME-spoofed unsupported files.
- Use a clear, consistent message:

  > Unsupported file type. Please upload a PDF or DOCX file.

### Recruiting Lens 6,000-character job-description limit

- Increase the limit from 3,000 to 6,000 everywhere it is validated, displayed, persisted, or passed downstream.
- Cover textarea `maxLength`, live character counter, client validation, form schemas, server/API validation, database/RPC constraints where applicable, prompt construction, and truncation logic.
- Accept inputs up to and including 6,000 characters.
- Reject 6,001 or more characters.
- Preserve the complete submitted text through the analysis pipeline; do not silently truncate at 3,000.
- Use a clear, consistent message:

  > Job descriptions may contain up to 6,000 characters.

- Keep desktop and mobile layouts functional with the larger input.

## Implementation Boundaries

- Locate duplicated supported-file, page-limit, and Recruiting Lens character-limit constants.
- Prefer shared constants or schemas where practical to prevent frontend/backend drift.
- Preserve authentication, authorization, billing, Merit, analytics, and upload-security behavior.
- Do not change unrelated text-input limits.
- Do not change Recruiting Lens pricing or Merit costs.
- Do not redesign features beyond the UI changes required to communicate the restrictions.

## Required Tests

### File formats

- Valid PDF succeeds.
- Valid DOCX succeeds.
- `.md` is rejected.
- `.txt` is rejected.
- Renamed or MIME-spoofed unsupported content is rejected by backend validation.
- Upload UI advertises only PDF and DOCX.

### Page limits

- One-page PDF succeeds.
- Two-page PDF succeeds.
- Three-page PDF is rejected.
- One-page DOCX succeeds.
- Two-page DOCX succeeds.
- DOCX exceeding two pages is rejected.
- Rejected documents trigger neither AI processing nor Merit deduction.

### Recruiting Lens

- Input below 6,000 characters succeeds.
- Exactly 6,000 characters succeeds.
- 6,001 characters is rejected.
- Character counter uses 6,000.
- Server independently rejects oversized input.
- Input longer than the former 3,000-character limit is not truncated.

## Acceptance Criteria

- Every applicable PDF and DOCX upload is limited to two pages.
- `.md` and `.txt` cannot be selected, submitted, or processed.
- User-facing upload copy lists only PDF and DOCX.
- Recruiting Lens accepts complete job descriptions through 6,000 characters.
- Frontend and backend validation agree.
- Oversized and unsupported inputs fail before AI processing and Merit deduction.
- Existing supported upload and Recruiting Lens workflows continue to function.
- Relevant automated tests, type checks, linting, and production builds pass.
