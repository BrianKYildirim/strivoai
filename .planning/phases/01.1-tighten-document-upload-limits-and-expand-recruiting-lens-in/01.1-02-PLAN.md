<objective>
Raise the Recruiting Lens combined input ceiling so the 3,000 -> 6,000 job-description increase is fully additive, executing D-21's three-file lockstep change correctly the first time.

Purpose: Recruiting Lens has TWO independent caps — the per-field JD slice (plan 01.1-04) and a combined per-tier ceiling. Raising only the first leaves the second able to trim the JD back. This plan raises the second.
Output: `maxCharactersInput.recruitingLens` 48,000 -> 51,000 and `maxTokensInput.recruitingLens` 12,000 -> 12,750 in both `pricing-config.ts` and `pricing-config.snapshot.ts`, plus a Phase 02 baseline note.

This plan is intentionally independent of everything else in the phase — it shares no file with any other plan and can land first.
</objective>

<threat_model>
- **Gate breakage (highest practical risk).** `src/config/__tests__/sc12-snapshot.test.ts` machine-enforces `maxCharactersInput === maxTokensInput * 4` on every non-null row AND byte-equality against the snapshot. A partial edit turns `npm test` red, which turns `verify:baseline` red, which blocks every deploy in the repo — including plans unrelated to this one. Mitigation: all three cells in one commit; `npm run test` is the task's verify.
- **Silent revert.** The neighbouring cells carry Phase 02 measurement-window markers that plan 02-09 will sweep. An unmarked 01.1 cell could be reverted to 48,000 by a later phase with no test catching it. Mitigation: an explicit permanent marker comment naming Phase 01.1 and its exclusion from that sweep.
- **Cost/budget surface.** Raising an input ceiling raises the maximum billable input tokens per Recruiting Lens call. Bounded and intentional: +750 input tokens worst case per call, and only reachable if resume (5,000 chars) + JD (6,000) + LinkedIn (4,000) together exceeded the old ceiling, which they cannot (15,000 max). No pricing, tier, or merit-cost change (D-25).
- **Measurement integrity.** Phase 02 calibrates against `getMaxInputChars('recruitingLens')`. Comparing a pre-01.1 baseline to a post-01.1 measurement would silently mis-attribute the delta. Mitigation: dated note in the Phase 02 measurement log (D-23).
- No auth, authz, persistence, or user-input surface is touched.
</threat_model>
