<threat_model>
- **File-type spoofing (the brief's explicit requirement).** `Content-Type` and file extension are both attacker-controlled: the browser derives `File.type` from the extension, and `storage-js` forwards that as the upload `Content-Type`. Mitigation: `sniffKind` decides from bytes only — `%PDF-` within the first 1 KiB for PDF, `PK\x03\x04` plus a `word/document.xml` entry in the central directory for DOCX. `PK\x03\x04` alone is NOT sufficient: it also matches `.xlsx`, `.pptx`, `.odt`, `.jar`, and a plain `.zip`.
- **Silent under-enforcement.** Every failure mode in this module is silent by nature — a validator that returns "fine" makes the cap quietly stop existing while acceptance criteria read green. Mitigation: exhaustive truth-table tests including the negative cases, and an explicit asymmetric fail policy (below).
- **Asymmetric fail policy — get this exactly right.** DOCX `<Pages>` missing/zero/negative/malformed -> FAIL OPEN subject to the word backstop, because that metadata is legitimately absent from a large share of real exports (D-06). Unreadable ZIP or missing `word/document.xml` -> FAIL CLOSED as unsupported type. PDF is handled in plan 01.1-08 and fails CLOSED on parse failure. Fail-open on an unparseable container would let an attacker bypass the cap with a deliberately malformed file.
- **ZIP parsing on attacker-controlled bytes.** The central-directory walk reads offsets and lengths straight out of the input. A crafted archive can point offsets outside the buffer or declare a huge compressed size. Mitigation: bounds-check every computed offset and slice against `bytes.length` before use, cap the number of central-directory entries walked, cap the inflated size, and never throw out of the module — return `null` and let the caller decide.
- **Zip-bomb / CPU exhaustion.** Supabase Edge caps CPU at 2s per request. Mitigation: `MAX_UPLOAD_BYTES` bounds the input before this module runs (enforced in plan 01.1-08), plus an inflated-size cap here.
- **Content leakage in logs.** Document text must never be logged. Mitigation: this module is pure and does no logging; the caller logs sizes and verdicts only.
</threat_model>
