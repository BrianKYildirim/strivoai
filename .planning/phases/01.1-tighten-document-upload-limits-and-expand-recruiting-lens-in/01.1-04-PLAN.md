<objective>
Raise the Recruiting Lens job-description limit from 3,000 to 6,000 characters and replace silent truncation with an explicit rejection.

Purpose: Today the server silently discards everything past 3,000 characters. Users pasting a full job description get an analysis against a third of it with no indication. The brief requires acceptance through 6,000 and rejection — never truncation — above it.
Output: three client literals replaced by imports, one server slice replaced by a 400 guard, and boundary tests in both lanes.

Note: 6,000 is the number. The original brief said 8,000; D-15 revised it. Any 8,000 you encounter is stale.
</objective>

<threat_model>
- **Unbounded input.** Removing `.slice(0, 3000)` removes a de-facto input bound. The replacement guard must REJECT rather than pass through, or an attacker can drive arbitrary input tokens into a paid Anthropic call. Mitigation: the `> RECRUITING_LENS_JD_MAX_CHARS` check returns 400 at step 3, and the combined per-tier ceiling (plan 01.1-02) remains as the second bound.
- **Cost before authentication.** The guard sits at handler step 3, which is BEFORE `requireAuth` (step 4), `checkRateLimit` (step 6), and the merit gateway (step 7). This means an unauthenticated caller can cheaply trigger a 400 — acceptable, since it performs no DB read, no AI call, and no merit write, and matches the existing min-length guards' position exactly. It also guarantees D-17's before-merit/before-Anthropic requirement with zero re-sequencing.
- **Merit double-charge / stranded optimistic deduct.** `RecruitingLens.tsx` performs an optimistic merit deduct before invoking. A new 400 path that does not settle the rollback would strand the user's balance. Mitigation: verify `settle.rollback()` fires on the `invalid_input` branch (Task 1 acceptance criterion).
- **Message drift.** The rejection message is user-facing and locked verbatim. Mitigation: it is imported from `_shared/document-limits.ts`, never restated, and the Deno test asserts the response body's `message` field equals the literal.
- **Prompt injection surface increases.** The JD field is user-controlled text flowing into a prompt, and its capacity doubles. This does not introduce a new surface — the existing `prompt-sanitizer.ts` path is unchanged and still applies. No sanitisation behaviour is altered (D-25).
- No change to auth, tier gating, rate limits, pricing, or merit costs.
</threat_model>
