<objective>
Remove `.md` and `.txt` upload support end to end: the shared extension allowlist, the user-facing label, the plain-text extraction branch, and the storage bucket MIME allowlist.

Purpose: The brief requires that `.md` and `.txt` cannot be selected, submitted, or processed, and that upload copy lists only PDF and DOCX.
Output: narrowed constants, a deleted extraction branch, a new migration plus its rollback, and rewritten tests.

The migration FILE is written here. It is APPLIED in plan 01.1-07 (preview autonomous, production operator-gated).
</objective>

<threat_model>
- **The bucket allowlist does not stop spoofing (D-28).** `allowed_mime_types` validates the client-declared `Content-Type`, which `storage-js` derives from `File.type`, which the browser derives from the extension. Renaming `evil.md` to `evil.pdf` yields `application/pdf` and passes. This migration is defense-in-depth for the honest client and the direct-storage-API case ONLY. Magic-byte sniffing in the validation seam (plan 01.1-06/08) is the actual anti-spoofing enforcement. **Do not write an acceptance criterion claiming otherwise** — none in this plan does.
- **Destructive data risk.** Revoking MIME types could be misread as a mandate to purge historical `.md`/`.txt` resumes. It is not (D-14). `allowed_mime_types` gates NEW uploads only; existing objects and rows stay readable. No `DELETE`, no `ALTER`, no RLS change, no policy change — a single `UPDATE storage.buckets`.
- **Type-safety regression on historical reads.** Removing `'plain_text'` from the `ExtractionProvider` union would break type-safe reads of `resumes.extraction_metadata` rows already persisted with that provider. Mitigation: the union keeps `'plain_text'`; only the production write path is removed.
- **Stale-but-green test (RESEARCH Pitfall 8).** The existing migration assertion reads the OLD migration by absolute path and will keep passing while asserting the opposite of the requirement. Mitigation: Task 2 retargets it to the NEW migration with `not.toContain`.
- **Rollback obligation.** Every migration ships rollback SQL (CLAUDE.md). Mitigation: D-33's exact convention — separate file, same timestamp, same name, `.rollback.sql`, line 1 = `-- Rollback for <forward filename>`.
- No auth, authz, merit, or billing surface is touched.
</threat_model>
