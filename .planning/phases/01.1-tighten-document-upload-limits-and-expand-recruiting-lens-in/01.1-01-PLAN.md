<objective>
Create the single dual-imported source of truth for every limit and message this phase introduces, plus the Deno re-export bridge that lets edge functions read it without duplication.

Purpose: D-24/D-31 — the brief's central failure mode is frontend/backend constant drift. Every later plan in this phase imports from here. Nothing else in the phase is safe to start until this exists.
Output: `src/config/document-limits.ts`, its `_shared` bridge, tests in both lanes, and a widened `invokeWithTimeout` body type.

Behavior change in this plan: NONE. Nothing consumes these constants yet.
</objective>

<threat_model>
- **Constant drift (primary).** If a limit or message is restated anywhere else, client and server can disagree and a user sees "accepted, then rejected". Mitigation: zero-import canonical module + re-export bridge; later plans are forbidden from re-declaring these values, and their tests assert absence of the numeric literals.
- **Locale/format drift on the rendered message.** `Number.toLocaleString` behaviour can differ across runtimes. Mitigation: the three messages are hardcoded string literals, not templates, and both lanes assert the *rendered* string byte-for-byte.
- **Edge boundary leak.** Importing anything browser-only into `document-limits.ts` breaks the Deno import silently at deploy time, not test time. Mitigation: zero imports is a stated, tested invariant (`deno task check` type-checks the bridge).
- **Transport widening.** Widening `invokeWithTimeout`'s `body` union is additive-only and passed straight through; it does not relax auth, CORS, or timeout behaviour on any of the ~30 existing callers.
- Not in scope: no auth, authz, network, or persistence surface is touched by this plan.
</threat_model>
