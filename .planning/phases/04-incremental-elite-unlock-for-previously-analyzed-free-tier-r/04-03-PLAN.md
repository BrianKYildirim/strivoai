<threat_model>
## Trust Boundaries

| Boundary | Risk | Control |
|---|---|---|
| Browser/queue payload -> analyze-resume | IDs, tier, owner, or content can be forged | Authenticate first; owner-scope reads; resolve tier/content/base on server |
| Stored text -> model calls | Prompt injection or sensitive logging | Existing sanitizer, narrow output schema, counts/IDs-only telemetry |
| Sync/queue retries -> lifecycle and merit ledger | Duplicate generation or financial settlement | Stable identity and existing create/recover/settle/refund state machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04-01 | Elevation of Privilege | Unlock request IDs | mitigate | Owner-scoped resume and mirror lookups with non-enumerating failure responses. |
| T-04-02 | Spoofing | Client tier | mitigate | Ignore request tier and resolve current Elite access from server subscription state. |
| T-04-04 | Tampering | Replacement content/identity | mitigate | Use stored text/hashes/fingerprint; changed identity exits to fresh full analysis. |
| T-04-05 | Repudiation / Tampering | Retry and merit lifecycle | mitigate | Stable idempotency, create/recover lifecycle, and exactly-once settlement/refund tests. |
| T-04-06 | Tampering | Stored prompt input | mitigate | Existing prompt sanitizer and missing-only schema. |
| T-04-07 | Tampering | Failed generation/persistence | mitigate | No write before both validations; atomic RPC or no mutation. |
| T-04-09 | Information Disclosure | Logs and telemetry | mitigate | IDs, sections, token counts, duration, and status only. |
</threat_model>
