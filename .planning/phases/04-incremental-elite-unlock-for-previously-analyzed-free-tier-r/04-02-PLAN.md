<threat_model>
## Trust Boundaries

| Boundary | Risk | Control |
|---|---|---|
| Edge service role -> persistence RPC | A forged owner/base identity could mutate another result | Explicit owner, source-reference, tier, content identity, and expected-base predicates |
| Concurrent requests -> same resume/usage rows | Lost update or duplicate debit/mirror | Advisory/row lock, stable idempotency, unique replay identity, compare-and-swap |
| Operator shell -> Supabase environments | Preview migration could target production | Literal preview ref, before/after migration-list evidence, production hard stop |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04-01 | Elevation of Privilege | Persistence RPC | mitigate | Service-role-only grant and owner/source linkage inside the transaction. |
| T-04-04 | Tampering | Resume identity | mitigate | Stored hashes/fingerprint and base mirror identity are compared inside the lock. |
| T-04-05 | Tampering / Denial of Service | Concurrent unlocks | mitigate | Stable idempotency plus lock and compare-and-swap; replays return one stored result. |
| T-04-07 | Tampering | Multi-table persistence | mitigate | Same transaction for resume, merged mirror, and usage link; any failure rolls back. |
| T-04-08 | Elevation of Privilege | SECURITY DEFINER RPC | mitigate | Fixed search path, explicit predicates, revoked public/authenticated grants. |
| T-04-PREVIEW | Elevation of Privilege | Schema deployment | mitigate | Operator-gated literal preview ref; production untouched without `apply production`. |
</threat_model>
