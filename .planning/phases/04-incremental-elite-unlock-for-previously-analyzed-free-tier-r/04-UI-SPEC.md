# Phase 04 — UI Design Contract

> Visual and interaction contract for incremental Elite unlock on an existing Free-tier resume analysis. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui, initialized |
| Preset | `default` style, `slate` base, CSS variables, no prefix (source: `components.json`) |
| Component library | Existing local shadcn components built on Radix UI |
| Icon library | Lucide React |
| Font | Inter with system fallbacks |

This phase extends the current Results surface. It must not introduce a new page, visual theme, component registry, analysis layout, or hardcoded color. Reuse `Card`, `Button`, `MeritCostPreview`, `UniversalAnalyzing`, and the existing Results tier-gating components.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label micro gaps |
| sm | 8px | Inline status and compact text spacing |
| md | 16px | Default element spacing and mobile page padding |
| lg | 24px | Section separation and CTA bottom margin |
| xl | 32px | Results section gaps |
| 2xl | 48px | Major waiting-surface separation |
| 3xl | 64px | Page-level spacing only |

Exceptions: 12px between the CTA icon and content, 20px CTA card padding, and a 44px minimum touch target for buttons at the mobile breakpoint. These are established project values and remain multiples of 4.

### Component Spacing

- Keep the unlock card in its current Results position: after Strengths and before Priority Improvements.
- Card padding is 20px; icon/content gap is 12px; heading-to-body gap is 4px; body-to-cost/action region gap is 12px.
- The primary action is full-width below 640px and content-width at 640px and above.
- Preserve the Results container and its existing 16px mobile horizontal padding. The phase must not add horizontal scrolling.

---

## Typography

This phase declares four sizes and exactly two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | Regular 400 | 1.65 |
| Label / button / status | 14px | Semibold 600 | 1.4 |
| Heading | 20px | Semibold 600 | 1.2 |
| Display / overlay title | 24px | Semibold 600 | 1.2 |

- Use sentence case for every heading, status, and action.
- The merit count stays in the button label and must wrap normally on narrow screens.
- Do not use all-caps, monospace, `theme-v2`, or more than the two declared weights.

## Color

Use semantic CSS variables in both the default dark theme and light theme. Hex values and raw Tailwind palette utilities are forbidden on Phase 04 additions.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `background` — dark `hsl(0 0% 0%)`, light `hsl(0 0% 100%)` | Results page and full-screen analyzing overlay |
| Secondary (30%) | `card` / `secondary` — dark `hsl(0 0% 5%)` / `hsl(0 0% 10%)`, light `hsl(0 0% 98%)` / `hsl(0 0% 94%)` | Unlock card, icon well, progress rows, and bordered surfaces |
| Accent (10%) | `primary` — dark `hsl(357 100% 68%)`, light `hsl(357 100% 55%)` | Unlock icon, primary CTA, active progress indicator, spinner leading edge, focus ring |
| Destructive | `destructive` — dark `hsl(0 84.2% 60.2%)`, light `hsl(0 84.2% 50%)` | Inline unlock-failure icon and message only |

Accent reserved for: the Sparkles icon and its tinted well, “Unlock Elite insights” primary action, the active analyzing indicator, and keyboard focus rings. It must not color body copy, every link, completed insight content, or entire card backgrounds.

The failure action remains the normal primary button; it is not destructive because retrying does not delete or replace the stored Free analysis.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Unlock Elite insights — {cost} merits` |
| Empty state heading | Not applicable — the unlock affordance only renders over a valid stored Free analysis |
| Empty state body | Not applicable — missing or invalid base data follows the conflict/re-upload state below |
| Error state | `We couldn’t unlock the Elite insights. Your Free analysis is unchanged.` |
| Destructive confirmation | None — this phase has no destructive user action |

### Unlock Card

| Element | Locked copy |
|---------|-------------|
| Heading | `Unlock the rest of your Elite analysis` |
| Body | `Add only the missing Elite insights to this result. Your existing Free analysis won’t change.` |
| Primary action | `Unlock Elite insights — {cost} merits` |
| Pricing pending | `Loading pricing…` |
| Starting state | `Starting…` |

`{cost}` must come from the existing feature-cost query. Never hardcode a merit amount. Keep the existing `MeritCostPreview` balance and affordability copy immediately above the action.

### Progress and Completion

| Element | Copy |
|---------|------|
| Overlay title | `Unlocking Elite insights` |
| Checking stage | `Checking this analysis` |
| Reservation stage | `Reserving your credits` |
| Generation stage | `Generating missing Elite insights` |
| Validation stage | `Checking the new insights` |
| Save stage | `Saving your Elite analysis` |
| Completion announcement | `Elite insights unlocked.` |

The existing 45-second reassurance and `Continue in the background` action remain unchanged. The existing 120-second long-running/polling reassurance also remains unchanged. Unlock progress must never say that the system is rescoring, rewriting, or fully reanalyzing the original Free result.

### Recovery Copy

| Condition | Message | Action |
|-----------|---------|--------|
| Retryable generation, validation, network, or persistence failure | `We couldn’t unlock the Elite insights. Your Free analysis is unchanged.` | `Try again` |
| Changed content or identity mismatch | `This resume has changed, so it needs a new full analysis.` | `Analyze updated resume` |
| Stored resume text unavailable | `This resume’s text isn’t stored. Upload it again to create a new Elite analysis.` | `Upload resume` |
| Already completed replay | No message or charge prompt; render the persisted Elite result | None |

Do not render raw server, database, transport, model, or exception text. Do not make a merit refund claim in generic failure copy; the server lifecycle remains authoritative for accounting.

## Interaction Contract

### Eligibility and Visibility

Render the charging unlock card only when all client-known conditions hold:

- the current account normalizes to Elite;
- the displayed analysis has authoritative `analyzed_tier = 'free'`;
- the result belongs to the current stored resume record; and
- the server confirms at least one Elite-only section is missing before generation.

The server remains authoritative for ownership, current tier, base validity, stable identity, and missing sections. Client-provided tier, result data, filename, and resume text must not be treated as proof.

Preserve the existing tier matrix:

- Elite account + Free analysis: show the unlock card.
- Elite account + Elite/complete analysis: do not show the card.
- Free account: do not show the Elite unlock card; existing upgrade gating remains unchanged.
- Unknown/null analyzed tier: keep the existing neutral, non-charging path to a fresh Elite analysis.
- Feature cost `undefined`: show a disabled `Loading pricing…` button.
- Feature cost `null`: render no charging action.

### Ready State

- Present the locked card heading, body, database-driven merit preview, and primary action.
- The button includes the Sparkles icon, with the decorative icon marked `aria-hidden`.
- Clicking once disables the action immediately, sets `aria-busy="true"`, and starts one unlock attempt against the existing resume ID.
- Double-clicks, refreshes, and concurrent requests must converge on the same in-flight operation. The UI must never expose two simultaneous unlock actions.

### Progress State

- Remain on the same `/results/:resumeId` route and the same stored resume.
- Present the existing `UniversalAnalyzing` full-screen modal overlay with the locked title `Unlocking Elite insights`.
- Preserve its focus trap, body-scroll lock, focus restoration, polite stage announcement, connectivity notes, and reduced-motion behavior.
- Use unlock-specific stage copy from this contract. Do not reuse full-analysis labels such as “Evaluating your resume” or “Writing your assessment.”
- At 45 seconds, show the existing reassurance and `Continue in the background`. Dismissing the overlay returns focus to the Results page and does not cancel the unlock.
- After background continuation, replace the charging button with a disabled inline `Unlocking Elite insights…` status until the authoritative result or failure arrives.
- At 120 seconds, use the existing long-running/polling reassurance. A slow operation is not a failure by itself.

### Success State

- Close the overlay and reconcile the authoritative same-row result without changing the URL.
- Announce `Elite insights unlocked.` through one polite live region or one success toast, not both.
- Remove the unlock card once the stored row reports `analyzed_tier = 'elite'`.
- Reveal the existing full Results layout with the newly persisted sections.
- Preserve the original Free score, summary, strengths, visible improvements, rewrites, and criterion values without visual replacement or reset.
- Do not add a success modal. Existing completion celebration may run, but it must honor `prefers-reduced-motion`.
- Reloading or revisiting the same Results URL must show the completed Elite result immediately with no overlay, CTA, model call, or additional charge.

### Failure State

- Close the full-screen overlay and keep the unchanged Free result visible.
- Convert the unlock card to an inline recovery state at the same location above gated sections.
- Render the locked failure sentence once, with an inline destructive-semantic icon/message and a normal primary `Try again` action.
- Use one error surface only: do not combine the inline error with a duplicate toast or full-page Results error.
- Move focus to the inline recovery heading after the overlay closes. The error container uses `role="alert"`; the retry action remains keyboard reachable.
- Retry the same eligible unlock flow. It must not clone the resume, erase the Free result, or bypass server idempotency and accounting checks.
- Identity/content conflicts are not retryable unlock failures. Show the conflict copy and route its action through the existing fresh-upload/full-analysis path.

## Responsive and Accessibility Contract

- Support 320px-wide viewports without horizontal overflow.
- At the base breakpoint, allow the merit-bearing CTA label to wrap and make the button full width.
- Every actionable control has a minimum 44×44 CSS-pixel touch target on touch-sized viewports.
- Maintain visible `focus-visible` rings using the semantic `ring` token.
- The progress overlay remains `role="dialog"` with `aria-modal="true"` and an accessible name matching `Unlocking Elite insights`.
- Stage updates use one `aria-live="polite"` region. Inline terminal failure uses `role="alert"`.
- Do not communicate ready, active, success, or failure state by color alone; pair icon/color with text.
- With `prefers-reduced-motion: reduce`, use the existing static progress treatment and suppress repeating or celebratory motion.
- Return focus to the invoking CTA after background dismissal, and move focus to the inline recovery heading on terminal failure.
- Preserve semantic heading order inside Results; the unlock card heading is subordinate to the Results page heading.
