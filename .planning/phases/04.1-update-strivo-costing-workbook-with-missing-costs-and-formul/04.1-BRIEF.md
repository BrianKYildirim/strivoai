# Phase 04.1 Brief — Strivo Costing Workbook Update

## Objective

Update the existing workbook at `docs/Strivo AI Final Costing Plan.xlsx` so it includes important missing operating costs, replaces calculated hardcoded results with formulas, and remains simple and recognizable as the original workbook.

This phase modifies the supplied workbook in place. It must not create a replacement workbook or redesign the spreadsheet.

## Locked Requirements

### CWB-01 — Preserve the original workbook design

- Keep the existing layout, colors, fonts, font sizes, borders, alignment, number formats, and text formatting.
- Add sections using the workbook's existing visual language.
- Keep Worst Case, Mid Case, and Best Case visually consistent.
- Do not add charts unless they are necessary to understand a result.
- Keep labels plain and the main result focused on monthly revenue, monthly costs, and monthly profit.

### CWB-02 — Audit the workbook before changing it

- Inspect every current assumption, formula, and summary.
- Identify manually entered calculated results and replace them with formulas.
- Preserve existing pricing, Merit amounts, feature costs, token assumptions, and scenario assumptions unless clearly incorrect.
- Preserve useful existing sections.
- Identify duplicate assumptions and establish one editable source cell for each price or rate.

### CWB-03 — Enforce identical scenario structure and formulas

- Worst Case, Mid Case, and Best Case must have identical structure and formulas.
- Only scenario assumption values may differ.
- Every new cost must appear on all three sheets.
- Verify every copied formula references the correct cells on its own scenario sheet.

### CWB-04 — Correct and reconcile the current model

- Free users + monthly Elite users + annual Elite users must equal total MAU.
- Annual Elite users incur AI usage every month even though they pay annually.
- Convert annual subscription revenue to its correct monthly amount.
- Make Merit-shop buyer counts, revenue, Stripe fees, AI costs, totals, and profit formula-driven.
- Add simple visible checks that show an error when user or financial totals do not reconcile.

### CWB-05 — Add a simple Missing Costs section to every scenario

#### Refunds

- Add one editable refund-rate assumption.
- Calculate refunded subscription and Merit-shop revenue as collected revenue multiplied by the refund rate.
- Use reliable SaaS or payment data for the starting assumption and record the source URL and pricing/data date.

#### Chargebacks

- Add editable assumptions for chargeback rate and processor chargeback fee.
- Calculate both revenue lost and chargeback fees.
- Use current official Stripe fee data and reliable chargeback-rate data, with source URL and date.

#### Failed payments

- Add one editable assumption for payments that fail and are never recovered.
- Apply it only to paid subscription and Merit-shop revenue.
- Use a reliable current estimate, clearly marked and sourced when production data is unavailable.

#### OCR and document processing

- Inspect the codebase to determine exactly how PDF and DOCX files are processed.
- Identify every paid extraction or OCR service, every feature that uses it, normal-text versus OCR-fallback behavior, and the allowed page limits.
- Use current official pricing for each service actually used; do not invent an OCR cost.
- If the OCR incidence is unknown, add editable assumptions for the percentage of documents requiring OCR and average OCR pages.
- Calculate monthly OCR cost as documents uploaded × OCR percentage × average OCR pages × cost per OCR page.
- Keep OCR separate from Claude token costs and separate Free and Elite OCR costs when processing differs.

#### Supabase

- Inspect actual Supabase usage and configuration. Strivo is currently on Free; model an upgrade to Pro.
- Include the current official base plan price and only services Strivo actually uses.
- Evaluate relevant database compute, database/file storage, bandwidth or egress, authentication users, Edge Functions, backups, and other confirmed services.
- Separate fixed plan cost from usage-based overages and make usage assumptions editable.
- Record official source URL, pricing date, plan, included limits, and overage rates.

#### Vercel

- Inspect actual Vercel usage and configuration. Strivo is currently on Free; model an upgrade to Pro.
- Include the current official base plan price and only services Strivo actually uses.
- Evaluate relevant seats, functions/compute, bandwidth, image optimization, requests, logs, and other confirmed services.
- Separate fixed plan cost from usage-based overages and make usage assumptions editable.
- Record official source URL, pricing date, plan, included limits, and overage rates.

#### Namecheap and domain

- Model the domain already registered for $13.68 for one year, December 30, 2025 through December 30, 2026.
- Use the actual one-year annual auto-renewal cost of $18.58 as the ongoing assumption and divide annual cost by 12 for monthly costing.
- Include email, SSL, DNS, privacy, or hosting only if records show Strivo pays for them separately.
- Record source and date and keep values editable.

#### Other required services

- Include one Claude Code Pro subscription and one ChatGPT Plus (Codex) subscription as development costs.
- Inspect code, environment-variable names, package files, deployment configuration, documentation, and available billing records for other paid services Strivo actually depends on.
- Consider confirmed email, logging, monitoring, analytics, file storage, error tracking, authentication, and similar dependencies, but do not invent tools or costs.
- Prefer actual invoices or billing dashboards; otherwise use the current official price for the correct plan and record source URL, date, plan, included limits, and overage rate.

### CWB-06 — Model retry and failed-generation overhead simply

- Inspect automatic retries, fallback models, repeated document processing, and failures that may still consume tokens.
- Add one editable percentage named `AI Retry and Failure Overhead`.
- Calculate adjusted AI cost as current AI cost × (1 + overhead).
- Base the initial rate on logs when available. Otherwise mark it as an estimate and state that production retry data must replace it later.

### CWB-07 — Use evidence-backed current prices

- Prefer Strivo invoices, billing dashboards, usage logs, and account settings.
- When unavailable, use official provider pricing pages rather than blogs or unsourced estimates.
- Record source URL, pricing date, plan name, included limits, and overage rate.
- Clearly mark uncertainty and estimates; do not silently guess.
- Add a compact Sources and Last Updated section without cluttering the main model.

### CWB-08 — Separate fixed and usage-based monthly costs

Fixed costs include confirmed base plans, seats, the domain renewal divided by 12, and other recurring software plans.

Usage-based costs include Claude tokens, OCR pages, Supabase/Vercel overages, Stripe fees, refunds, chargebacks, and failed-payment losses.

### CWB-09 — Update the monthly summary

The visually consistent summary on every scenario must show:

- Subscription revenue
- Merit-shop revenue
- Total revenue
- Stripe processing fees
- Refund costs
- Chargeback costs
- Failed-payment loss
- Claude AI costs, including the retry/failure adjustment
- OCR and document-processing costs
- Supabase costs
- Vercel costs
- Namecheap and domain costs
- Other required service costs
- Total monthly costs
- Monthly profit before owner taxes
- Estimated amount per founder using the workbook's existing split and tax assumptions

### CWB-10 — Add simple operating results

- Cost per Free user
- Cost per Elite user
- Revenue per total user
- Profit per total user
- Paid-user percentage
- Total fixed monthly cost
- Total usage-based monthly cost

Do not add investor metrics or a complicated forecasting system.

### CWB-11 — Add a compact production-data To-Do section

List the values that must later be replaced with real production data:

- Percentage of documents requiring OCR
- Average OCR pages
- Actual retry rate
- Actual failed-payment rate
- Actual refund rate
- Actual chargeback rate
- Actual Supabase usage
- Actual Vercel usage
- Actual storage and bandwidth
- Actual average token use
- Actual feature usage by tier

### CWB-12 — Verification

- Change total MAU and confirm all user counts, revenue, costs, and profit update.
- Change paid-user percentages and confirm totals update.
- Change feature usage and confirm AI costs update.
- Change vendor prices and confirm totals update.
- Confirm the three scenario sheets use the same formulas and structure.
- Confirm no broken references, circular formulas, or formula errors.
- Confirm all totals and reconciliation checks pass.
- Confirm the original formatting remains preserved.

### CWB-13 — Repository and workflow constraints

- Inspect the workbook and codebase before implementation.
- Keep implementation changes small and reversible.
- Do not modify `.gitignore`.
- Do not commit `.planning/` artifacts.
- Phase planning must identify the appropriate spreadsheet tooling and a formula/format verification method before workbook edits begin.

## Deliverable

An updated `docs/Strivo AI Final Costing Plan.xlsx` that remains visually recognizable as the supplied workbook, uses formula-driven scenario calculations, includes sourced missing costs, and passes the scenario and sensitivity checks above.
