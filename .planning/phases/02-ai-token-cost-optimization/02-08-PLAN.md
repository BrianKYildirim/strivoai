<hard_stop_notice>
## THIS PLAN MUST NOT BE AUTO-ADVANCED

`workflow.auto_advance` is `true` in `.planning/config.json`. It does **not** apply here.

This plan is `autonomous: false` and its checkpoint is `gate="blocking-human"`. An executor that
auto-approves it has violated the phase's locked decision and the operator's standing instruction to
honour `autonomous: false` operator checkpoints even in auto-mode.

There is no default answer. There is no "approve all" shortcut. The operator gives a verdict
**per cell** — APPROVE, REJECT, or AMEND-to-value. Silence is not approval. A blanket "looks good"
is not a per-cell verdict; if that is the reply, ask for the per-cell table.

Why the granularity matters: these caps ship to production, and a cap below the model's appetite
produces `stop_reason=max_tokens` -> terminal `422 output_truncated` -> hard fail -> Merit refund ->
zero revenue at full cost. Each cell has different evidence quality behind it (some are flagged
"cap cannot be trusted here yet" because their prompt leaves output shape unbounded), so a single
aggregate approval would launder a weak cell in with a strong one.
</hard_stop_notice>
