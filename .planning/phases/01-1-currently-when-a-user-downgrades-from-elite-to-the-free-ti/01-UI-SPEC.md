# Phase 01 — UI Design Contract

> Visual and interaction contract for scheduled Elite-to-Free downgrade feedback and renewal recovery. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui with Tailwind CSS variables |
| Preset | Existing `default` style, Radix base, slate base color |
| Component library | Existing Radix primitives through `@/components/ui` |
| Icon library | Lucide React |
| Font | Inter with the existing system sans-serif fallback stack |

Use only existing semantic tokens and primitives. Do not introduce a new theme, third-party block, billing-specific palette, or hardcoded color. Reuse `Alert`, `AlertDialog`, `Button`, `Badge`, and `Card` where their current semantics fit.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps and compact inline alignment |
| sm | 8px | Button content gaps, badge padding, dialog footer gaps |
| md | 16px | Alert/panel padding and mobile vertical gaps |
| lg | 24px | Desktop panel padding, section-to-section gap, `mb-6` dashboard rhythm |
| xl | 32px | Tier-card internal padding and large responsive separation |
| 2xl | 48px | Major Pricing section separation only |
| 3xl | 64px | Existing page-level spacing only; do not add inside the new compact states |

Exceptions: interactive controls keep the existing 40px minimum height; the primary renewal CTA may use the existing 44px `size="lg"` height on mobile. Dismiss controls must expose at least a 40px by 40px target even when the visible icon is 16px.

---

## Typography

Use only the following phase-specific sizes and two weights. Existing page-level headings outside the new components remain unchanged.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label / supporting copy | 14px | 400 | 1.5 |
| Status heading / dialog title | 18px | 600 | 1.3 |
| Tier-card heading | 24px | 600 | 1.2 |

Dates use tabular numerals when available but never monospace. Countdown emphasis is weight 600, never oversized display text. Do not use all-caps for financial state or countdown copy.

---

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` | Page background, dialog body, neutral negative space |
| Secondary (30%) | `hsl(var(--card))`, `hsl(var(--secondary))`, `hsl(var(--border))` | Membership panel, tier cards, neutral/sync states, dividers |
| Accent (10%) | `hsl(var(--primary))` | Crown/Calendar/Clock icon, scheduled badge, final-week border emphasis, focus ring |
| High-contrast action | `hsl(var(--foreground))` on `hsl(var(--background))` text | Filled `Keep Elite and renew`, confirm, and Retry controls in both themes |
| Destructive | `hsl(var(--destructive))` | Existing downgrade confirmation and true error messaging only; never the stable pending state |

Accent reserved for: pending/Scheduled status indicators, final-week countdown emphasis, confirmed-renewal icon, and keyboard focus rings.

Every filled renewal/recovery CTA uses the proven semantic-token pair `bg-foreground text-background hover:bg-foreground/90`, with the existing `ring-ring`/primary focus cue. Do not use the existing coral `bg-primary text-primary-foreground` pair for CTA text because it does not meet WCAG AA contrast in both themes. `Keep Elite and renew` remains the primary action by placement, weight, and filled treatment; this color correction does not demote its interaction priority.

Pending downgrade is a stable billing status, not an error. Use `border-primary/30 bg-primary/5` or equivalent semantic-token treatment, not destructive red. Syncing uses muted/secondary treatment. Confirmed renewal uses the primary token with a `CheckCircle2` icon; do not introduce a green success token in this phase.

All light/dark appearances must come from the existing CSS variables. Text remains `text-foreground` or `text-muted-foreground`; never place muted text where it fails contrast against a translucent surface.

## Surface Contracts

### Pricing membership panel

- Render only for an authenticated, real Elite subscription with a pending Free downgrade, or for the just-completed renewal confirmation flow. Signed-out and normal Free users retain the current Pricing experience.
- Place the panel in the existing `main`, after the pricing intro/interval toggle and immediately before the `aria-label="Subscription tiers"` grid. Match the grid width (`max-w-4xl mx-auto px-4`) and use a 24px bottom gap.
- Use a bordered card/status-panel composition, not a second page hero. Desktop layout is icon + copy on the left and one renewal CTA on the right. Below `sm`, stack the CTA beneath the copy at full width.
- Dated pending state leads with the full local date. Missing-date state remains visible but does not render a date placeholder, skeleton date, or estimate.
- Stripe-confirmed/profile-syncing replaces the pending wording in the same panel. Once profile state confirms, replace it with the short confirmed state for the remainder of the mounted Pricing visit; a later clean visit returns to normal Pricing.

### Tier cards

- Replace interacting booleans with one explicit visual status contract: `available | current | scheduled`.
- Pending downgrade maps Elite to `current` and Free to `scheduled`.
- Elite keeps the current-plan emphasis and disabled `Current plan` control. Free receives a visible `Scheduled` status/badge and a disabled `Scheduled` control.
- A Scheduled card must not dispatch `onCta`; guard this both in the card and in the Pricing handler. There is no secondary downgrade link anywhere in the pending state.
- Scheduled styling may use a subtle `border-primary/30 bg-primary/5`; it must not out-rank the current Elite card. Preserve current tier-card geometry so the two cards remain aligned.
- Immediately after an explicit Stripe response confirms `cancel_at_period_end: false`, Elite remains `current` and Free returns to `available`, restoring normal tier-card actions without waiting for the webhook/profile sync. The syncing panel may remain visible until persisted state catches up, but stale profile data must not re-disable the cards in this confirmed browser state.

### Dashboard final-week alert

- Render inside the existing dashboard content container before `RunningLowCard`, `OutcomeOverdueBanner`, and `CohortBackfillBanner`. It is always the first banner in DOM and visual order.
- Use the existing `Alert` composition with `mb-6`, `border-primary/40`, `bg-primary/10`, a Lucide `Clock3` or `CalendarClock` icon, and the high-contrast filled CTA treatment defined above.
- Desktop layout: countdown/date copy left, CTA right, dismiss control at the top-right edge. Mobile: copy then full-width CTA; reserve space so the dismiss target never overlaps text or action.
- Dismissal is session-only. Key `sessionStorage` by authenticated user ID and period-end value. If storage is unavailable, fall back to component state. A changed billing boundary must not inherit an earlier dismissal.
- Do not render the dashboard alert when the exact date is absent/invalid, outside the 0–7 local-calendar-day window, after the exact period-end instant, after Stripe-confirmed restoration in the current browser state, or once the profile is restored/expired.

### Renewal confirmation dialog

- Both Pricing and Dashboard launch the same shared `AlertDialog`; do not duplicate mutation or copy logic.
- Dialog title, description, exact date, and footer remain visible without scrolling at common mobile heights. Use the existing `max-w-lg`, 24px padding, and responsive stacked footer.
- Opening the dialog is non-mutating. If the profile date is missing, show a preview-loading state and disable confirmation until the authenticated Stripe preview returns an exact date.
- Secondary control is `Not now`; it closes the dialog and leaves the downgrade scheduled. Primary control is `Keep Elite and renew`.
- While restoring, disable the trigger, confirmation, and close/cancel controls that could create duplicate submissions. Show `Loader2` and `Restoring renewal…` without changing button width materially.
- A failed or ambiguous restore keeps the dialog open, preserves the scheduled state, shows the specific error inline, and exposes `Retry`.
- After Stripe confirms, emit the success toast immediately, suppress stale warnings, restore normal tier-card actions immediately, and transition the panel/dialog to the syncing state until the webhook-backed profile clears pending state. Do not wait for profile reconciliation before changing Free from `scheduled` to `available`.

### Confirmed renewal

- Pricing shows a compact persistent status panel with `CheckCircle2`, heading `Automatic renewal is on.`, and supporting continuity copy.
- If renewal began from Dashboard, the final-week warning disappears immediately after Stripe confirmation; the shared dialog transitions to the confirmed state and remains until the user closes it, in addition to the success toast.
- Do not show confetti, celebratory motion, an upsell, or a price. This is recovery of an existing subscription commitment, not a new purchase celebration.

## State and Interaction Matrix

| State | Pricing panel | Elite card | Free card | Dashboard | Renewal dialog |
|-------|---------------|------------|-----------|-----------|----------------|
| Normal | Hidden | Current for Elite user | Available | Hidden | Closed |
| Pending, dated | Date-led warning + renewal CTA | Current, disabled | Scheduled, disabled | Show only at 0–7 days | Exact-date confirmation ready |
| Pending, date syncing | Confirming-date copy + renewal CTA | Current, disabled | Scheduled, disabled | Hidden | Preview loading; confirm disabled |
| Preview failed | Pending state unchanged | Current, disabled | Scheduled, disabled | Hidden if threshold unknown | Specific inline error + Retry |
| Restore processing | Existing panel remains; CTA disabled | Current, disabled | Scheduled, disabled | Warning suppressed only after Stripe confirms | All submit paths disabled + loader |
| Stripe confirmed, profile syncing | Syncing status panel | Current, disabled | Available; normal action restored immediately | Warning suppressed | Syncing status; no second renewal submit |
| Restored | `Automatic renewal is on.` for current visit | Current, disabled | Available | Hidden | Confirmed state + Close |
| Restore failed/ambiguous | Pending state unchanged | Current, disabled | Scheduled, disabled | Existing warning remains if eligible | Failure + Retry; no success cue |
| Expired | Pending UI hidden | Driven by authoritative tier | Driven by authoritative tier | Hidden | Renewal action unavailable |

No optimistic frontend write may clear persisted pending downgrade state. Visual suppression after explicit Stripe confirmation is temporary browser state while the webhook/profile query reconciles.

## Date and Countdown Contract

- Normalize the cancel response Unix seconds and profile ISO timestamp at the UI boundary into `Date | null`.
- Render the full browser-local date as `MMMM d, yyyy` (for example, `August 31, 2026`). Never show a time, timezone abbreviation, relative-only date, or guessed date.
- Final-week eligibility requires both a future exact instant and a local calendar-day difference from 0 through 7 inclusive.
- Eligibility and countdown copy are clock-driven, not render-only. While a valid pending period end exists, arm cleaned-up one-shot timers for the next browser-local midnight and the exact period-end instant so the UI reevaluates without navigation, reload, query invalidation, or user input.
- The local-midnight timer recomputes `now`, the calendar-day difference, countdown copy, and next midnight after every fire. The exact-boundary timer recomputes `now` and removes the alert/panel at the authoritative instant. If an exact-boundary delay exceeds the platform timer maximum, re-arm it from each midnight tick until it can be scheduled safely.
- Clear both timers on unmount and whenever the user ID, period end, pending/restored status, or locally confirmed Stripe state changes. One-shot callbacks must never survive into a later user or billing period.
- Countdown variants:
  - 2–7: `{n} days left — your Elite access ends on {date}.`
  - 1: `1 day left — your Elite access ends on {date}.`
  - 0 before the exact boundary: `Elite ends today — your Elite access ends on {date}.`
- At or after the exact Stripe boundary, render no pending reminder even if a stale pending field remains briefly.

## Accessibility and Feedback

- The Pricing panel is a labeled status section, not a repeatedly announced `role="alert"`. New syncing/confirmed text uses a polite `aria-live="polite"` status region.
- The final-week Dashboard surface uses the existing `Alert` role and a meaningful heading. The countdown/date must be text, not icon-only.
- `AlertDialogTitle` and `AlertDialogDescription` must remain connected to the Radix dialog. Initial focus lands on `Not now`; destructive financial changes never occur on dialog open.
- Disabled Scheduled and Current controls remain perceivable with their exact label and native `disabled`; card status is also available as text outside the control.
- Dismiss button label: `Dismiss Elite expiration reminder for this session`.
- Loading icons use `aria-hidden="true"`; the button text carries the state. Avoid an indeterminate page-level spinner.
- Use the existing `focus-visible:ring-2 focus-visible:ring-ring` behavior for every action and dismiss control.
- Do not rely on color alone: pair pending, syncing, confirmed, failure, Current, and Scheduled states with icon and text.
- Toasts supplement the persistent state; they never replace it.

## Responsive and Motion Contract

- New surfaces must work at 320px, 768px, and the current desktop container widths without horizontal scrolling.
- At mobile widths, panel/banner content stacks in reading order: status icon/heading, supporting copy, primary CTA. The CTA is full width; at `sm` and above it becomes width-fit and right-aligned.
- Tier cards retain the current one-column mobile and two-column desktop grid. Status labels must not change card height enough to misalign the desktop pair.
- Use only existing Radix fade/zoom dialog motion and Tailwind transition colors. Do not add countdown pulsing, shaking, glow animation, auto-focus animation, or urgency motion.
- Respect `prefers-reduced-motion` through existing component behavior; no new custom animation is required.
