<threat_model>
ASVS Level 1 scope: authenticated billing Edge Function, Stripe mutation response validation, webhook reconciliation, and user-facing CORS error contracts.

Threats:
- **T-01 HIGH - IDOR / subscription ownership bypass (ASVS V4 access control):** a caller could attempt to restore another customer's subscription by supplying an ID. Mitigation: accept only an action discriminator, authenticate with `requireAuth({ type: 'user' })`, and select `stripe_subscription_id` exclusively through `ctx.userId`. Any client subscription/customer identifier is rejected or ignored. Tests must prove cross-user isolation.
- **T-02 HIGH - false financial success / ambiguous provider response (ASVS V5 validation):** a 2xx response, malformed body, network ambiguity, or Stripe object that does not explicitly contain `cancel_at_period_end === false` could be treated as renewal. Mitigation: validate the action and authoritative Stripe response shape, require a finite positive period end, and return a CORS-readable failure otherwise. Never clear profile state from the request path.
- **T-03 HIGH - webhook integrity / duplicate entitlement grant (ASVS V8 data integrity):** a same-tier renewal event could leave stale pending state, alter the tier, or grant Merits. Mitigation: preserve insert-first webhook idempotency, keep Elite unchanged, clear only the pending field in the authoritative webhook update, and assert zero Merit RPC calls.
- **T-04 MEDIUM - secret or payment-data exposure (ASVS V7 logging):** error logging could leak credentials or payment details. Mitigation: retain structured reason-code logging and never log authorization headers, Stripe secrets, payment method data, or response bodies containing sensitive data.

Block-on-HIGH: yes. Any failing or missing T-01, T-02, or T-03 assertion blocks completion of this plan and all dependent waves.
</threat_model>

<objective>

</objective>
