<threat_model>
ASVS Level 1 scope: browser-side billing-state reads, financial confirmation UI, provider-response parsing, and time/session state.

Threats:
- **T-05 HIGH - duplicate or unconfirmed financial mutation (ASVS V3 session/V5 validation):** dialog open, double click, close/reopen, or stale controls could submit renewal without explicit confirmation or submit twice. Mitigation: opening is read-only, initial focus is `Not now`, confirmation stays disabled without an exact date, all close/confirm/trigger paths lock during restore, and an in-flight guard prevents duplicate invokes.
- **T-06 HIGH - false success from stale/ambiguous client state (ASVS V5 validation):** stale profile data, a 2xx with the wrong shape, or network ambiguity could clear warnings. Mitigation: require `ok === true`, `action === 'restore'`, `cancel_at_period_end === false`, and a valid date before local suppression; never write billing profile fields; failed/ambiguous calls preserve pending state and offer Retry.
- **T-07 MEDIUM - cross-user/session state leakage (ASVS V3 session management):** React Query cache or dismissal state could bleed across users/periods. Mitigation: key subscription queries by user ID, key dismissal values by user plus period end, clear timers/effects on dependency changes, and do not use admin tier simulation as billing authority.
- **T-08 MEDIUM - misleading date/price disclosure (ASVS V5 input/output validation):** malformed dates or inferred price could misstate the commitment. Mitigation: strict date normalization, exact-date preview fallback, no invoice/price computation, and locked copy.

Block-on-HIGH: yes. T-05 or T-06 failure blocks all Pricing and Dashboard integration.
</threat_model>
