<threat_model>
ASVS Level 1 scope: Pricing client billing-state transitions and session-bound financial mutation.

Threats:
- **T-01 HIGH - stale provisional state outranks webhook truth (ASVS V4/V5 business logic):** local provisional pending can keep a Current/Scheduled billing presentation after the authoritative profile clears, expires, or changes period, misrepresenting real billing status and hiding renewal recovery. Mitigation: retire provisional state as soon as the authoritative query confirms pending; after retirement, only `useSubscriptionState` drives the pending/expired/cleared presentation. Provisional never writes the profile.
- **T-02 HIGH - cross-session financial confirmation (ASVS V3 session / V5 business logic):** a downgrade dialog opened under user A can submit cancel-subscription after the authenticated session becomes user B, cancelling the wrong account. Mitigation: close/reset the dialog on authenticated-user change and re-read the current authenticated user immediately before invoking cancellation, aborting on any mismatch or absent user (zero cancel-subscription calls).

Block-on-HIGH: yes. T-01 or T-02 failure blocks completion; no stale-state override or cross-session cancellation path may be waived.
</threat_model>

<objective>
Close CR-01 and WR-01 in Pricing so authoritative webhook/profile truth always defeats stale provisional browser state, and no downgrade confirmation can act on a stale authenticated identity.

Purpose: Restore the D-03/D-14/D-18 invariant (authoritative state wins; expiry/renewal retires pending UI) and the D-04 duplicate/misdirected-mutation safety that the initial verification found broken on the same mount.
Output: Updated `src/pages/Pricing.tsx` transition logic plus focused regression tests.
</objective>
