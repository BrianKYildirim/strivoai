## Run-counting boundaries

### When a run begins

| Option | Description | Selected |
|--------|-------------|----------|
| After authentication and request-envelope validation | Create before content validation, extraction, Merit activity, or AI work | Yes |
| At Edge Function receipt | Also captures malformed and unauthorized traffic | No |
| When expensive work begins | Omits cache hits and early product failures | No |

**User's choice:** Option 1. After asking whether option 2 would help debugging, the user kept option 1 with the refined boundary that pre-auth/malformed traffic remains in diagnostics while post-auth content and processing failures remain in costing telemetry.

### Cache hits

| Option | Description | Selected |
|--------|-------------|----------|
| Completed run with cache/reuse marker | Counts successful product use with zero new AI cost | Yes |
| No feature run | Tracks newly generated output only | No |
| Record but exclude from completion and MAU | Preserves the event while defining MAU narrowly | No |

**User's choice:** Option 1.

### Reruns and Elite unlocks

| Option | Description | Selected |
|--------|-------------|----------|

| Update the original Free run | Loses historical tier and settlement boundaries | No |

**User's choice:** Option 1.

### Unfinished runs

| Option | Description | Selected |
|--------|-------------|----------|

## Reporting, exclusions, and retention

### Reporting surface

| Option | Description | Selected |
|--------|-------------|----------|

| SQL only | Flexible but manual for every refresh | No |

**User's choice:** Option 1. No user-facing dashboard.

### Internal/test-account exclusion

| Option | Description | Selected |
|--------|-------------|----------|
| Server-owned classification snapshotted on each run | Auditable and historically stable | Yes |
| Exclude admins/emails automatically | Current admin membership rewrites history | No |
| SQL-maintained list only | Hard to synchronize and reproduce | No |

**User's choice:** Option 1.

### Retention

| Option | Description | Selected |
|--------|-------------|----------|
| 24 months raw, 5 years privacy-safe aggregates | Supports seasonality and annual comparison | Yes |
| 13 months raw, 3 years aggregates | Smaller but shorter trend history | No |
| 180 days raw, no durable aggregates | Minimal retention with weak annual analysis | No |

**User's choice:** Option 1. Retention is automatically enforced.

### Account deletion

| Option | Description | Selected |
|--------|-------------|----------|
| Sever Auth UUID; retain irreversible costing subject | Preserves distinct-user history without an account link | Yes |
| Delete all telemetry | Historical totals shrink retroactively | No |
| Retain Auth UUID for 24 months | Simplest but retains an account identifier | No |

**User's choice:** The user replied `11`; interpreted as option 1 under the established repeated-selection convention and explicitly surfaced before final approval. The user then approved context generation.
