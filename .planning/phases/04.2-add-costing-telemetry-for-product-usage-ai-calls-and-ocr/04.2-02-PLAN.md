<threat_model>
## Trust Boundaries

| Boundary | Risk | Control |
|---|---|---|
| Client request -> feature-run snapshot | Spoofed user, tier, environment, or exclusion | Resolve all trusted fields after auth from server state/config |
| Retry wrapper -> AI ledger | Duplicate/misclassified attempts | Operation-scoped monotonic allocator and idempotent physical-attempt key |
| Provider response -> cost | Forged/unknown usage treated as zero | Exact response usage, effective pricing lookup, explicit unknown state |
| Telemetry DB -> product/Merit path | Instrumentation outage breaks paid feature | Awaited but caught never-throws helpers; existing lifecycle remains authority |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04.2-06 | Spoofing | Run snapshots | mitigate | Server-only tier/period/environment/exclusion resolution. |
| T-04.2-07 | Tampering | Attempt numbering and prices | mitigate | Shared allocator, effective price ID, raw usage preservation, idempotent key. |
| T-04.2-08 | Information Disclosure | Error/telemetry payload | mitigate | Controlled codes only; types exclude raw content and secrets. |
| T-04.2-09 | Denial of Service | Telemetry persistence | mitigate | Never-throws writes and no retry loop around a consistently unavailable telemetry route. |
| T-04.2-10 | Repudiation | Merit/refund linkage | mitigate | Observe canonical gateway result on the same immutable feature run. |
</threat_model>
