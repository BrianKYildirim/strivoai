<threat_model>
## Trust Boundaries

| Boundary | Risk | Control |
|---|---|---|
| Browser payload -> feature handler | Spoofed identity/tier/environment/cost | Auth, strict envelope, opaque token, server snapshot resolution |
| Cache/rerun/queue -> run ledger | Duplicate or mutated prior run | Stable action idempotency and explicit new run variants |
| Merit/provider/save -> terminal status | Cost/refund hidden by later failure | Correlate each result independently; terminalize truthfully once |
| Frontend storage/logging -> opaque token | Token replay or leakage | In-memory only, short lifetime, static negative assertions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04.2-16 | Spoofing | Feature requests | mitigate | Server auth and authoritative snapshot resolution. |
| T-04.2-17 | Tampering | Cache/rerun/job correlation | mitigate | Idempotent action key, explicit variant, immutable terminal runs. |
| T-04.2-18 | Repudiation | Merit/provider/result sequence | mitigate | Same run ID across exact gateway, attempt, save, and terminal evidence. |
| T-04.2-19 | Information Disclosure | Client correlation | mitigate | Opaque expiring token, no persistence/logging/URL exposure. |
| T-04.2-20 | Denial of Service | Telemetry outage | mitigate | Shared never-throws helpers; no product retries caused by telemetry. |
</threat_model>
