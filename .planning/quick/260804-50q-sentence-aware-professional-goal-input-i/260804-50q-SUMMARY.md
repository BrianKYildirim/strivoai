# Quick 260804-50q: Sentence-Aware Professional Goal Input Summary

Onboarding Step 4 now accepts one-to-two natural sentences in a 500-char textarea, and
`parse_professional_goal()` deterministically extracts six additional signals plus a
display summary and a keyword set — with **zero** additional AI calls, zero merit/billing
change and zero token-budget change, all provable from the diff.

---

## 1. The 11-key jsonb contract

`public.parse_professional_goal(p_goal text) RETURNS jsonb` — signature, `LANGUAGE plpgsql`,
`STABLE` and `SET search_path = public` are byte-identical to 20260712000002, so
`compute_goal_readiness` needed no edit and the trigger graph is untouched.

| # | Key | Status | Meaning |
|---|-----|--------|---------|
| 1 | `role` | LEGACY — semantics unchanged | longest `goal_taxonomy` role match, tie-break term ASC |
| 2 | `industry` | LEGACY — semantics unchanged | longest `goal_taxonomy` industry match, same tie-break |
| 3 | `location` | LEGACY key, **bug fixed** | preposition-anchored capitalized span; now skips taxonomy terms + month names |
| 4 | `opportunity_type` | LEGACY — original 9 terms in original order, 8 APPENDED | internship / co-op / … / summer analyst / off-cycle / … |
| 5 | `year` | LEGACY — semantics unchanged | first `20xx` |
| 6 | `timeframe` | **additive**, nullable | "summer 2027", "by end of 2027", "next year", "after graduation"… else falls back to `year` |
| 7 | `seniority` | **additive**, nullable | fixed most-specific-first list (vice president … vp) |
| 8 | `company_type` | **additive**, nullable | fixed longest-first list (leading global bank, bulge bracket, big four, startup…) |
| 9 | `long_term_direction` | **additive**, nullable | the user's own later-ambition clause, **verbatim**, capped at 200 chars |
| 10 | `normalized_summary` | **additive**, nullable | derived display label, `' • '`-joined, capped at 160 chars |
| 11 | `keywords` | **additive**, ALWAYS an array | all matched taxonomy terms + derived signals, distinct, sorted, capped at 12; `[]` when empty, never SQL NULL |

Keys 1–5 come first and in their original order. All six additive keys are OPTIONAL on the
TypeScript side (`?`), so a row persisted before this migration still type-checks and still
renders.

`COMMENT ON FUNCTION` records the contract in the database itself, including
"additive — readers must tolerate absent keys on rows parsed before 20260804010000".

### Scenario 1 — short phrase (`GP-01`)

Input: `Investment Banking Internship — NYC 2027`

```json
{
  "role": "Investment Banking",
  "year": "2027",
  "industry": "Investment Banking",
  "keywords": ["2027", "intern", "internship", "investment bank", "investment banking"],
  "location": null,
  "seniority": "intern",
  "timeframe": "2027",
  "company_type": "investment bank",
  "opportunity_type": "internship",
  "normalized_summary": "Investment Banking • Internship • 2027",
  "long_term_direction": null
}
```

`location` stays `null` because "NYC" is not preposition-anchored — the parser NEVER
guesses. That is unchanged from the old behaviour.

## 4. Migration and rollback

| | |
|---|---|
| Forward | `supabase/migrations/20260804010000_sentence_aware_goal_parsing.sql` |
| Rollback | `supabase/migrations/rollback/20260804010000_sentence_aware_goal_parsing.rollback.sql` |

The forward migration is **one statement**: `CREATE OR REPLACE FUNCTION`. No table, column,
constraint, policy, trigger, GRANT or REVOKE is touched, and no row is written.
`CREATE OR REPLACE` preserves the existing ACL, so the EXECUTE revokes from
`public`/`anon`/`authenticated` set by 20260712000002 survive.

The rollback restores the 20260712000002 parser body **verbatim**. Already-persisted 11-key
rows are harmless under rollback: every reader ignores the extra keys, and each row
re-collapses to 5 keys on the next trigger fire. No backfill needed in either direction.

Applied via the **CLI**, not the Supabase MCP `apply_migration`, so the Preview

(`zjpjapgraoxdukdvpjes`) immediately afterwards, and `db push` was **never** run against

**PRODUCTION IS NOT MIGRATED.** It still runs the 5-key parser. Applying it there requires

### Performance note

The previous body scanned `public.goal_taxonomy` **twice** (once for role, once for
industry). The new body scans it **once** and derives both from a single index-aligned
ordered result, so it is strictly faster. That matters: this runs inside an AFTER trigger on
the analyze-resume save tail, where `statement_timeout` is NOT caught by
`EXCEPTION WHEN OTHERS`.

## 6. Deviations from plan

### `[Rule 3 — Blocking]` Two guard counter assertions were stale and had never run

- **Found during:** Task 1C, when the extended guard was run standalone before registration.
- **Issue:** `goal-readiness-guard.test.ts` asserted that `cors-audit.test.ts` contains the
  literal `USER_FUNCTIONS.length, 20` and that `sanitizer-coverage.test.ts` contains
  `AI_INGESTERS.length, 5`. Both assertions **fail on unmodified HEAD** — verified by
  running `git show HEAD:...goal-readiness-guard.test.ts` unmodified (`43 passed | 2 failed`).
  The real values are `USER_FUNCTIONS.length, 19` (Paddle retirement and the LinkedIn
  free-scan removal each retired a function after 260712) and `sanitizer-coverage.test.ts`
  has **no `.length` assertion at all**, so that substring could never have matched. Both
  had gone undetected because the file is absent from `deno.json`'s `test:ci` — exactly the
  gap the plan's finding 6 identified.
- **Why it blocked:** Task 1C + Task 3B require this file to be registered in `test:ci`.
  Registering a red file turns `verify:baseline` red for reasons unrelated to this task.
- **Fix:** Both assertions now parse the files' **actual content** (regex-extract the pinned
  number; count the `AI_INGESTERS` entries) instead of matching a hardcoded assertion
  string, so they cannot silently rot again. The invariant is unchanged and still has teeth:
  these counts must not GROW because of goal work. `19` and `5` are the true current values.
- **Files modified:** `supabase/functions/_shared/goal-readiness-guard.test.ts`
- **Commit:** `8e2735f5`

### `[Rule 1 — Bug]` `company_type` echoed the role back into the display label

- **Found during:** Task 1 Preview spot-check.
- **Issue:** `'investment bank'` is a substring of `'investment banking'`, so the single most
  common existing goal format rendered as
  `Investment Banking • Internship • Investment Bank • New York • 2027` — the role repeated
  as a company type. The plan specified suppressing `industry` when it equals `role` but did
  not anticipate this second redundancy.
- **Fix:** `company_type` is dropped from `normalized_summary` when it is a substring of the
  role or the industry. **Display-only** — the `company_type` key itself and `keywords` are
  unaffected, and the scorer never reads either.
- **Files modified:** `supabase/migrations/20260804010000_sentence_aware_goal_parsing.sql`
- **Commit:** `8e2735f5`
