<objective>
Make onboarding Step 4 accept one-to-two natural sentences as well as a short phrase, and
deterministically extract a richer set of goal signals plus a normalized summary and keywords —
with **zero** additional AI/model calls, zero merit/billing change, and zero token-budget change.

Purpose: today the goal parser is a 5-key regex tuned for the em-dash phrase format. A user who
writes the way people actually write ("I want to secure an investment banking internship in New
York in 2027, ideally at a leading global bank. I want to build the experience needed to move into
private equity later.") loses the company-type preference, the long-term direction, and — worse —
can get a *taxonomy term* misread as a location. Goal Readiness then scores against a goal it only
half-understood.

Output: a sentence-aware `parse_professional_goal()` returning the 5 existing keys **unchanged**
plus 6 additive nullable keys (`timeframe`, `seniority`, `company_type`, `long_term_direction`,
`normalized_summary`, `keywords`); a textarea on both goal-edit surfaces; a summary-first dashboard
chip; and DB-backed + vitest proofs for all five required scenarios.
</objective>

**A. Write the forward migration** `20260804010000_sentence_aware_goal_parsing.sql`.

Header comment must follow the 20260712000002 house style: PURPOSE / ZERO AI (no `pg_net`, no
`http`, no `net.*`) / ADDITIVE (CREATE OR REPLACE only; no table, column, constraint, policy or
GRANT is touched) / ROLLBACK pointer to the sibling rollback file.

Single statement: `CREATE OR REPLACE FUNCTION public.parse_professional_goal(p_goal text) RETURNS
jsonb LANGUAGE plpgsql STABLE SET search_path = public`. **Signature, language, volatility and
`search_path` stay identical** so `compute_goal_readiness` needs no edit and the trigger graph is
untouched.

Body, in order:

1. `IF p_goal IS NULL OR btrim(p_goal) = '' THEN RETURN NULL; END IF;` (unchanged).
2. `v_norm := lower(p_goal);` and `v_flat := regexp_replace(btrim(p_goal), '\s+', ' ', 'g')`
   (whitespace-normalized copy used ONLY for derived fields — `p_goal` itself is never modified).
3. **Sentences.** `v_sentences := regexp_split_to_array(v_flat, '[.;!?]+(\s+|$)')`, drop empties,
   keep at most the first 4 elements (bounds the work).
4. **ONE taxonomy scan** (replaces today's two):
   ```sql
   WITH matched AS (
     SELECT t.kind, t.term FROM public.goal_taxonomy t
      WHERE position(lower(t.term) IN v_norm) > 0
   )
   SELECT
     (SELECT term FROM matched WHERE kind = 'role'     ORDER BY length(term) DESC, term ASC LIMIT 1),
     (SELECT term FROM matched WHERE kind = 'industry' ORDER BY length(term) DESC, term ASC LIMIT 1),
     COALESCE((SELECT array_agg(DISTINCT lower(term) ORDER BY lower(term)) FROM matched), ARRAY[]::text[])
     INTO v_role, v_industry, v_tax_terms;
   ```
   Longest-match-wins + the same deterministic tie-break, so `role`/`industry` are byte-identical
   to today.
5. **`year`** — unchanged: `substring(p_goal FROM '(20[0-9]{2})')`.
6. **`opportunity_type`** — keep the existing 9-element array **in its existing order**, then
   APPEND (never insert before) `'summer analyst','off-cycle','spring week','insight',
   'residency','traineeship','part-time','contract'`. Appending guarantees existing inputs resolve
   exactly as they do today.
7. **`location` — the fix.** Match ALL preposition-anchored capitalized spans, in order, capped at
   the first 5:
   `regexp_matches(v_flat, '(?:\ybased in\y|\ymoving to\y|\yrelocating to\y|\ymove to\y|\yin\y|\yat\y|\ynear\y)\s+([A-Z][A-Za-z.''-]*(?:\s+[A-Z][A-Za-z.''-]*){0,2})', 'g')`.
   Take the **first** candidate that is (a) non-blank and (b) whose `lower()` is NOT present in
   `v_tax_terms` and (c) not in a small fixed stopword set (`'i','strivo','ideally','my','the'` +
   the 12 month names). Otherwise NULL. **Never guess.** No nested quantifiers — the inner group is
   bounded `{0,2}`.
8. **`timeframe`** (NEW, distinct from `year`) — first hit of an ordered pattern list against
   `v_norm`, storing the matched substring lowercased:
   `(summer|fall|autumn|winter|spring)\s+20[0-9]{2}` · `q[1-4]\s*20[0-9]{2}` ·
   `by (the )?end of 20[0-9]{2}` · `by 20[0-9]{2}` ·
   `(with)?in (the )?next [0-9]{1,2} (months?|years?)` · `next (summer|year|semester|term)` ·
   `this (summer|year|semester)` · `after graduation` · `post[- ]graduation` · `long[- ]term`.
   If none match and `v_year` is non-null, `v_timeframe := v_year`.
9. **`seniority`** (NEW) — first hit over `v_norm` from a FIXED, most-specific-first array:
   `'vice president','head of','c-suite','entry-level','mid-level','intern','graduate','junior',
   'senior','analyst','associate','manager','director','principal','partner','lead','vp'`.
10. **`company_type`** (NEW) — first hit over `v_norm` from a FIXED, longest-first array:
    `'leading global bank','bulge bracket','bulge-bracket','elite boutique','middle market',
    'hedge fund','asset manager','investment bank','research lab','public sector','big tech',
    'fortune 500','big four','big 4','mbb','faang','boutique','startup','start-up','scale-up',
    'unicorn','consultancy','agency','nonprofit','ngo','government','academia','global bank','bank'`.
11. **`long_term_direction`** (NEW) — cue regex
    `\y(later|eventually|long[- ]term|longer[- ]term|down the line|ultimately|in the future|move into|transition into|pivot into|progress to|work towards|work toward)\y`.
    Walk `v_sentences` from index 2 upward; the FIRST sentence matching the cue is captured
    **verbatim** (user casing preserved), `btrim`med and `left(..., 200)`. If no later sentence
    matches, and sentence 1 matches the cue, capture from the cue's start index to the end of
    sentence 1 (same trim/cap). Else NULL.
12. **`keywords`** (NEW) — `to_jsonb()` of a text[] built from: `v_tax_terms` (ALL matched taxonomy
    terms, not just the longest) UNION lowercased non-null `v_location`, `v_opportunity`,
    `v_seniority`, `v_company_type`, `v_timeframe`, `v_year`. Filter `length >= 3`, DISTINCT,
    `ORDER BY 1`, then `[1:12]`. Always an array — `'[]'::jsonb` when empty, never SQL NULL.
13. **`normalized_summary`** (NEW) — join with `' • '` the non-null members of this FIXED ordered
    list, then `left(..., 160)`; NULL if the list is empty:
    `v_role`, `initcap(v_opportunity)`, `v_industry` (**only when `v_industry IS DISTINCT FROM
    v_role`**), `initcap(v_company_type)`, `v_location`, `COALESCE(v_timeframe, v_year)`.
    This is a DERIVED label only. It must never be written back to `professional_goal`.
14. `RETURN jsonb_build_object(...)` with **all 11 keys**, the 5 legacy keys FIRST and in their
    existing order.

Add a `COMMENT ON FUNCTION public.parse_professional_goal(text)` naming the 11 keys and stating
