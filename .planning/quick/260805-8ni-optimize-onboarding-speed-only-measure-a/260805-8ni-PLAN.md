## Task 2 — OPT-1 + OPT-3: remove the blocking token wait and parallelize independent work

**files:** `src/pages/Onboarding.tsx`

**action:**

**2a (OPT-1).** Move the `correlationEnvelope` construction and the `getFeatureRunToken()` call
from after the `resumes` insert (current lines ~418-434) to immediately **after the
`validate-document` gate** (current line ~357). Fire it **without awaiting**:

- keep `correlationEnvelope` assigned to the same outer `let` so the `finally`
  `clearFeatureRunToken(correlationEnvelope)` still runs on every terminal path;
- hold the in-flight promise in a local, and attach a `.catch(() => undefined)` **at creation
  time** so a 503 can never surface as an unhandled rejection;
- `await` that already-settled promise at the point the token is first consumed (immediately
  before the optional LinkedIn extraction / the parallel group), preserving the existing
  `try/catch → featureRunToken = undefined` fallback semantics exactly.

This overlaps the ~3.4 s `begin-feature-run` round-trip with upload → `createSignedUrl` →
`resumes` insert. It must **not** move the call earlier than the validation gate — doing so
would mint costing runs for documents that are later rejected (behavior change).

**2b (OPT-3).** Replace the sequential trio at current lines ~497 / ~502 / ~537:

```ts
const writeResults = await Promise.all(writes);
const resumeExtraction = await extractDocumentFromFile({ … });
…
await invalidateMerits();          // common branch only
```

with a concurrent group started together and resolved via `Promise.allSettled`, unwrapped in
**exactly the original failure order**:

1. writes rejection
2. writes `.error` field
3. extraction rejection
4. merits rejection

The `cameFromCheckout || pendingUpgradeTier` branch keeps `reconcileTierUpgrade` sequential and
after the group, with its `toast('Confirming your plan...')` in the same position — only the
common no-upgrade-signal branch is parallelized.

**Constraints — do not alter:**
- the `validate-document` gate or its early `return`
- `resumeRecordRef` reuse (one resumes row per attempt → one charge)
- the awaited upload → signed URL → insert order
- `sessionStorage['onboarding_wait_<id>']` written once before every `/results` navigation
- the `extractDocumentFromFile` arguments (`resumeId` must still be passed, so resume-text
  persistence for Career Compass is untouched)
- both `analyze-resume` dispatch branches' request bodies
- `toast.success("Setup complete! Analyzing your resume...")` position
- the `finally` teardown

**verify:** `npm run lint && npm run type-check && npm run test`

**done:** No `await` remains between the validation gate and the `resumes` insert other than the
pre-existing upload chain; writes/extraction/merits start concurrently; all existing
`Onboarding.*` tests pass unchanged.
