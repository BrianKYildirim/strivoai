<objective>
Fix the last REFUND-TRUTH violation: `_shared/terminalize-stuck-run.ts:136` persists
`patch.refunded = true` based on refund **eligibility** (`canRefund`) rather than refund
**outcome**, so a genuinely failed `refund_merits` RPC still marks the row as refunded.

Purpose: a false `refunded=true` is not self-healing. It is precisely what makes the row
ineligible for the `reap-stale-analysis-runs` backstop (which skips any row with
`merit_settled || refunded`, `reap-stale-analysis-runs/index.ts:186`). The comment at
`:126-127` promises "the idempotent reaper backstop will retry it" — and the very next
statement disarms that safety net, permanently stranding the user's Merit.

Output: outcome-derived column write, the return contract untouched, and a regression suite
covering all three refund outcomes.
