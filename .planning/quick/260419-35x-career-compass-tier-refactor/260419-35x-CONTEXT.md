# Quick Task 260419-35x: Career Compass Free-Tier Refactor + Tier-Gated Locks — Context

**Gathered:** 2026-04-19
**Status:** Ready for planning

<domain>
## Task Boundary

Refactor Career Compass so free-tier analysis runs as a **single Anthropic call** (≤4000 maxTokens, no parallel fan-out) and mirrors the Resume Analysis UX for tier gating: free users see every section with visible content at the top and blurred placeholder content below. Career Compass becomes **dependent on prior Resume Analysis AND prior LinkedIn Grader results** — both must already exist for the current user; neither the resume PDF nor the LinkedIn PDF is uploaded in the Career Compass flow anymore. The analysis consumes the richer structured outputs from those prior analyses. Pro and Elite behavior stays on the existing parallel fan-out path.

Scope: `supabase/functions/analyze-career/`, `src/pages/CareerCompass.tsx` + `src/components/career-compass/*`, shared tier-shape utility for career. Out of scope: Interview Prep, Recruiting Lens, LinkedIn Grader refactor, Resume Analysis refactor (resume analysis is the **reference** for locking — its lock logic/visuals are copied, not changed).

</domain>

<decisions>
## Implementation Decisions

### Backend — Free-tier execution model
- **Single call, not parallel.** Free tier bypasses `executeCareerParallelCalls` and uses a direct `invokeAnthropicText` call (same shape as the legacy path but budget-corrected).
- **maxTokens ≤ 4000** for free tier. Pro/Elite keep the existing parallel fan-out with their current budgets.
- **No hardcoded `maxTokens: 2500`.** Fix the line 1076 regression as part of this work — legacy free path must use 4000, not 2500.
- The Merit gateway wiring stays; merit cost unchanged at **3 merits** for free.

### Backend — Input sourcing (required prior analyses)
- Career Compass requires the caller to already have a **most-recent Resume Analysis** row AND a **most-recent LinkedIn Grader analysis** row for their `user_id`.
- If either is missing, return a **structured 412 (or equivalent)** response with flags `{ missing: ['resume' | 'linkedin' | 'both'] }` so the frontend can render a CTA directing the user to run the missing analysis first.
- Inputs consumed: **structured analysis outputs** (the richer JSON from the prior rows), not raw PDF text. Resume analysis JSON (scores + rewrites + summary) and LinkedIn grader JSON feed the Career Compass prompt.
- PDF storage paths / raw text are no longer accepted in the request body for Career Compass.

### Backend — Prompt + output shape (free tier)
- Free-tier prompt instructs the model to produce ONLY what the free UI renders as visible:
  - Full `careerDNA` (4 sentences)
  - Exactly **1** `careerFields` entry (the top best-fit field)
  - Exactly **1** `roles`/best-fit role entry
  - `roleReadinessBreakdown.overallScore` + `targetRole` only (no strengths/gaps/skillAssessments/readinessVerdict)
  - Exactly **first 2 phases** of 1 `roleRoadmaps` entry (not 5)
  - Omit: `surpriseFits`, remaining `careerFields`/`roles`/`roleRoadmaps`/`roadmap` categories
- Output-token budget of 4000 must cover this reduced shape with headroom.
- `applyCareerTierShape` is extended so even if the model overproduces, the server strips free-tier output down to the above whitelist (defense-in-depth, same spirit as existing D-07).

### Frontend — Tier gating pattern (mirrors Resume Analysis)
- Reuse the exact Resume Analysis locking visuals: blurred locked section with placeholder copy + upgrade CTA, same component (`ProFeatureBlur` or the equivalent used on `src/pages/Results.tsx`).
- **Visible content is always rendered above** the locked region in each section — tabs/layout reorder where necessary so the free-visible portion is at the top and the locked remainder is beneath.
- Placeholder copy under the blur is deterministic (not fetched from the backend). Same copy pattern Resume Analysis uses.
- Per-section free-tier visibility:
  | Section | Free visible | Free locked |
  |---|---|---|
  | Career DNA | All | — |
  | Best Fit Roles | 1st role | Rest of list |
  | Fields | 1st field | Rest of list |
  | Roles | 1st role | Rest of list |
  | Readiness | Score box | Strengths/Gaps/Assessments/Verdict |
  | Roadmap | First 2 phases | Remaining 3 phases |
  | Surprise Fits | — | Whole section (Pro/Elite only) |
- Pro unlocks: Surprise Fits + everything else. Elite: full, unchanged.

### Frontend — Layout
- Career Compass analysis page has unwanted horizontal whitespace on both sides. Make tabs fill the full page width with **only a small gutter between the left-hand nav and the right edge** (match the spacing pattern used by Resume Analysis Results or the most recently-updated feature page).

### Claude's Discretion
- Exact placeholder copy under locks (match Resume Analysis voice; don't invent a new pattern).
- Precise gutter value — match existing analysis-page convention, not a bespoke number.
- Whether to introduce a new `fetchPriorAnalysisInputs` helper or inline the two SELECTs in `analyze-career` — pick whichever is more consistent with the existing repo style.
- Error copy for the "missing prior analysis" CTA on the frontend — clear, actionable, match existing toast/CTA style.

</decisions>
