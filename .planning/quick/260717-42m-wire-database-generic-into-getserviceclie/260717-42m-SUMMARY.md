### What the generic found that nobody predicted (the real value)

- **`interview-prep-analyze:298`** — `resumes.file_path` is `string | null` and was passed
  straight into `.download()`. It only "worked" by round-tripping to storage and failing
  there. Now guarded explicitly, preserving the same error contract.
- **`extract-analysis-structure/types.ts` had drifted from the DB in three ways**, all
  invisible until the generic landed:
  - `analysis_type?: ExtractFeature` — the column is plain `text`, NOT an enum. The union
    asserted a guarantee the database does not make.
  - `raw_response: Record<string, unknown>` — the column is `jsonb`; the value may be an
    array or scalar. (Extractors already narrow via `asRecord()`, which is why it never bit.)
  - `created_at?: string \| null` — the column is NOT NULL.
  Replaced with a derived `Pick<Database[...]['Row'], ...>` so it cannot drift again. The
  file's own doc comment (written in 260717-0fo) had predicted exactly this moment.

### The `?? null` → `?? undefined` trap, checked rather than assumed

Three sites passed explicit `null` into optional RPC args. The naive fix is dangerous:
**omission only equals NULL when there are no overloads** — otherwise it re-dispatches to a
different function. Each was verified against the migrations:
- `create_or_recover_analysis_run` — single signature, `p_resume_id uuid DEFAULT NULL` →
  omission exactly equivalent. Safe.
- `check_and_deduct_merits` — in-code comments claimed a 3-arg overload existed, which would
  have made omission a real behavior change. `20260520000000_drop_legacy_check_and_deduct_merits_3arg.sql`
  **dropped it** — which is precisely why codegen emits a single entry here but a *union* for
  `record_ai_usage`. Only the 4-arg remains. Safe.

### One behavior change, deliberately surfaced not buried

`analyze-career:565`: `(x as unknown[]) || []` → `Array.isArray(x) ? x : []`. The old cast
erased at runtime to `x || []`, so a truthy non-array (e.g. a string) passed through into
the `key_insights` column; it now yields `[]`. This is defensive hardening and cannot make
previously-valid data invalid, but it is **not** strictly type-only. Flagged to the operator
rather than waved through.
