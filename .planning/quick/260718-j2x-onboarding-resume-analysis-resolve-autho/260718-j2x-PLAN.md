<objective>
Fix onboarding resume analysis so the generated analysis always reflects the user's
AUTHORITATIVE CURRENT subscription tier at the moment Finish is clicked, and restore a
continuous loading spinner (free + Elite) with a duplicate-submit guard.

Root cause (settled in CONTEXT — do not revisit): the backend `analyze-resume` already
resolves tier server-side from `profiles.subscription_tier` and discards `rawBody.tier`.
The bug is entitlement FRESHNESS — `profiles.subscription_tier` can still read `free` at
the instant Finish runs because a mid-onboarding Stripe upgrade has not yet propagated.
The `analyze-resume` free path then correctly produces a free-depth analysis while the UI
shows Elite chrome.

Fix locus: reuse the EXISTING freshness primitive `useMerits().reconcileTierUpgrade()`
(the same bounded poll Dashboard.tsx uses on `?checkout=complete`). No new abstraction, no
client-tier plumbing, no edge change, no edge redeploy. Pure frontend.

Purpose: paying Elite users must get Elite-depth analysis on their very first onboarding
run; the business-critical resume flow must never silently downgrade.
Output: updated `Onboarding.tsx` + reconciled recovery test + new behavioral freshness test.
</objective>
