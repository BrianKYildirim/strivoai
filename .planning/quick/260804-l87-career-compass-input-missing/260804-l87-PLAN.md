# Quick Task 260804-l87 — Career Compass `INPUT_MISSING` on a fresh Free account

## Problem (observed in production, 2026-08-04)

A brand-new Free account completed onboarding, Resume Analysis, and LinkedIn Grader
successfully, then Career Compass returned:

> "Analysis hit a server error — Our service had a hiccup — your Merits were refunded."

Production job `67b8e64f-22fd-44dd-916b-796d662d70d1`:
`failure_code=INPUT_MISSING`, `failure_stage=generating`, `merit_settled=false`,
`refunded=true`, `tier=free`.

## Root cause

A missing production secret cascaded into permanent loss of the user's resume text.

1. `STRIVO_RUNTIME_ENV` is documented as REQUIRED on Supabase prod secrets
   (`docs/ENVIRONMENT.md:79`) and is consumed by `_shared/runtime-environment.ts`,
   which THROWS when it is unset. It was never set in Production.
2. `createFeatureRun` catches that throw and returns `{ok:false}`, so
   `begin-feature-run` answers **503 `feature_run_unavailable`** on 100% of calls.
   Evidence: prod `feature_runs` and `costing_subjects` contain **0 rows, ever**.
3. Every caller swallows it (`catch { featureRunToken = undefined }`) — by design,
   telemetry is meant to be best-effort.
4. But `ocr-pdf` HARD-REQUIRES that token (`ocr-pdf/index.ts:343-353`) and answers
   **400 `invalid_feature_run_token`**. `persistAcceptedPdfjsResumeText` only
   `console.warn`ed and returned null.
5. So `resumes.extracted_text` was never written. Prod confirms the regression date:
   every resumes row through 2026-07-30 has text; **every row on 2026-08-03/04 has none**.
6. Backend raw-byte PDF parsing is an intentional no-op
   (`_shared/pdf-parser.ts` pins `pdfjsText:null`, `images:[]`,
   `claude_ocr_blocked_by_policy`), so the server cannot recover on its own.
7. `CareerCompass.tsx` only produced `resumeTextContent` when a NEW file was uploaded,
   so the saved-resume path sent none. All three sources empty →
   `analyze-career:1876` returns 400 → `INPUT_MISSING` → refund.

Resume Analysis passed because onboarding hands it the text INLINE in the same session.
LinkedIn Grader passed because it never reads resume text. Career Compass is the only
feature that must read resume text in a LATER session from persisted state.

**Ruled out:** the sentence-aware goal migration. Production HAS
`20260804010000_sentence_aware_goal_parsing`, the deployed `parse_professional_goal`
body is the new sentence-aware version, and the failing user's `career_targets` row
carries `professional_goal_structured` with all 11 keys and `goal_readiness_score=43`.
No edge function reads `professional_goal*` at all. There is NO schema/migration drift.

## Tasks

### Task 1 — Persist accepted browser resume text even when telemetry is down
- **files:** `src/lib/document-extraction.ts`
- **action:** When `persistAcceptedPdfjsResumeText`'s `ocr-pdf` call fails, write the
  accepted text straight to `resumes` via `persistAcceptedResumeTextDirect`, touching
  only the five sanctioned client-write columns (`extracted_text`, `text_hash`,
  `document_hash`, `extraction_version`, `extraction_metadata`). Return null on any
  failure so the caller falls through to its existing behavior.
- **verify:** `src/lib/__tests__/document-extraction.persistence.test.ts` fails without
  the change (`expected 1 call, got 0`) and passes with it.
- **done:** Accepted text survives a `begin-feature-run` outage.

### Task 2 — Resolve resume text on the saved-resume path and heal legacy rows
- **files:** `src/pages/CareerCompass.tsx`
- **action:** Read `id` + `extracted_text` with the saved resume. On submit with no new
  upload, use the durable text; if absent, download the stored file and re-extract with
  the same browser parser, threading `resumeId` so the row is healed permanently.
  Return `""` on any failure — never fabricate text.
- **verify:** `src/pages/__tests__/CareerCompass.saved-resume-text.test.ts`.
- **done:** Saved-resume submissions always carry text when it is recoverable.

### Task 3 — Regression coverage
- **files:** both test files above.
- **action:** Pin the exact production condition (`invalid_feature_run_token`), the
  server-owned column boundary, the no-fabrication rule, and that `analyze-career`
  still fails closed.
- **done:** `verify:baseline` green.
