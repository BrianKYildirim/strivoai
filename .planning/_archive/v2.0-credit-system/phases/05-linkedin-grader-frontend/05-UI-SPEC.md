## Spacing Scale

Declared values (all multiples of 4, mapped to existing Tailwind defaults — no new tokens):

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `p-1`, `gap-1` | Icon/text gap inside badges, copy-button padding |
| sm | 8px | `p-2`, `gap-2` | Inline element spacing inside insight cards, rewrite card header gap |
| md | 16px | `p-4`, `gap-4` | Default card padding, profileInsights grid gap, rewrite card body padding |
| lg | 24px | `p-6`, `gap-6` | Section padding inside `Card` shell, vertical gap between insight cards on mobile |
| xl | 32px | `py-8`, `gap-8` | Vertical gap between major result sections (Score → Insights → Strengths → Sections → Rewrites → Top Fixes) |
| 2xl | 48px | `py-12` | Page-level top/bottom padding under the navbar clearance |
| 3xl | 64px | `py-16` | Hero score block top breathing room on desktop |

Exceptions:
- Score circle hero element retains its current SVG-driven sizing (160px diameter on desktop, 120px on mobile) — this is a single visual primitive, not a layout token.
- Quoted-text callout inside profileInsights cards uses a 12px (`pl-3`) left-border indent — exception to the 8-point scale, justified because it mirrors the existing block-quote pattern already in `LinkedInGrader.tsx` and matches Tailwind's prose plugin convention.

## Typography

Exactly 4 sizes, exactly 2 weights. Inter font, line-height pairs match existing page conventions.

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|----------|
| Body | 16px | 400 (regular) | 1.5 | `text-base font-normal leading-normal` |
| Label | 14px | 600 (semibold) | 1.4 | `text-sm font-semibold` |
| Heading (section title) | 20px | 600 (semibold) | 1.3 | `text-xl font-semibold leading-tight` |
| Display (score numerals + "What's Working" hero) | 28px | 600 (semibold) | 1.2 | `text-3xl font-semibold leading-tight` |

Notes:
- Quoted profile text inside profileInsights cards uses Body size + italic style (`italic`). Italic is a style modifier, not a separate weight — still counts as weight 400.
- Score numerals inside the hero circle are an SVG/text override at 36px and are counted as a single one-off display primitive (not a new token).
- Numbered bullet markers in `feedback: string[]` arrays use Label spec.

## Color

The page uses semantic CSS variable tokens from `src/index.css` exclusively. No hardcoded hex per CLAUDE.md ("Use semantic design tokens, not hardcoded colors"). The 60/30/10 split below describes the visual weight of the LinkedIn Grader results page specifically.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` / `text-foreground` | Page background, body copy, default surface |
| Secondary (30%) | `bg-card` / `text-card-foreground`, `bg-muted` / `text-muted-foreground` | All result cards (insights, strengths, section breakdown, rewrites, top fixes), helper text under Analyze button, borders via `border-border` |
| Accent (10%) | `bg-primary` / `text-primary` / `text-primary-foreground` (coral `#FF5F67` brand color resolved through theme) | Primary "Analyze Profile" CTA, score progress ring, "headline" rewrite card top banner, link/hover states |
| Destructive | `bg-destructive` / `text-destructive` / `text-destructive-foreground` | Error toasts only — no destructive actions exist in this phase (no delete, no clear) |

Accent reserved for (explicit list — never "all interactive elements"):
1. The single primary CTA: "Analyze Profile" / "Re-scan Profile" button
2. The score progress ring stroke (driven by `getScoreColor` helper — already exists, unchanged)
3. The headline rewrite card top banner (`rewrites[0]`) — the hard invariant from CONTEXT.md D-06, framed with a coral/rose accent gradient via existing tokens
4. Active filter / focus rings (`ring-primary`)

NOT accent (must use neutral/secondary tokens):
- profileInsights cards — use emerald-tinted success token (`text-emerald-600 dark:text-emerald-400` is the existing pattern in `LinkedInGrader.tsx` for positive callouts; treat as a semantic "success" alias, not the brand accent)
- Key Strengths cards — `bg-card` with emerald icon only
- Section breakdown progress bars — driven by `getScoreColor` (status-derived: red/amber/emerald)
- topFixes cards — `bg-card` with neutral border

Dark mode: All tokens above resolve via `darkMode: ["class"]` already configured. No light-mode-only colors permitted.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (no prior scan) | `Analyze Profile` |
| Primary CTA (cached result visible) | `Re-scan Profile` |
| Secondary CTA after results | `Analyze Another Profile` (preserved from existing code) |
| Cross-feature CTA after results | `Grade My Resume Too` (preserved from existing code) |
| Entitlement helper — free available | `Free scan available this billing cycle` (emerald muted text directly under Analyze button) |
| Entitlement helper — credit will be used | `This will use 1 AI credit ({N} remaining)` — `{N}` populated when `useAiCredits` exposes balance, otherwise omit the parenthetical |
| Entitlement helper — query failed | `This will use 1 AI credit` (graceful degrade per CONTEXT.md Claude's Discretion bullet) |
| Entitlement helper — loading | `Checking eligibility…` (muted, no spinner — text-only to avoid layout shift) |
| profileInsights section heading | `What's Working For You` (per CONTEXT.md specifics — frames v3.0 mission "is my profile actually helping me get recruited") |
| profileInsights section subheading | `Standout elements recruiters notice first` |
| profileInsights empty state | Section is hidden entirely when `profileInsights.length === 0` (v3.0 contract guarantees 2-4 items, so this is a defensive fallback only — no copy needed) |
| Quoted-text callout label inside each insight card | `From your profile:` (small caps label above the italic quote) |
| Insight body line label | `Why this matters to recruiters:` |
| Key Strengths heading | `Key Strengths` (preserved) |
| Section Breakdown heading | `Score Breakdown` (preserved from current file) |
| Rewrites section heading | `Paste-Ready Rewrites` |
| Rewrites section subheading | `Drop these straight into your profile — no edits required` |
| Headline rewrite card label (`rewrites[0]`) | `Headline` with badge `Top Priority` |
| Generic rewrite card labels (`rewrites[1..3]`) | `Rewrite 2`, `Rewrite 3`, `Rewrite 4` (positional — backend does not label them beyond index) |
| Rewrite copy button | Icon-only `<Copy />` button with `aria-label="Copy rewrite to clipboard"` |
| Rewrite copy success | `Copied to clipboard!` (existing toast string — reused) |
| Top Fixes heading | `Ready-to-Paste Improvements` (preserved) |
| Top Fixes card before/after labels | `Current:` / `Suggested fix:` (updated from legacy `suggestedRewrite` wording) |
| Empty state — no profile analyzed yet | Heading: `Grade your LinkedIn profile` / Body: `Upload a PDF export or paste your profile text. We'll score it across 4 sections and give you paste-ready rewrites in under 60 seconds.` |
| Error state — analysis failed | `We couldn't analyze your profile. {server error message}. Try again or paste a shorter profile excerpt.` (uses existing `toast.error` pattern with `invokeWithTimeout` error shape) |
| Error state — entitlement query failed | (silent — degrade to "will use credit" helper, no toast) |
| Cache badge | `Last graded {relative date}` (preserved) |
| Destructive confirmations | None — this phase introduces zero destructive actions. Re-scan overwrites cached state but is non-destructive (server retains history in `linkedin_grades`). No confirmation modal needed. |

Voice rules:
- Second person ("your profile", "you").
- Active voice, present tense.
- Specific verbs over generic ("Re-scan", not "Submit"; "Drop these into", not "Use these").
- Numbers as digits (`1 AI credit`, `4 sections`, not `one AI credit`).
- No exclamation points except the existing `Copied to clipboard!` toast (preserved for consistency).

## Layout Rules

- Page max-width: `max-w-4xl mx-auto` (preserved from existing file).
- Vertical rhythm between major result sections: 32px (`space-y-8`).
- profileInsights grid: `grid-cols-1 md:grid-cols-2 gap-4` (md breakpoint = 768px, the existing Tailwind default).
- Rewrite cards: stacked vertically `space-y-4`, full-width inside `max-w-4xl`. Headline card (`rewrites[0]`) gets a top accent banner ~6px tall using `bg-primary/80`.
- Section breakdown cards: `grid-cols-1 md:grid-cols-2 gap-4` (4 cards = 2x2 on desktop, stacked on mobile).
- Navbar clearance: page top padding `pt-24` (96px) — preserved from existing IPC-11 fix already applied to the LinkedIn page.
- Touch targets: all interactive elements ≥ 44x44px. Copy buttons use `size="sm"` shadcn button which renders 36px — extend hit area with `p-2` wrapper to reach 44px on mobile.

|---------|---------|-------|-------|--------|----------|
| Primary CTA | `bg-primary` | `bg-primary/90` | `ring-2 ring-primary ring-offset-2` | `bg-primary/80` | `opacity-50 cursor-not-allowed` |

Loading states:
- During analysis: existing `UniversalAnalyzing` overlay with `linkedInSteps` — reused unchanged.
- Entitlement check: helper text shows `Checking eligibility…` without disabling the button (graceful degrade — if it never resolves, button still works and backend enforces the rule per D-09).

Animations:
- New profileInsights and rewrites blocks use `motion.div` with `initial={{ opacity: 0, y: 10 }}`, `animate={{ opacity: 1, y: 0 }}`, `transition={{ delay: index * 0.05, duration: 0.3 }}` to match the existing stagger pattern in the file.
- No animations longer than 400ms. No infinite animations on result content (only on the loading overlay).

## Accessibility Contract

- All icon-only buttons require `aria-label` (Copy buttons, score circle if interactive).
- Quoted profile text uses semantic `<blockquote>` element, not styled `<div>`.
- Section headings use `<h2>` for top-level result blocks (`What's Working For You`, `Key Strengths`, `Score Breakdown`, `Paste-Ready Rewrites`, `Ready-to-Paste Improvements`) and `<h3>` for cards within them.
- Color is never the sole signal: section status uses icon + text label, not just color. Score color is paired with the numeric value.
- Focus rings always visible (`ring-2 ring-primary ring-offset-2`) — never `outline-none` without replacement.
- Toast notifications are announced via sonner's built-in `aria-live` region (default behavior).
- Dark mode: every token used above resolves correctly through the `dark:` class — no light-only colors.
