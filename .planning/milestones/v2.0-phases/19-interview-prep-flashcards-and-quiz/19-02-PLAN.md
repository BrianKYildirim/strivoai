Create the directory `supabase/functions/interview-prep-analyze/` and the file `index.ts` inside it. The complete handler flow is specified below -- implement all 13 steps as a single cohesive edge function.

**Imports** (follow recruiting-lens/index.ts import pattern):
```typescript
import "https://deno.land/x/xhr@0.1.0/mod.ts";
import { serve } from "https://deno.land/std@0.168.0/http/server.ts";
```

**Handler flow** (inside `serve(async (req) => { ... })`):

1. OPTIONS handling: `if (req.method === 'OPTIONS') return handleOptionsRequest({ type: 'user' });`
2. Request ID + logger: `const reqId = crypto.randomUUID().slice(0, 8); const log = createLogger('interview-prep-analyze', reqId);`
3. Parse + validate body (BEFORE auth, before Merit -- per Pitfall 6 / D-02): Parse JSON body. Extract `jobDescription` (string, truncate to 12000 chars), `jobTitle` (string, truncate to 200), `company` (string, truncate to 200). If `jobDescription` missing or length < 50: return 400 `{ error: 'invalid_input', message: 'Job description is required (minimum 50 characters).' }`.
4. Auth: `const userContext = await requireAuth(req, { type: 'user' });` -- If null: return 401.
5. Tier gate (per D-13, IPC-01): If `userContext.tier === 'free'`: return 403 `{ error: 'pro_or_elite_required', message: 'Interview Prep requires Pro or Elite.' }`. Set `const tier = userContext.tier as Tier;` and `const isElite = tier === 'elite';`.
6. Per-feature rate limit: `checkRateLimit(userId, tier, { key: 'interview-prep-analyze', limits: { free: 0, pro: 10, elite: 20 } })`.
7. Daily cap check (Elite only, per D-11, D-12, IPC-06 -- BEFORE Merit deduction): COUNT interview_quizzes WHERE user_id AND mode='quiz' AND created_at >= todayMidnightUtc. If count >= 3: return 429 `{ error: 'daily_cap_reached', message: 'Daily quiz limit reached (3/3). Try again tomorrow.' }`.
8. Auto-fetch resume (per D-01, D-02 -- BEFORE Merit deduction): Query `resumes` table for most recent analyzed resume. If none: return 400 `{ error: 'no_resume' }`. Download PDF from Storage via `supabase.storage.from('resumes').download(resume.file_path)`. Extract text via `extractPDFText()`.
9. Sanitize user inputs: `const sanitizedJD = sanitizeUserContent(jobDescription, 'interview-prep-analyze', log);`
10. MERIT_SYSTEM_ENABLED branch (per D-06): `withMerits({ userId, tier, corsType: 'user' }, 'interview_prep', async (txId) => { ... })`. Inside the callback: build prompt via `loadPromptVariant('interview', tier, promptParams)`, call `invokeAnthropicText` with `model=getModel(tier, 'interview')`, `timeoutMs=getTimeout(tier, callType)` where callType is `'quiz'` for Elite or `'core'` for Pro, `maxTokens=10000` for Elite (IPC-10) or `6000` for Pro. Parse + validate with retry. Persist quiz row to `interview_quizzes` and questions/flashcards to `interview_quiz_answers`.

    **Streak update logic** (Elite only, per D-10, D-11, D-12 -- inside the withMerits callback AFTER successful quiz generation and DB persist):
    Fetch the user's current streak row from `interview_streaks` (maybeSingle). Compute `todayUtc` as `new Date()` truncated to UTC date (year, month, day). Compare against `last_quiz_date`:
    - If `last_quiz_date` is null (first ever quiz): set `current_streak = 1`.
    - If `todayUtc > last_quiz_date` (new calendar day): compare hours since `last_quiz_at`. If hours > 48 (streak expired), reset `current_streak = 1`. Otherwise increment `current_streak += 1`.
    - If `todayUtc === last_quiz_date` (same calendar day): no streak change (already incremented today).
    Upsert to `interview_streaks` with: `current_streak`, `last_quiz_at = new Date().toISOString()`, `last_quiz_date = todayUtc`, `updated_at = new Date().toISOString()`.
    Also count today's quiz usage (reuse the daily cap count query result or re-query) for the response.

    Build discriminated response: `{ mode: 'flashcard', flashcards: [...] }` for Pro or `{ mode: 'quiz', questions: [...], streak: {...}, daily_usage: {...} }` for Elite.

11. Legacy fallback (below the `if (MERIT_SYSTEM_ENABLED)` branch): This code path is only reachable when `MERIT_SYSTEM_ENABLED=false`. Per D-06, the frontend routing contract is: when `MERIT_SYSTEM_ENABLED=false`, the frontend calls `interview-prep-coach` (the legacy v1.0 function) directly -- it never calls `interview-prep-analyze`. The `interview-prep-analyze` function is a Merit-path-only function that did not exist before Phase 19. Therefore, return 503 with `{ error: 'merit_system_required', message: 'This function requires the Merit system. Use interview-prep-coach for legacy mode.' }` as a defensive guard. This is acceptable because the frontend only routes to this function when `MERIT_SYSTEM_ENABLED=true`.
12. parseAiResponse helper at module level: strip markdown fences, try JSON.parse, fallback to repairTruncatedJSON.
13. Error catch: log and return 500.

| client -> interview-prep-analyze | Untrusted JD text, optional title/company from browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-05 | Tampering | JD text prompt injection | mitigate | `sanitizeUserContent(jobDescription, ...)` strips known injection phrases before AI call |
| T-19-06 | Elevation of Privilege | Free user direct API call | mitigate | Server-side tier check `tier === 'free'` returns 403 before any processing |
| T-19-07 | Denial of Service | Daily cap bypass via concurrent requests | accept | Application-level COUNT check has a small race window for simultaneous requests; low risk since it requires sub-second concurrency from same user |
| T-19-08 | Spoofing | Forged tier in request | mitigate | Tier is read from `profiles.subscription_tier` via `requireAuth` -- never from request body |
| T-19-09 | Information Disclosure | Resume text in AI prompt | accept | Resume text is the user's own data being sent to Anthropic API for their own analysis; no cross-user data exposure |
| T-19-10 | Tampering | Merit deduction before valid input | mitigate | Input validation (JD length check) and resume existence check occur BEFORE the `withMerits` callback (Pitfall 6 defense) |
</threat_model>
