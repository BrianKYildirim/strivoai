## Cost map — where the (feature, tier) → Merit cost mapping lives

| Option | Description | Selected |
|--------|-------------|----------|
| Hardcoded CASE in RPC | One source of truth, no caller trust; cost changes need a migration. | |
| New lookup table `merit_feature_costs` | Seed table, joined by RPC, data-edit cost changes. | ✓ |
| Cost passed as RPC parameter | Trust moves to edge function callers. | |

**User's choice:** New lookup table `merit_feature_costs`
**Notes:** Enables frontend UX-02 cost previews via direct read, keeps RPC small.

---

## Refund bucket — what `refund_merits` does about origin buckets

| Option | Description | Selected |
|--------|-------------|----------|
| Return to original bucket(s) exactly | Reads original deduction, handles split deductions precisely. | ✓ |
| Always refund to shop_balance | Simple but breaks no-rollover semantics. | |
| Always refund to subscription_balance | Wrong for Free users, inflates next reset baseline. | |

**User's choice:** Return to original bucket(s) exactly
**Notes:** Drove the D-06 split-row design with shared `deduction_id` UUID.

## Reset RPC — what `reset_subscription_merits` enforces

| Option | Description | Selected |
|--------|-------------|----------|
| Dumb setter — always overwrites | Caller owns cadence; RPC trusts caller-supplied reset date. | ✓ |
| Cycle-aware — checks `reset_date` | Guards against premature reset but complicates TEST-02. | |
| Dumb setter, caller supplies next reset_date | Same as dumb setter but explicit about date param. | |

**User's choice:** Dumb setter — always overwrites
**Notes:** Date math lives in Phase 12 Stripe webhook. TEST-02 simulates reset dates via caller param.

## Split row — how split deductions are recorded

| Option | Description | Selected |
|--------|-------------|----------|
| Two rows sharing a `deduction_id` | Clean per-bucket refund, leverages existing `balance_type` column. | ✓ |
| Single row with JSON breakdown | Simpler reconciliation but `balance_type` becomes ambiguous. | |
| Single-bucket rule: never split | Sidesteps the problem but changes spec §2.6 behavior. | |

**User's choice:** Two rows sharing a `deduction_id`
**Notes:** `deduction_id` UUID is generated by RPC, returned as the refund handle.

## LIG-05 — who handles the free-monthly LinkedIn scan rule

| Option | Description | Selected |
|--------|-------------|----------|
| Caller handles — RPC stays dumb | Edge function reads `free_linkedin_scan_used`, skips RPC call. | ✓ |
| RPC handles — knows LIG-05 rule | Centralized but leaks feature policy into generic RPC. | |

**User's choice:** Caller handles — RPC stays dumb
**Notes:** `check_and_deduct_merits` signature stays clean: `(user_id, feature, tier)`.

## Cost table — shape of `merit_feature_costs`

| Option | Description | Selected |
|--------|-------------|----------|
| Minimal: `(feature, tier, cost)` + read-all RLS | Three columns, CHECK on tier, frontend can read for UX-02. | ✓ |

## Reconcile — surface for the MER-12 invariant

| Option | Description | Selected |
|--------|-------------|----------|
| RPC `reconcile_merit_balance(user_id)` | Per-user, callable from admin/cron/tests, matches "runnable on demand". | ✓ |
| SQL VIEW `merit_reconciliation` | Bulk drift query without procedural surface. | |
| Both — RPC wraps the view | More surface, more tests. | |

**User's choice:** RPC `reconcile_merit_balance(user_id)`
**Notes:** Returns `(user_id, balance_sum, transactions_sum, drift)`; invariant is `drift = 0`.

## Tier gate — how `check_and_deduct_merits` handles locked features

| Option | Description | Selected |
|--------|-------------|----------|
| Return `tier_locked` before balance check | Missing cost row = locked; zero deduction on locked features. | ✓ |

**User's choice:** Return `tier_locked` before balance check
**Notes:** Cost table becomes the single source of truth for both cost AND tier access.

## Refund age — time window on refunds

| Option | Description | Selected |
|--------|-------------|----------|
| No time window — any age | Idempotency via `refund_of` metadata check, not a clock. | ✓ |

**User's choice:** No time window — any age
**Notes:** Matches TEST-07 (AI failure refund) and leaves admin paths open.
