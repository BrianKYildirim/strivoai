## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI ↔ remote DB | `supabase db push` runs DDL with elevated Postgres role — drift between local SQL file and remote schema is a tampering vector |
| anon JWT ↔ tables | RLS is the last line of defense; a permissive INSERT/UPDATE/DELETE policy here would let any authenticated user forge rows |

## STRIDE Threat Register

ASVS categories: V4 Access Control, V8 Data Protection, V14 Configuration.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-RLS-01 | Elevation of Privilege | Missing SELECT-own policy lets user_B read user_A's quizzes | mitigate | Task 3 tests 6/7/8 assert anon + cross-user cannot read/update/delete; migration preserves existing SELECT-own policies |
| T-23-RLS-02 | Tampering | Permissive INSERT/UPDATE/DELETE policy added accidentally | mitigate | Task 1 acceptance grep for `CREATE POLICY.*(INSERT|UPDATE|DELETE).*auth.uid` returns zero; Task 3 test 5/7/8 confirms anon + cross-user cannot write |
| T-23-DB-01 | Tampering | `supabase db push` applies unintended diff (file drift) | mitigate | Task 2 dry-run gate: STOP if diff shows deletions or unrelated changes |
| T-23-DB-02 | Denial of Service | Partial-apply leaves schema inconsistent | accept | Supabase CLI wraps push in a transaction; on failure, file remains unchanged — re-run idempotent via `IF NOT EXISTS` / `IF EXISTS` guards |
| T-23-DB-03 | Information Disclosure | Verification query leaks table contents to logs | accept | Verification queries are metadata-only (`information_schema`, `pg_indexes`), no row data |
| T-23-IDX-01 | DoS | Missing index causes full-scan on daily-cap COUNT query | mitigate | Two partial indexes created on (user_id, created_at DESC) WHERE tier=... — bounds cap query to O(log n) |
