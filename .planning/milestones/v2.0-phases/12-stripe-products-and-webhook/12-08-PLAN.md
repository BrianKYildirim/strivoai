Current (buggy):
```typescript
function addOneMonth(iso: string): string {
  const d = new Date(iso);
  d.setUTCMonth(d.getUTCMonth() + 1);
  return d.toISOString();
}
```

Replace with:
```typescript
function addOneMonth(iso: string): string {
  const d = new Date(iso);
  const targetMonth = (d.getUTCMonth() + 1) % 12;
  d.setUTCMonth(d.getUTCMonth() + 1);
  // Clamp: if day overflowed into next month (e.g. Jan 31 -> Mar 3), use last day of target month
  if (d.getUTCMonth() !== targetMonth) {
    d.setUTCDate(0);
  }
  return d.toISOString();
}
```

This prevents subscribers with reset dates on the 29th, 30th, or 31st from drifting forward over successive months (e.g., Jan 31 -> Feb 28 -> Mar 28 instead of Jan 31 -> Mar 3 -> Apr 3).

to:

Change `log.warn` to `log.error` because a DB error is not a warning — it means data loss if treated as success.

Do the same for all four lookup blocks.

**Step 4:** Change the `if (!matchedBy)` block at lines 402-413 from always returning 200 to checking `dbErrorEncountered`:

```typescript
if (!matchedBy) {
  if (dbErrorEncountered) {
    log.error("profile-lookup-db-error", {
      eventId: event.id,
      type: event.type,
      searched: {
        hasCustomerId: !!customerId,
        hasSubscriptionId: !!subscriptionId,
        hasEmail: !!customerEmail,
```
