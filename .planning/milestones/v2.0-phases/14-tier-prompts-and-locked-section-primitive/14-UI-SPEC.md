# Phase 14 — UI Design Contract

> Visual and interaction contract for the three locked-tier UI primitives (`<LockedSection>`, `<LockedListItem>`, `<EliteFeatureGate>`) plus the `/dev/locked-sections` sandbox route. Generated by gsd-ui-researcher; verified by gsd-ui-checker.

Phase 14 ships ONLY the primitives and the dev sandbox. It does not gate any production feature surface — that work lands in Phases 15–19. The contract below is therefore intentionally tight: one component family, one sandbox page, zero call-site changes.

## Spacing Scale

Inherits Tailwind defaults (4px base unit). Phase 14 components use ONLY these tokens:

| Token | Value | Tailwind class | Usage in Phase 14 |
|-------|-------|----------------|-------------------|
| xs | 4px | `gap-1`, `p-1` | Icon-to-label gaps inside CTA button |
| sm | 8px | `gap-2`, `p-2` | Teaser line spacing, badge padding |
| md | 16px | `gap-4`, `p-4` | Default body padding inside `<LockedSection>` |
| lg | 24px | `gap-6`, `p-6` | `<LockedSection>` outer padding, header-to-body separator |
| xl | 32px | `gap-8`, `p-8` | Sandbox page section gap |
| 2xl | 48px | `gap-12` | Sandbox page top/bottom margin |

**Exceptions:**
- CTA `<Button>` minimum tap target: **44×44px** (mobile a11y requirement). Use `min-h-[44px] min-w-[44px]` on icon-only variants; default shadcn `Button size="default"` already meets this for text+icon.
- `<LockedListItem>` numbered cards MUST match the height of the unlocked sibling item exactly to avoid layout shift. Use `min-h-[var(--locked-item-height)]` set via inline style or matching Tailwind class — never an arbitrary px value that desyncs from the unlocked item.

## Typography

Phase 14 uses exactly **3 sizes** and **2 weights** — all via Tailwind utility classes, no custom CSS.

| Role | Size | Weight | Line Height | Tailwind | Usage |
|------|------|--------|-------------|----------|-------|
| Body / teaser | 16px | 400 (regular) | 1.5 | `text-base font-normal leading-normal` | The 1-sentence teaser inside `<LockedSection>`; default body text |
| Label / CTA | 14px | 600 (semibold) | 1.5 | `text-sm font-semibold leading-normal` | CTA button label, badge label, `<LockedListItem>` "Edit X of N — Locked" caption |
| Heading | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold leading-tight` | `<LockedSection>` visible header (the unblurred title above the locked body) |

`<EliteFeatureGate>` reuses the typographic scale of `<ProFeatureGate>` directly (it is a structural copy-paste per CONTEXT D-08); the table above governs `<LockedSection>` and `<LockedListItem>` only.

No display-size text in this phase. No third weight, no italics.

## Color

Strict semantic tokens only. No hardcoded hex values inside component bodies. The sole exception is `<EliteFeatureGate>`, which inherits the `featureColor?: string` prop precedent from `<ProFeatureGate>` (caller-provided HSL or hex string forwarded into inline style, used for accent glow only). Component internals NEVER hardcode colors.

| Role | Token | Tailwind | Usage in Phase 14 |
|------|-------|----------|-------------------|
| Dominant (60%) | `--background` | `bg-background text-foreground` | `<LockedSection>` outer surface, sandbox page background |
| Secondary (30%) | `--card`, `--muted` | `bg-card`, `bg-muted/40`, `border-border` | `<LockedSection>` body container, `<LockedListItem>` card surface, blurred-skeleton bars (`bg-muted/40`) |
| Accent (10%) | `--primary` | `bg-primary text-primary-foreground`, `text-primary` | CTA button background, lock icon glow ring, "Pro Exclusive" / "Elite Exclusive" badge |
| Muted text | `--muted-foreground` | `text-muted-foreground` | Teaser sentence, "Edit X of N — Locked" label |
| Destructive | `--destructive` | (not used in Phase 14) | No destructive actions in this phase |

**Accent (`--primary`) is reserved for these specific elements ONLY:**

1. The single primary upgrade CTA `<Button>` inside `<LockedSection>`, `<LockedListItem>`, and `<EliteFeatureGate>` (one CTA per instance, never multiple)
2. The lock-icon backplate (`bg-primary/15` tint behind the `<Lock>` glyph)
3. The tier badge ("PRO EXCLUSIVE" / "ELITE EXCLUSIVE")

Accent is NOT used on body text, borders, headers, hover states for non-CTA elements, or anywhere else.

**Dark mode contract:** every class above MUST render legibly in both themes via HSL CSS variables. Sandbox page MUST be tested in both `next-themes` modes before approval.

## Interaction Contract

### `<LockedSection>`
- **Blur strength:** body content rendered at `blur-[6px] opacity-40 select-none pointer-events-none` (matches `<ProFeatureGate>` precedent at line 95). Strong enough that text is unreadable; soft enough that layout structure remains visible — user perceives "there IS something there, but I can't read it."
- **Blurred body content:** generated skeleton placeholder bars (`bg-muted/40` rounded divs at varying widths). Callers do NOT supply children. Per CONTEXT D-05, the API is flat-props only.
- **Lock icon overlay:** centered over the blurred body, `Lock` glyph from lucide-react at 32px inside a 64×64 rounded-2xl plate (`bg-primary/15`, primary-tinted glow). Gentle scale pulse via framer-motion `animate={{ scale: [1, 1.05, 1] }}` on a 2s loop. NO rotation, NO shimmer animation — those belong to the heavier `<ProFeatureGate>`.
- **Header:** rendered ABOVE the blurred body, fully visible (not blurred). Uses Heading typography (20px / 600 / 1.2).
- **Teaser:** rendered BELOW the blurred body, fully visible. Body typography (16px / 400 / 1.5). Single sentence, never wraps to more than 2 lines on the narrowest supported viewport (320px).
- **CTA:** single shadcn `<Button variant="default" size="default">` below the teaser. Label text from copywriting contract below. On click → `navigate(ctaHref)` (default `/pricing`). NO inline upgrade modal in Phase 14 — Phase 20 owns the destination route.

### `<LockedListItem>`
- Renders a card with the same outer border-radius and border treatment as the unlocked sibling item.
- Shows the label `"Edit {index} of {total} — Locked"` (e.g. "Edit 2 of 5 — Locked") in 14px/600 muted-foreground color.
- Small 16px `<Lock>` icon inline-left of the label.
- One subtle CTA link "Upgrade to {Pro|Elite}" rendered as a shadcn `<Button variant="link" size="sm">` inside the card. NOT a full primary button — list items would otherwise create CTA overload.
- Height is matched to the unlocked item via the `min-h-[var(--locked-item-height)]` pattern. Sandbox MUST demonstrate this with a real-height unlocked sibling.

### `<EliteFeatureGate>`
- Structural copy-paste of `<ProFeatureGate>`. Same animation timeline, same layout, same Framer Motion choreography.
- Differences: badge text "ELITE EXCLUSIVE", default button label "Upgrade to Elite", default `featureColor` falls back to `hsl(var(--primary))` (no hardcoded blue).
- Renders children only when `userTier === 'elite'`; otherwise renders the locked card. Accepts `userTier: 'free' | 'pro' | 'elite'` prop.

### Accessibility (applies to all three primitives)
- Blurred placeholder body MUST have `aria-hidden="true"` so screen readers skip it entirely.
- The visible header, teaser, and CTA MUST be announced normally. The CTA `<Button>` MUST have an accessible name matching its visible label.
- The lock icon overlay is decorative: `aria-hidden="true"` on the icon wrapper.
- Tier badge ("PRO EXCLUSIVE") is announced as part of the natural reading order via plain text inside the `<Badge>`.
- Focus order: header → teaser → CTA. No tabbable elements inside the blurred body.
- CTA tap target ≥ 44×44px on mobile.
- Color contrast: every token combination above (foreground on background, primary-foreground on primary, muted-foreground on background) MUST meet WCAG AA 4.5:1 in both light and dark themes — confirm in sandbox.

### Animation
- Reuse Framer Motion patterns from `<ProFeatureGate>` for `<EliteFeatureGate>` verbatim.
- For `<LockedSection>` and `<LockedListItem>`, use ONLY: (1) the gentle 2s scale pulse on the lock icon, (2) a one-shot `initial={{ opacity: 0 }} animate={{ opacity: 1 }}` fade-in on mount with 200ms duration. No rotating gradient borders, no shimmer overlays, no floating sparkles. The heavier choreography is reserved for whole-feature gates.
- Respect `prefers-reduced-motion`: when set, all motion components fall back to static states. Use Framer Motion's `useReducedMotion()` hook.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — `<LockedSection>` (Pro lock) | `Upgrade to Pro` |
| Primary CTA — `<LockedSection>` (Elite lock) | `Upgrade to Elite` |
| Primary CTA — `<EliteFeatureGate>` | `Upgrade to Elite` |
| Primary CTA — `<LockedListItem>` (Pro lock) | `Upgrade to Pro` (rendered as `<Button variant="link">`) |
| Primary CTA — `<LockedListItem>` (Elite lock) | `Upgrade to Elite` (rendered as `<Button variant="link">`) |
| `<LockedSection>` header default | Caller-supplied via `title` prop — REQUIRED, no default. Sandbox examples: `Power Phrases`, `Recruiter Insights`, `Industry Keywords` |
| `<LockedSection>` teaser default | Caller-supplied via `teaser` prop — REQUIRED, no default. Pattern: `"{Tier} unlocks {short concrete benefit}."` Sandbox example: `"Elite unlocks 5–8 industry-specific phrases."` |
| `<LockedListItem>` label pattern | `Edit {index} of {total} — Locked` (literal en-dash `—`, not hyphen) |
| Tier badge — Pro lock | `PRO EXCLUSIVE` (uppercase, tracked +0.05em via `tracking-wide`) |
| Tier badge — Elite lock | `ELITE EXCLUSIVE` (uppercase, tracked +0.05em via `tracking-wide`) |
| Empty state heading | Not applicable — Phase 14 ships no data-driven views. Sandbox is hand-authored static content. |
| Empty state body | Not applicable. |
| Error state | Not applicable — primitives do not perform fetches or have failure modes. The `ctaHref` link relies on React Router's standard fallback when `/pricing` does not yet exist (Phase 20). |
| Destructive confirmation | None — Phase 14 has zero destructive actions. |

**Voice rules:**
- Use the imperative for CTAs ("Upgrade to Pro", not "Click here to upgrade" or "You should upgrade").
- Teasers use present tense and name the tier explicitly ("Elite unlocks…", not "Unlock by upgrading…").
- Never use the word "premium" — say "Pro" or "Elite" by name.
- Never apologize ("Sorry, this is locked"). Frame as opportunity, not denial.

## Dev Sandbox Route Contract (`/dev/locked-sections`)

- **Path:** `/dev/locked-sections` (final path is Claude's Discretion per CONTEXT D-10; this is the recommended default).
- **Gating:** wrap the route element in an `import.meta.env.DEV` check at the router level so production bundles tree-shake the module entirely (zero bytes shipped to prod).
- **Layout:** vertical stack of labeled sections, each demonstrating one variant with sample data. Use 2xl spacing between sections, lg spacing inside.
- **Required variants on the page:**
  1. `<LockedSection requiredTier="pro" />` with sample title + teaser
  2. `<LockedSection requiredTier="elite" />` with sample title + teaser
  3. `<LockedListItem>` array — 1 unlocked card (real content) + 4 locked cards (`index={2..5}`, `total={5}`) demonstrating height parity
  4. `<EliteFeatureGate userTier="pro">` rendering a placeholder Elite-only field
  5. `<EliteFeatureGate userTier="elite">` rendering the same field unlocked, to prove the gate releases
- **Theme toggle:** include a one-line theme-toggle button at the top of the sandbox so the developer can verify both light and dark themes in a single screen.
- **Copy as documentation:** each section has a small caption above it explaining the intended call-site usage. This page IS the Phase 15–19 author reference.
