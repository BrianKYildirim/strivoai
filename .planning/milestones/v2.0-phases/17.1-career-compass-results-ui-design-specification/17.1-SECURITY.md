## Implementation Notes

- **BlurredLockCard deviation.** Plans 17.1-01 and 17.1-02 specified `LockedListItem` / `LockedSection` as the locked-content primitive. The implementation uses `BlurredLockCard` (see `src/components/BlurredLockCard.tsx`) — the replacement primitive referenced in the deprecated-banner comments at `LockedListItem.tsx:15-20` and `LockedSection.tsx:15-20`. The T-17.1-04 security property (no Pro/Elite payload embedded in DOM for Free users) still holds because every `BlurredLockCard` site in this phase fills its children with hardcoded static strings, not `analysis.*` data.
- **CSS blur is not a security control.** `BlurredLockCard` applies `blur-md opacity-60` at `BlurredLockCard.tsx:40`. This is purely a visual affordance; its children are hardcoded placeholders rather than gated secrets, so no data confidentiality depends on the filter.
- **Elite payload access pattern.** `src/pages/CareerCompass.tsx:889-900` reads `(analysis as any).compensationIntelligence` to feed Elite-only tabs. Access is wrapped in `subscriptionTier === "elite"` JSX guards at lines 884 and 896. The backend tier-shaping contract (Phase 17 D-14) remains the authoritative trust boundary.

## Residual Risk

All seven items are residual by design (`accept` disposition). The accepted posture depends on the Phase 17 backend tier-shaping contract (D-14): if that contract regresses and Pro/Elite fields leak to Free users in the payload, the display-only gating in this phase's UI will not prevent exposure. Mitigation for that regression path must live in Phase 17 backend tests, not in this phase's UI.
