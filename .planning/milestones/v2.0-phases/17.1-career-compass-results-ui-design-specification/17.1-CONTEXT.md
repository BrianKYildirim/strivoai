# Phase 17.1: Career Compass Results UI Design Specification - Context

**Gathered:** 2026-04-18
**Status:** Ready for planning

<domain>
## Phase Boundary

Implement the Career Compass **results display** frontend according to the UI-SPEC.md design contract. Decompose the existing 2036-line `CareerCompass.tsx` monolith into focused subcomponents, wire tier-conditional rendering (Free/Pro/Elite), and deliver all visual elements specified in the UI-SPEC (score ring, semantic colors, confetti, cached banner, animations).

**In scope:**
- Results rendering: Career DNA card, Best-Fit Role Families, Surprise Fits, 6-tab panel (Fields, Roles, Readiness, Roadmap, Salary, Strategy)
- Tier-conditional rendering with LockedSection/LockedListItem for Free users
- Tab count adapting to tier (4 for Free/Pro, 6 for Elite)
- SVG radial score ring with semantic emerald/amber/red colors
- Role comparison dialog and multi-role readiness display
- Confetti, fade-in animations, LockedSection motion effects
- Cached results banner with refresh button
- Component decomposition into `src/components/career-compass/`

**Out of scope:**
- Input form (resume upload, LinkedIn PDF, LinkedIn URL) — stays as-is
- Backend changes (Phase 17 handles gating, tier resolution, output shaping)
- Other features' UI — only Career Compass results page

</domain>

<decisions>
## Implementation Decisions

### Page Restructuring

- **D-01:** Split `CareerCompass.tsx` (2036 lines) into subcomponents. The main `pages/CareerCompass.tsx` becomes an orchestrator (~200 lines) handling state, data fetching, and routing between input form and results view.
- **D-02:** Subcomponents live in `src/components/career-compass/`. Expected components: CareerDNACard, BestFitRoles, SurpriseFits, ReadinessTab, FieldsTab, RolesTab, RoadmapTab, ScoreRing, RoleComparisonDialog, CachedResultsBanner, and tier-specific wrappers as needed.

### Scope

- **D-03:** This phase covers **results display only**. The input form (resume upload, LinkedIn PDF input, LinkedIn URL) is not redesigned in this phase — it stays as-is in the orchestrator page.

### Upgrade Flow

- **D-04:** Locked section upgrade CTAs navigate to `/pricing`. Both `LockedSection` and `LockedListItem` already default `ctaHref="/pricing"` — no changes needed to the shared components. Career Compass passes no custom `ctaHref`.

### Visual Polish

- **D-05:** All visual elements from the UI-SPEC are must-haves: tier-conditional rendering, SVG score ring with semantic colors, confetti on completion, fade-in animations, cached results banner.
- **D-06:** **Preserve + adjust** approach — keep existing working visual code (confetti, score ring, tab structure, locked sections) and adjust only where the UI-SPEC specifies differences. Minimize churn and regression risk.

### Claude's Discretion

- Exact subcomponent boundaries and prop interfaces — planner decides based on data flow analysis
- Whether to extract the AVAILABLE_ROLES constant to a shared file or keep inline
- Internal state management within subcomponents (local state vs. props drilling vs. context)
- Exact CSS class adjustments to match UI-SPEC spacing/typography tokens

</decisions>

### Established Patterns
- **Tabs with tier-conditional count**: Current code already renders 4 tabs for Free/Pro and 6 for Elite (lines 1174-1207).
- **SVG radial score ring**: Current code has inline SVG circle with dasharray calculation (around line 1282).
- **Confetti on completion**: `canvas-confetti` fires in useEffect when analysis completes.
- **Semantic score colors**: Emerald/amber/red already used for score badges and progress bars.
- **invokeWithTimeout**: Supabase function call wrapper with timeout handling, already in use.

### Integration Points
- **State management**: `useState` for analysis result, loading, comparison state. `useAiCredits` for merit/credit context. `useAdminTierTest` for admin tier override.
- **Route**: `/career-compass` in App.tsx router.
- **Data flow**: `invokeWithTimeout('analyze-career', ...)` returns analysis JSON → stored in `analysis` state → rendered by tab panels.

<specifics>
## Specific Ideas

- The existing 2036-line file already implements most of the UI-SPEC's visual elements — the decomposition is primarily about maintainability and testability, not a visual redesign.
- The "preserve + adjust" approach means reading the UI-SPEC for any spacing, typography, or color differences from current code and adjusting only those — not rewriting working visual code.
- The input form section (~lines 722-1020) stays in the orchestrator page but could be extracted as a single `CareerCompassInput` component for cleanliness without redesigning it.

</specifics>
