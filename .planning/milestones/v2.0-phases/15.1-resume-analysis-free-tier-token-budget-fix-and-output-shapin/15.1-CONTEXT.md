# Phase 15.1: Resume Analysis Free-Tier Token Budget Fix & Output Shaping - Context

**Gathered:** 2026-04-17 (updated)
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix free-tier resume analysis to correctly display partial results with visible lock states, ensuring free users see how much they're missing. Changes span both backend (output shaping) and frontend (per-item lock/unlock rendering).

**Backend changes:**

1. **Collapse 3 parallel Anthropic calls to 1** for Free tier — resume text input sent once instead of 3x.
2. **Right-size the Free maxTokens budget** — current 6000 cap is overprovisioned for the spec's ~3,500 actual output.
3. **Align OCR PDF function** with tier-config model selection and lower per-page token budget.
4. **Switch unlocked criteria from C1 to C6** — `applyTierShape` must keep C6 (Achievement Orientation, 20% weight) with full 3-bullet feedback, not C1 (Visual Clarity).
5. **Ensure Free tier never generates locked content** — single-call prompt only requests visible fields, reinforced by `applyTierShape` defense-in-depth.

**Frontend changes:**

6. **Always show all sections** to free users — score, executive summary, resume signals, strengths, priority actions fully visible.
7. **Priority Improvements**: show 1 real entry + 4 hardcoded placeholder entries behind blur.
8. **Detailed Criteria Analysis**: show Achievement Orientation (C6) fully unlocked with 3 bullet points; lock all other 10 criteria entirely (name, score, bullets all blurred).
9. **Remove first-analysis bypass** — free users always see the partial/locked view.

**Out of scope:**

* Tier gating for other features (Phases 16-19)
* Changes to Pro/Elite call architecture or budgets
* Merit deduction logic changes (Phase 13 contract unchanged)
* Changes to the async queue path (process-resume-analysis-job)

</domain>

<decisions>
## Implementation Decisions

### Free-Tier Call Architecture

* **D-01:** Free tier uses a **single Anthropic call** instead of the current 3 parallel calls. The single call produces the complete Free output JSON in one shot: all 11 criterion scores (C6 detailed with 3 bullets, others score-only), `executiveSummary`, `resumeSignal`, full `strengths`, and exactly 1 `priorityImprovements` entry. Resume input is sent once, cutting input token cost by ~67%.
* **D-02:** The single Free call uses **maxTokens: 4000** — ~15% headroom above the spec's ~3,500 actual output.
* **D-03:** **`TIER_MAX_TOKENS.free`** **stays at 6000** in `tier-config.ts`. The 4000 cap is a local override in `analyze-resume/index.ts`.

### Single-Call Prompt

* **D-04:** A **new** **`buildFreeConsolidatedPrompt()`** function in `resume-prompts.ts` produces the system prompt for the single Free call. Must request all 11 criteria scores, C6 (Achievement Orientation) detailed feedback with 3 bullets, and summary fields in one JSON response.
* **D-05:** The single Free call **bypasses** **`mergeAndValidateResults()`**. The response is parsed (with `repairTruncatedJSON` if needed), then passed through `applyTierShape(result, 'free')` and `reconcileScore()`.

### Backend Criteria Shaping

* **D-06:** **`applyTierShape` must keep C6 (Achievement Orientation & Quantified Impact, 20% weight) with full feedback**, not C1 (Visual Clarity). Find by `id === 'c6_achievement_orientation'` instead of using index 0. Strip feedback from all other criteria to `{id, label, weight, score}`.
* **D-07:** C6 feedback must contain exactly **3 bullet points** for free tier (the standard `{observation, impact, fix}` format).

### Quality Floor

* **D-08:** A **quality floor check** validates the single-call output: if all criterion scores are 0 or all are identical, **retry once** before returning an error.

### Fallback Path

* **D-09:** The existing all-calls-fail fallback path uses **`buildFreeConsolidatedPrompt()`** for Free users. Pro/Elite fallback remains `buildFallbackPrompt()`.

### OCR PDF Alignment

* **D-10:** OCR PDF keeps Haiku for all tiers. Import `FREE_MODEL` from `tier-config.ts` instead of env var.
* **D-11:** OCR does not deduct Merits. It's a pre-processing step.
* **D-12:** OCR maxTokens lowered from 4000 to 3000 per page.

### Frontend — Free Tier Display

* **D-13:** **Remove the `isFirstAnalysis` bypass.** Free users ALWAYS see the partial/locked view, even on their very first analysis. Delete the condition `showFullResults = isFirstAnalysis === true || userTier !== 'free'` and replace with `showFullResults = userTier !== 'free'`.
* **D-14:** **All sections render for free users.** Score, executive summary, resume signals, strengths, priority actions section generate and display fully.
* **D-15:** **Priority Improvements section** always renders for free users:
  - 1 real improvement entry (from backend `priorityImprovements[0]`) renders normally at the top
  - Below it, an "Upgrade to unlock 4 more improvements" divider
  - 4 hardcoded placeholder entries rendered with blurred teaser text behind a blur effect with lock icon — creates FOMO. Placeholder text is frontend-hardcoded (no backend token cost).
* **D-16:** **Detailed Criteria Analysis section** for free users:
  - Achievement Orientation & Quantified Impact (C6, 20% weight) renders fully unlocked with its 3 feedback bullet points at the top
  - Below it, an "Upgrade to unlock 10 more criteria" divider
  - The other 10 criteria are **entirely behind blur** — name, score bar, weight badge, and bullets all locked. These use frontend-hardcoded placeholder text behind blur.
* **D-17:** **Placeholder approach:** Frontend hardcodes realistic-sounding teaser text for locked items. Blurred so users can see there's content but can't read it. No backend generation needed — zero token cost for placeholders.

### Claude's Discretion

* Exact structure and wording of `buildFreeConsolidatedPrompt()` — must request C6 detailed feedback specifically.
* Whether `CALL_CONFIGS` is modified or a separate code path is used before `executeParallelCalls`.
* How the quality floor retry integrates.
* Whether `reconcileScore()` applies before or after `applyTierShape`.
* Specific placeholder teaser text strings for the 4 fake improvements and 10 locked criteria.
* Visual styling of the "Upgrade to unlock X more" divider.

</decisions>

<specifics>
## Specific Ideas

* The existing fallback path (lines 340-378) is structurally identical to what the Free single-call path needs.
* `applyTierShape` should find C6 by `id === 'c6_achievement_orientation'` not by array index — more robust against reordering.
* Frontend sorts criteria by `weight` descending, so Achievement Orientation (20%) naturally appears first after sort.
* The split-section pattern (unlocked items, divider, blurred locked items) should be reusable across Priority Improvements and Detailed Criteria sections.
* Placeholder pool for improvements could include things like "Restructure your experience section for maximum recruiter impact" — realistic-sounding but generic, behind blur so exact text doesn't matter much.
