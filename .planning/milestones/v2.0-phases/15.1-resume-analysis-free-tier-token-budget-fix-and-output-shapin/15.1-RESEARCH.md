# Phase 15.1: Resume Analysis Free-Tier Token Budget Fix & Output Shaping - Research

**Researched:** 2026-04-17
**Domain:** Supabase Edge Function (Deno) -- Anthropic API call architecture, token budget optimization, prompt engineering
**Confidence:** HIGH

## Summary

Phase 15.1 is a cost optimization and output shaping phase for the Free tier of `analyze-resume`. The current implementation sends the resume text 3 times (criteria-1, criteria-2, summary) as parallel calls, paying 3x input token cost for a tier that only produces ~3,500 output tokens. The fix collapses Free to a single Anthropic call, right-sizes `maxTokens` to 4000 (from the 6000 cap allocated across the 3-call split), and aligns the OCR PDF function with tier-config model selection.

The codebase is well-structured for this change. The existing fallback single-call path (lines 340-378 in `analyze-resume/index.ts`) is structurally identical to what the new Free primary path needs: single Anthropic call -> JSON parse -> `reconcileScore()` -> `applyTierShape()`. The new `buildFreeConsolidatedPrompt()` function in `resume-prompts.ts` produces a purpose-built single-call prompt. Pro and Elite paths remain completely unchanged -- this is strictly Free tier optimization.

**Primary recommendation:** Add a Free-tier branch before `executeParallelCalls()` in both the merit and legacy paths, following the existing fallback pattern. The new prompt function is the only net-new code; everything else is routing logic reusing existing infrastructure.

### Pattern 1: Free Single-Call Branch (Before Parallel Fan-Out)

**What:** Insert a tier check before `executeParallelCalls()` that routes Free users to a single-call path.
**When to use:** `resolvedTier === 'free'`
**Example:**

```typescript
// Source: existing fallback pattern at analyze-resume/index.ts:340-378
// D-01: Free tier uses single Anthropic call (not 3 parallel)
if (resolvedTier === 'free') {
  const FREE_SINGLE_CALL_MAX_TOKENS = 4000; // D-02: local override, not TIER_MAX_TOKENS
  const freeSystemPrompt = buildFreeConsolidatedPrompt(promptParams, improvementContext);

  const freeResp = await invokeAnthropicText({
    model: ANTHROPIC_MODEL_TEXT,
    system: freeSystemPrompt,
    messages: [{ role: 'user', content: userPrompt }],
    maxTokens: FREE_SINGLE_CALL_MAX_TOKENS,
    temperature: 0.3,
    fixtureKey: 'analyze_resume',
    timeoutMs: getTimeout(resolvedTier as Tier),
  });

  if (!freeResp.ok) throw new MeritRefundable(freeResp.status, freeResp.error);

  const repaired = repairTruncatedJSON(freeResp.text.trim());
  let freeResult: Record<string, any>;
  try {
    freeResult = JSON.parse(repaired);
  } catch (parseErr) {
    throw new MeritRefundable(500, `JSON parse failed: ${(parseErr as Error).message}`);
  }

  // D-06: Quality floor check
  if (!passesQualityFloor(freeResult)) {
    // Retry once
    const retryResp = await invokeAnthropicText({ /* same params */ });
    // ... parse and validate retry ...
  }

  freeResult = reconcileScore(freeResult);
  applyTierShape(freeResult, 'free');
  freeResult._mergeSource = 'free-single';

  // DB update + return
  // ...
}
// Pro/Elite continue to executeParallelCalls() below
```

### Pattern 2: Quality Floor Check

**What:** Validates single-call output isn't degenerate (all scores zero or all identical).
**When to use:** After JSON parse, before `reconcileScore`/`applyTierShape`.
**Example:**

```typescript
// Source: CONTEXT.md D-06
function passesQualityFloor(result: Record<string, unknown>): boolean {
  const criteria = (result.criterionFeedback || result.criteria || []) as Array<{ score?: number }>;
  if (criteria.length === 0) return false;

  const scores = criteria.map(c => Number(c.score) || 0);
  const allZero = scores.every(s => s === 0);
  const allIdentical = scores.every(s => s === scores[0]);

  return !allZero && !allIdentical;
}
```

- **Modifying `CALL_CONFIGS` maxTokensFree values to 0:** This would work but is fragile -- future developers would need to understand that `maxTokensFree: 0` means "skip for free" rather than "budget is 0". A direct tier check before the parallel path is clearer. [ASSUMED -- discretion area, either approach works per CONTEXT.md]

## Common Pitfalls

### Pitfall 1: Boot-Time Assertion Failure After Free Path Change

**What goes wrong:** The existing boot-time assertion at `analyze-resume/index.ts:53-60` sums `CALL_CONFIGS[tier]` and checks against `TIER_MAX_TOKENS[tier]`. If the Free single-call path uses a local 4000 cap instead of CALL_CONFIGS entries, the assertion still checks the old CALL_CONFIGS free values (sum = 6000) against `TIER_MAX_TOKENS.free` (6000) which passes -- but is now semantically wrong since Free no longer uses those configs.
**Why it happens:** The assertion was designed for the 3-call architecture. The Free single-call path bypasses CALL_CONFIGS entirely.
**How to avoid:** Either (a) add a separate assertion for the Free single-call cap: `FREE_SINGLE_CALL_MAX_TOKENS <= TIER_MAX_TOKENS.free`, or (b) set `maxTokensFree: 0` in all CALL_CONFIGS entries and add a separate assertion that `FREE_SINGLE_CALL_MAX_TOKENS <= TIER_MAX_TOKENS.free`. Option (a) is simpler. [VERIFIED: analyze-resume/index.ts:53-60]
**Warning signs:** Module fails to load with assertion error after editing CALL_CONFIGS.

### Pitfall 2: Duplicated Free Path in Both Merit and Legacy Branches

**What goes wrong:** `analyze-resume/index.ts` has two complete code paths -- the merit branch (lines 256-537) and the legacy branch (lines 542-1131). The Free single-call branch must be inserted in BOTH paths, creating duplication risk.
**Why it happens:** The legacy path is kept for `MERIT_SYSTEM_ENABLED=false` backward compatibility (MIG-05).
**How to avoid:** Extract the Free single-call logic into a helper function that both paths call. The helper takes `userPrompt`, `promptParams`, `ANTHROPIC_MODEL_TEXT`, `resolvedTier`, and returns the shaped result. Both paths call the helper and handle DB update + email + usage recording in their own way.
**Warning signs:** Free tier output differs between merit-on and merit-off code paths. [VERIFIED: analyze-resume/index.ts has both branches]

### Pitfall 3: Streaming Mode Omission

**What goes wrong:** The streaming SSE path (merit + legacy) has its own implementation separate from the non-streaming path. If the Free single-call branch is only added to the non-streaming path, streaming Free requests still use 3 parallel calls.
**Why it happens:** The streaming path is a separate async IIFE inside the request handler.
**How to avoid:** The Free single-call branch must be inserted in ALL four code paths: (1) merit streaming, (2) merit non-streaming, (3) legacy streaming, (4) legacy non-streaming. Using a shared helper function makes this manageable.
**Warning signs:** Streaming requests for Free users take longer than non-streaming (because they still use 3 calls). [VERIFIED: 4 distinct code paths in analyze-resume/index.ts]

### Pitfall 4: Fallback Path Using Wrong Prompt for Free

**What goes wrong:** When all parallel calls fail, the existing fallback uses `buildFallbackPrompt()`. For Free tier, D-07 requires using `buildFreeConsolidatedPrompt()` instead. Missing this change means the fallback generates Pro-shaped output for Free users.
**Why it happens:** The fallback path is deep inside error handling code, easy to miss.
**How to avoid:** The Free single-call branch eliminates the fallback scenario for Free entirely -- if the single call fails, there is no "all parallel calls failed" condition. The Free path either succeeds, retries (D-06 quality floor), or throws. The fallback path only triggers for Pro/Elite.
**Warning signs:** Free fallback output contains `rewriteSuggestions`, `industryGuess`, etc. [VERIFIED: analyze-resume/index.ts fallback at lines 340-378]

### Pitfall 5: Quality Floor Check on Shaped vs Raw Output

**What goes wrong:** If `passesQualityFloor()` runs after `applyTierShape()`, the C2-C11 entries have been stripped to `{ id, score }` format. The quality floor check still works (it reads `.score`), but the retry would use the shaped output shape as a reference, which is fine. However, running it before shaping is safer per CONTEXT.md specifics.
**Why it happens:** Ordering ambiguity between reconcileScore, quality floor, and applyTierShape.
**How to avoid:** Run quality floor check on the raw parsed result BEFORE any transformations. Sequence: parse -> quality floor check -> reconcileScore -> applyTierShape.
**Warning signs:** Quality floor retry loop produces different results depending on check ordering.

### Pitfall 6: OCR Import Breaking Deno Bundle

**What goes wrong:** `ocr-pdf/index.ts` currently reads `ANTHROPIC_MODEL_TEXT` from `Deno.env.get()`. Importing `FREE_MODEL` from `_shared/tier-config.ts` adds a new import dependency. If `tier-config.ts` has transitive imports that conflict with ocr-pdf's import map, the function fails to deploy.
**Why it happens:** Deno edge functions have isolated import maps.
**How to avoid:** `tier-config.ts` is a pure module with zero edge-layer dependencies (confirmed in its header comment). It only exports constants and pure functions. Safe to import from any edge function. [VERIFIED: tier-config.ts has no imports except type imports]
**Warning signs:** `supabase functions deploy ocr-pdf` fails with import resolution error.

 * Builds a consolidated single-call system prompt for Free tier.
 * Combines criteria scoring (all 11) + summary fields into one JSON response.

${FREE_TIER_SUFFIX}

SINGLE RESPONSE FORMAT: Return ALL of the following in ONE JSON object. No markdown, no text outside JSON.

### Example 2: Quality Floor Validator

```typescript
// Source: CONTEXT.md D-06
/**
 * Checks for degenerate single-call output (model laziness/hallucination).
 * Returns true if output passes quality floor, false if retry needed.
 */
function passesQualityFloor(result: Record<string, unknown>): boolean {
  const criteria = (result.criterionFeedback || result.criteria || []) as Array<{ score?: number }>;
  if (criteria.length === 0) return false;

  const scores = criteria.map(c => Number(c.score) || 0);

  // All zero = model didn't score anything
  if (scores.every(s => s === 0)) return false;

  // All identical = model is lazy (e.g., all 50s)
  if (scores.every(s => s === scores[0])) return false;

  return true;
}
```

## Cost Analysis

### Current Free Tier Cost (3 Parallel Calls)

Using Claude Haiku 4.5 pricing: $1/M input tokens, $5/M output tokens [CITED: https://platform.claude.com/docs/en/about-claude/pricing]

- **Input tokens per call:** Resume prompt (~2,000 tokens shared prefix) + resume text (~1,000-2,500 tokens) + per-call suffix (~200-400 tokens) = ~3,200-4,900 tokens per call
- **3 calls total input:** ~9,600-14,700 input tokens (resume sent 3x)
- **Output tokens (total across 3 calls):** ~3,500 tokens (Free tier output)
- **Cost estimate (3 calls):** Input ($0.010-0.015) + Output ($0.018) = ~$0.028-0.033

### Optimized Free Tier Cost (1 Call)

- **Input tokens (1 call):** ~3,200-4,900 tokens (resume sent once, combined prompt slightly longer)
- **Output tokens:** ~3,500 tokens (same output)
- **Cost estimate (1 call):** Input ($0.003-0.005) + Output ($0.018) = ~$0.021-0.023

**Savings:** ~25-30% reduction in per-analysis cost for Free tier. Input cost drops by ~67% (resume sent once instead of 3x). Total savings are smaller because output tokens dominate the cost for Haiku 4.5. [ASSUMED -- exact savings depend on actual prompt token counts]

### OCR Cost Change

- **Before:** 4000 maxTokens per page
- **After:** 3000 maxTokens per page
- **Impact:** Negligible -- OCR output is typically 500-1500 tokens per page. The cap reduction only matters if a page is exceptionally dense. No cost change for typical resumes. [ASSUMED -- based on CONTEXT.md D-10 rationale]
