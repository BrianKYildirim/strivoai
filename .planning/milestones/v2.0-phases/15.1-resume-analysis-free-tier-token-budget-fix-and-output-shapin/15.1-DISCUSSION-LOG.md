## Session 1 (Original)

### Free-Tier Call Budget

#### Token Cap

| Option      | Description                                                                                        | Selected |
| ----------- | -------------------------------------------------------------------------------------------------- | -------- |
| 4000 tokens | \~15% headroom above spec's \~3,500 actual output. Tight budget, keeps cost under \$0.051 ceiling. |          |
| 4500 tokens | \~30% headroom. More breathing room for edge cases. Slightly higher cost.                          |          |
| 3500 tokens | Match spec exactly. Zero margin — risk of truncated JSON.                                          |          |

**User's choice:** 4000 tokens
**Notes:** None

#### TIER\_MAX\_TOKENS.free Update

| Option                      | Description                                                                                      | Selected |
| --------------------------- | ------------------------------------------------------------------------------------------------ | -------- |
| Update to match             | Change TIER\_MAX\_TOKENS.free from 6000 to 4000. Single source of truth.                         |          |
| Keep 6000, override locally | Leave tier-config.ts at 6000. analyze-resume uses 4000 locally. Other features keep own budgets. |          |

**User's choice:** Keep 6000, override locally
**Notes:** Other features (LinkedIn, Career Compass) have independent Free budgets that depend on TIER\_MAX\_TOKENS.free.

### Quality vs. Cost

#### Priority

| Option                   | Description                                                                         | Selected |

## Session 2 (Update — Free Tier Display Requirements)

### Placeholder Content

| Option              | Description                                                                                                                      | Selected |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Frontend hardcoded  | Frontend renders static placeholder text. Backend sends nothing extra — cheapest option, no token cost.                          |          |
| Backend placeholder | Backend generates realistic-looking but generic placeholder text and sends it marked as locked. Costs tokens.                    |          |
| Frontend realistic  | Frontend has a hardcoded pool of realistic-sounding placeholder text that rotates. No backend cost but looks like real analysis. |          |

**User's choice:** Frontend hardcoded
**Notes:** No backend token cost for placeholders.

#### Follow-up: Placeholder Visual Style

| Option              | Description                                                                                                                                   | Selected |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Blurred teaser text | Show realistic-looking placeholder text behind a blur effect with a lock icon. User can see there's content but can't read it — creates FOMO. |          |
| Redacted cards      | Show the improvement card structure but replace the body with a 'Locked — Upgrade to Pro' message. Clean and explicit.                        |          |

**User's choice:** Blurred teaser text
**Notes:** FOMO-driven approach — users see there's content but can't read it.

### Lock Visuals

| Option               | Description                                                                                                                                         | Selected |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Per-item blur + lock | Each locked item gets its own blur overlay and small lock icon. No full-section overlay.                                                            |          |
| Split section        | Unlocked items render normally at the top. Below them, a single 'Upgrade to unlock X more' divider, then all locked items shown blurred beneath it. |          |
| Inline lock badge    | Locked items show their title/header clearly but the content area has a lock badge and blurred placeholder text.                                    |          |

**User's choice:** Split section
**Notes:** Unlocked content at top, divider, then locked blurred content below.

#### Follow-up: Detailed Criteria Lock Granularity

| Option                        | Description                                                                                                                                            | Selected |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- |
| Score visible, bullets locked | Show criteria name, weight badge, and score bar for all 11 criteria. Only the feedback bullet points are blurred/locked.                               |          |
| Everything locked             | Only Achievement Orientation criteria card is fully visible. The other 10 criteria are entirely behind the blur — name, score, and bullets all locked. |          |

**User's choice:** Everything locked
**Notes:** Other 10 criteria completely behind blur — name, score bar, weight badge, and bullets all locked.

### First Analysis

| Option                | Description                                                                                                                               | Selected |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Always partial        | Free users always see the locked/partial view from day one. Consistent experience, stronger upgrade pressure from the start.              |          |
| First free, then lock | Keep current behavior: first analysis shows everything, subsequent analyses show locked view. Gives users a taste of the full experience. |          |

**User's choice:** Always partial
**Notes:** Remove the isFirstAnalysis bypass entirely. Free users always see locked/partial view.

### Criteria Selection

| Option              | Description                                                                                                              | Selected |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------ | -------- |
| Yes, C6 Achievement | Switch to keeping C6 (achievement\_orientation, 20% weight) with full 3-bullet feedback. Strip all others to score-only. |          |
| Different criteria  | User wants a different criteria to be the unlocked one for free tier.                                                    |          |

**User's choice:** Yes, C6 Achievement
**Notes:** Backend applyTierShape must find C6 by id ('c6\_achievement\_orientation') instead of using index 0. Frontend sorts by weight so C6 (20%) appears first.
