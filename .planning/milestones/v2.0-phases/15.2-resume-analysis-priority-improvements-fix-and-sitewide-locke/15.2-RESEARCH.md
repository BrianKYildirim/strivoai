## Summary

This phase has two workstreams: (1) fixing the resume analysis priority improvements display so free users see a real `PriorityCard` with structured rewrite data instead of a plain-text fallback, and (2) creating a unified `BlurredLockCard` component to replace all inline blur patterns and the Phase 14 `LockedSection`/`LockedListItem` components across Results, CareerCompass, RecruitingLens, and LinkedInGrader pages.

The backend change is surgical: `applyTierShape` in `result-merger.ts` currently strips `rewriteSuggestions` entirely for free tier (it is not in `FREE_ALLOWED_FIELDS`), and the free prompt (`buildFreeConsolidatedPrompt`) explicitly instructs the model NOT to generate rewriteSuggestions. Both must be updated to allow exactly 1 rewriteSuggestion through. The frontend change in Results.tsx is then straightforward -- `improvementSuggestions` already derives from `rewriteSuggestions`, so having 1 entry flow through means the existing PriorityCard rendering path works for free users.

The BlurredLockCard component is a new children-based composable component that replaces the flat-props `LockedSection` pattern. It accepts arbitrary children (fake content), renders them blurred, and overlays a lock icon with hover-to-unlock animation. This is a fundamentally different design from `LockedSection` (which generates its own skeleton lines) -- `BlurredLockCard` shows realistic fake content behind blur for stronger FOMO effect.

**Primary recommendation:** Implement in two waves -- Wave 1: backend fix + BlurredLockCard component creation + Results.tsx migration; Wave 2: CareerCompass, RecruitingLens, LinkedInGrader migrations.

### Pattern 1: BlurredLockCard Component Design

**What:** A children-based composable component that renders arbitrary content behind a blur overlay with a lock-to-unlock hover animation.

**Key design decisions:**
- Uses `children` prop (not flat props like `LockedSection`) to allow realistic fake content
- Framer Motion `whileHover` for the lock icon animation [ASSUMED -- Claude's Discretion]
- Lock icon morphs from `Lock` to `Unlock` (lucide-react) on hover
- Text "Upgrade to unlock your full potential" appears on hover below lock icon
- Clicking lock icon or text navigates to `/pricing`

**Example:**
```typescript
// Source: D-04 from CONTEXT.md + codebase patterns
import { useState } from 'react';
import { motion, AnimatePresence } from 'framer-motion';
import { Lock, Unlock, Crown } from 'lucide-react';
import { useNavigate } from 'react-router-dom';

interface BlurredLockCardProps {
  children: React.ReactNode;
  className?: string;
  ctaHref?: string;
}

export const BlurredLockCard = ({
  children,
  className = '',
  ctaHref = '/pricing',
}: BlurredLockCardProps) => {
  const navigate = useNavigate();
  const [isHovered, setIsHovered] = useState(false);

  return (
    <div
      className={`relative ${className}`}
      onMouseEnter={() => setIsHovered(true)}
      onMouseLeave={() => setIsHovered(false)}
    >
      {/* Blurred children content */}
      <div
        className="blur-sm opacity-50 pointer-events-none select-none"
        aria-hidden="true"
      >
        {children}
      </div>

      {/* Lock overlay */}
      <div
        className="absolute inset-0 flex flex-col items-center justify-center cursor-pointer"
        onClick={() => navigate(ctaHref)}
        role="button"
        tabIndex={0}
      >
        <motion.div
          animate={{ scale: isHovered ? 1.1 : 1 }}
          transition={{ duration: 0.2 }}
        >
          <AnimatePresence mode="wait">
            {isHovered ? (
              <motion.div key="unlock" initial={{ opacity: 0 }} animate={{ opacity: 1 }} exit={{ opacity: 0 }}>
                <Unlock className="h-5 w-5 text-primary" />
              </motion.div>
            ) : (
              <motion.div key="lock" initial={{ opacity: 0 }} animate={{ opacity: 1 }} exit={{ opacity: 0 }}>
                <Lock className="h-5 w-5 text-muted-foreground/60" />
              </motion.div>
            )}
          </AnimatePresence>
        </motion.div>

        <AnimatePresence>
          {isHovered && (
            <motion.p
              initial={{ opacity: 0, y: 4 }}
              animate={{ opacity: 1, y: 0 }}
              exit={{ opacity: 0, y: 4 }}
              className="text-xs text-primary font-medium mt-2"
            >
              Upgrade to unlock your full potential
            </motion.p>
          )}
        </AnimatePresence>
      </div>
    </div>
  );
};
```

## Common Pitfalls

### Pitfall 1: rewriteSuggestions vs priorityImprovements confusion
**What goes wrong:** The Results.tsx `improvementSuggestions` array is derived from `rewriteSuggestions` (structured objects with originalText, improvedText, etc.), NOT from `priorityImprovements` (plain text strings). If `rewriteSuggestions` is empty, the code falls back to a legacy path that builds suggestions from criteria highlights. Free users currently get the fallback path because `rewriteSuggestions` is stripped entirely.
**Why it happens:** The field names are confusing -- `priorityImprovements` are plain-text action items, `rewriteSuggestions` are structured rewrite objects that power the PriorityCard UI.
**How to avoid:** The backend fix (D-01) must add `rewriteSuggestions` to `FREE_ALLOWED_FIELDS` AND update the free prompt to generate 1 rewriteSuggestion. Both changes are required -- the whitelist alone won't help if the prompt doesn't generate the field.
**Warning signs:** Free users see a plain-text box instead of PriorityCard with original/improved text comparison.

### Pitfall 2: FREE_TIER_SUFFIX explicitly forbids rewriteSuggestions
**What goes wrong:** The `FREE_TIER_SUFFIX` constant (resume-prompts.ts line 66-70) contains the text: "DO NOT include any of: rewriteSuggestions, industryGuess, suggestedTargetRoles...". If this suffix is not updated, the model won't generate rewriteSuggestions even if the schema includes them.
**Why it happens:** `buildFreeConsolidatedPrompt` appends `FREE_TIER_SUFFIX` which has an explicit deny-list. The deny-list must be edited to remove `rewriteSuggestions` from the forbidden list and add instructions to generate exactly 1.
**How to avoid:** Update BOTH the `FREE_TIER_SUFFIX` constant AND the JSON schema in `buildFreeConsolidatedPrompt`.
**Warning signs:** Backend returns no `rewriteSuggestions` field despite whitelist change.

### Pitfall 3: LinkedIn Grader free-tier data shape conflict with D-12
**What goes wrong:** D-12 says free users see `profileInsights` ("What's Working for You") fully visible. But the CURRENT backend (`stripLinkedInFreeTier` at grade-linkedin/index.ts:91) DELETES `profileInsights` entirely per LIG-02. And the current free prompt (`buildFreeSystemPrompt` in prompts.ts:26) doesn't request profileInsights.
**Why it happens:** Phase 15.2 D-12 OVERRIDES the original LIG-02 requirement for the frontend display. The backend must now generate and pass through profileInsights for free tier.
**How to avoid:** Update the free prompt to include profileInsights generation, and update `stripLinkedInFreeTier` to keep profileInsights. Also update `maxTokens` to 3000 per D-13 (down from current 4000).
**Warning signs:** Free LinkedIn users see empty "What's Working for You" section.

### Pitfall 4: LinkedIn Grader sectionBreakdown Profile Completeness identification
**What goes wrong:** D-12 says only "Profile Completeness" section is unlocked with 3 bullet points. The section must be identified by key/name, not by array index, because LLM output ordering can vary.
**Why it happens:** sectionBreakdown is an array of objects with `name` field. Array index is fragile.
**How to avoid:** Identify by `name` matching (e.g., `section.name === 'Profile Completeness'` or case-insensitive match). The CONTEXT.md specifics section recommends "stable key/ID rather than array index."
**Warning signs:** Wrong section unlocked, or no section unlocked.

### Pitfall 5: LockedSection/LockedListItem usage count in CareerCompass
**What goes wrong:** CareerCompass.tsx has 7 distinct `LockedSection`/`LockedListItem` usages across multiple sections (career fields, surprise fits, skill gaps, salary progression, compensation intelligence, etc.). Missing even one creates visual inconsistency.
**Why it happens:** Large file (~2000 lines), usages scattered throughout conditional rendering blocks.
**How to avoid:** Grep for all `LockedSection` and `LockedListItem` imports and usages. Replace systematically. There are 7 in CareerCompass and 12+ in RecruitingLens.
**Warning signs:** Partial migration -- some sections use old pattern, others use BlurredLockCard.

### Pitfall 6: BlurredLockCard accessibility
**What goes wrong:** Blurred content with `pointer-events-none` makes the overlay interactive but the children non-interactive. If the overlay doesn't have proper ARIA attributes, screen readers can't convey the locked state.
**Why it happens:** Blur is a visual-only cue.
**How to avoid:** Add `role="button"`, `tabIndex={0}`, `aria-label="Locked content - upgrade to unlock"`, and keyboard event handler (Enter/Space) on the clickable overlay.
**Warning signs:** Accessibility audit failures.
