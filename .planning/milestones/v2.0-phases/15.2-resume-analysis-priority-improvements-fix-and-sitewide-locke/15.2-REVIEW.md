# Phase 15.2: Code Review Report

## Summary

This phase introduces the `BlurredLockCard` component as a replacement for `LockedListItem` and `LockedSection`, adds free-tier partial results to LinkedIn Grader, implements tier-gated content in Recruiting Lens, updates the result-merger with rewriteSuggestions caps, and adds comprehensive tests.

The component and backend code is generally well-structured. The main concerns are: (1) a test that asserts the wrong criterion is kept in the free-tier feedback shaping, which will fail when actually run; (2) an unhandled promise rejection on clipboard write in LinkedInGrader; (3) a missing React Hook dependency in RecruitingLens; (4) the legacy LinkedIn grader code path not applying the free-tier strip function.

## Warnings

### WR-01: Test asserts wrong criterion kept in free-tier feedback shaping

**File:** `supabase/functions/_shared/result-merger.test.ts:464-485`
**Issue:** The test is titled "strips feedback from C2-C11, keeps C1 full" and asserts that `criteria[0]` (C1, `c1_visual_clarity`) retains its feedback. However, the implementation at `result-merger.ts:335` keeps feedback only for `c6_achievement_orientation` (index 5), not C1. This test should fail when run because C1's feedback will be stripped. The test assertions at lines 472-473 check C1 (index 0) but should check C6 (index 5).
**Fix:**
```typescript
Deno.test("applyTierShape free: strips feedback from C1-C5,C7-C11, keeps C6 full", () => {
  const merged = makeFullMergedOutput();
  applyTierShape(merged, 'free');

  const criteria = merged.criterionFeedback as Record<string, unknown>[];
  assertEquals(criteria.length, 11);

  // C1 (index 0): stripped to {id, label, weight, score} only
  assertEquals((criteria[0] as Record<string, unknown>).feedback, undefined);

  // C6 (index 5): keeps full feedback
  assertEquals((criteria[5] as Record<string, unknown>).feedback !== undefined, true);
  assertEquals(((criteria[5] as Record<string, unknown>).feedback as Record<string, unknown>).observation, 'Strong metrics');

  // C2 (index 1): stripped
  assertEquals((criteria[1] as Record<string, unknown>).feedback, undefined);

  // C11 (index 10): also stripped
  assertEquals((criteria[10] as Record<string, unknown>).feedback, undefined);
});
```

### WR-02: Unhandled promise rejection on clipboard write

**File:** `src/pages/LinkedInGrader.tsx:1001-1002`
**Issue:** `navigator.clipboard.writeText()` returns a Promise that is not awaited or caught. If the clipboard API is unavailable (e.g., non-HTTPS context, browser permissions denied, or the page is not focused), this will throw an unhandled promise rejection. The Recruiting Lens page at line 657-663 correctly wraps clipboard access in a try/catch, but LinkedInGrader does not.
**Fix:**
```typescript
onClick={async () => {
  try {
    await navigator.clipboard.writeText(fix.suggestedFix);
    toast.success('Copied to clipboard!');
  } catch {
    toast.error('Copy failed');
  }
}}
```

### WR-03: Missing React Hook dependency in RecruitingLens useEffect

**File:** `src/pages/RecruitingLens.tsx:219-281`
**Issue:** The `useEffect` at line 219 uses `navigate` and `getEffectiveTier` inside the callback but has an empty dependency array `[]`. While `navigate` from `useNavigate` is generally stable, `getEffectiveTier` comes from `useAdminTierTest()` context and could change if the admin tier override is toggled. This would cause the init function to use a stale `getEffectiveTier` reference.
**Fix:**
```typescript
}, [navigate, getEffectiveTier]);
```

### WR-04: Legacy code path in grade-linkedin does not apply free-tier strip

**File:** `supabase/functions/grade-linkedin/index.ts:466-590`
**Issue:** The legacy code path (lines 337-590, reached when `MERIT_SYSTEM_ENABLED` is false) does not call `stripLinkedInFreeTier()` before returning the result. The merit-enabled path correctly applies the strip at line 180-182 via `runTieredAiCall`, but the legacy path at line 587 returns the full parsed result without any free-tier stripping. If a free-tier user hits this legacy path, they would receive the full Pro-tier LinkedIn grade data including all feedback arrays and all topFixes entries.
**Fix:** Add the free-tier strip before the response on the legacy path, after the validation block around line 532:
```typescript
// Apply free-tier strip (defense-in-depth)
// Note: legacy path doesn't have tier from userContext, but free users
// should be using the merit path. This is a safety net.
```
Alternatively, confirm that free users are always routed through the merit-enabled path. If `MERIT_SYSTEM_ENABLED` is always `true` in production, this is a low-risk gap in dead code.

### IN-02: `console.log` in production code path

**File:** `src/pages/RecruitingLens.tsx:259`
**Issue:** `console.log('[RecruitingLens] Using analysis_results fallback path')` is present in the fallback data loading path. Per project conventions, bracket-prefixed logs are standard, but this is purely informational and may add noise in production.
**Fix:** Consider using a conditional debug log or removing if the fallback path is confirmed stable.

### IN-03: Unused `Unlock` import in BlurredLockCard

**File:** `src/components/BlurredLockCard.tsx:3`
**Issue:** The `Unlock` icon from `lucide-react` is imported and used, so this is valid. However, the `useState` import for the `isHovered` state exists purely for hover animation. The component uses `onMouseEnter`/`onMouseLeave` which do not fire on touch devices. Touch/mobile users will never see the unlock animation or the "Upgrade to unlock" text.
**Fix:** No code change needed, but consider always showing the lock icon and upgrade text on touch devices (e.g., via a media query or touch detection).

### IN-04: `any` type assertion in LinkedInGrader

**File:** `src/pages/LinkedInGrader.tsx:287,304`
**Issue:** `invokeWithTimeout<any>` on line 287 and `(data as any)` on line 304 bypass type safety. The response data should be typed to the `LinkedInResult` interface.
**Fix:**
```typescript
const { data, error } = await invokeWithTimeout<LinkedInResult>(
  'grade-linkedin',
  { body: { ... } },
  120000,
);
```
And check for error fields without `as any`:
```typescript
if (data && typeof data === 'object' && 'error' in data) {
  throw new Error((data as { error: string }).error);
}
```
