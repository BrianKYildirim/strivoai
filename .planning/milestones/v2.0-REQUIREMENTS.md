## v2.0 Requirements

### Merit Currency (MER)

* [x] **MER-01**: Create `user_merits` table with columns `id`, `user_id`, `subscription_balance`, `shop_balance`, `lifetime_granted`, `subscription_reset_date`, `free_linkedin_scan_used`, `created_at`, `updated_at` (spec §2.5, §6)
* [x] **MER-02**: Create `merit_transactions` table with `id`, `user_id`, `amount`, `balance_type` (enum: subscription | shop | grant | refund), `source`, `feature`, `metadata` (jsonb), `created_at` (spec §2.5)
* [x] **MER-03**: Create `merit_shop_purchases` table with `id`, `user_id`, `pack_size`, `price_cents`, `stripe_payment_intent_id` (unique), `stripe_receipt_url`, `status` enum, `created_at` (spec §2.5)
* [x] **MER-04**: RLS policies — users can READ only their own `user_merits` and `merit_transactions`; all writes go through SECURITY DEFINER RPCs (spec §9.2)
* [x] **MER-05**: RPC `check_and_deduct_merits(user_id, feature, tier)` — atomic, row-locked, returns `{ success, remaining_balance, deducted_from }` or `{ error, upgrade_required }`; deducts subscription first, overflow from shop (spec §2.4, §2.6, §9.5)
* [x] **MER-06**: RPC `refund_merits(user_id, transaction_id)` — idempotent reversal of a deduction; same `transaction_id` cannot be refunded twice (spec §2.6, §9.2)
* [x] **MER-07**: RPC `get_merit_balance(user_id)` returns `{ subscription_balance, shop_balance, total, next_reset_date }` (spec §2.6)
* [x] **MER-08**: RPC `credit_shop_merits(user_id, pack_size, stripe_payment_id)` — credits `shop_balance`, inserts purchase row, idempotent on `stripe_payment_id` (spec §2.6, §5.2, §9.5)
* [x] **MER-09**: RPC `reset_subscription_merits(user_id, tier)` — sets `subscription_balance` to 75 (Pro) / 150 (Elite); resets `free_linkedin_scan_used = false` (spec §2.6, §6)
* [x] **MER-10**: Free user account creation grants 5 lifetime Merits (one-time, never refilled, never expires) into `subscription_balance` with `lifetime_granted = 5` (spec §2.2)
* [x] **MER-11**: Merit deduction MUST happen BEFORE the AI call; on AI failure the deduction is auto-refunded and logged (spec §2.4, §9.3) — sync path Phase 13; async path Phase 26
* [x] **MER-12**: Merit balance reconciliation query — `subscription_balance + shop_balance` must equal sum of `merit_transactions` for user; runnable on demand (spec §9.5)
* [x] **MER-13**: Merit balance must NEVER go negative; enforced at RPC level via `CHECK` constraint and row-level locking (spec §9.5)
* [x] **MER-14**: Subscription Merits reset monthly and do NOT roll over; shop Merits never expire and always roll over — distinction tracked via the two columns (spec §2.2, §5.3)
