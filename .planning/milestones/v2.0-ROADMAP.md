## Overview

v2.0 replaces Strivo's legacy global credit pool with a Merit-currency monetization layer end-to-end: a dual-balance ledger (subscription resets monthly, shop never expires), atomic SECURITY DEFINER RPCs as the only legitimate write path, Stripe Live as primary checkout (4 subscription Price IDs + 4 one-time Top-Up Pack Price IDs + signed idempotent webhook), tier-gated AI prompt variants where Free output is generated as partial-by-prompt (never as hidden-by-UI), the new Interview Prep runtime (Pro flashcards + Elite quiz with Duolingo-style streak), and a full UX surface (balance badge, low-balance warnings, out-of-merits modal, `/pricing` page with monthly/annual toggle, Merit Shop top-ups). Cutover landed 2026-04-29: `MERIT_SYSTEM_ENABLED=true` in production, all 7 Stripe HANDLED_EVENTS subscribed against `/functions/v1/stripe-webhook-handler`, real `pack_3` purchase confirmed crediting merits via `payment-intent-credited` log line.

## Phase Goals (extracted from ROADMAP.md v2.0 section, preserved verbatim summary)

### Phase 10 — merit-ledger-foundation
Establish the Merit currency database layer with atomic-safe schema and seed every existing user as Free + 5 lifetime Merits. Tables: `user_merits`, `merit_transactions`, `merit_shop_purchases`. RLS rejects user-side writes; `CHECK` prevents negative balance; legacy `usage_tracking` retained read-only.

### Phase 11 — merit-rpcs-and-reconciliation
Ship atomic SECURITY DEFINER RPCs as the only legitimate write path: `check_and_deduct_merits` (subscription-first / shop-fallback), `refund_merits` (idempotent), `credit_shop_merits` (idempotent on `stripe_payment_intent_id`), `reset_subscription_merits`, `get_merit_balance`, plus pgTAP coverage for TEST-01..03.

### Phase 12 — stripe-products-and-webhook
Stripe replaces Paddle as primary checkout (subs + shop). 4 subscription Price IDs + 4 shop pack Price IDs + signed idempotent webhook handler covering 7 HANDLED_EVENTS. `agk02110` coupon preserved. Yearly plans bill upfront, Merits granted monthly on anniversary (NOT lump-sum). Pro→Elite upgrade credits the difference, never double-grants.

### Phase 13 — merit-enforcement-and-feature-flag
Universal `check-and-deduct-merits` gateway wired into every AI feature with pre-call deduction + auto-refund on failure. `MERIT_SYSTEM_ENABLED` flag for cutover. Per-user 60/hour AI rate limit. Admin metrics + alert thresholds (negative balance / 5% AI failure / 2% shop failure).

### Phase 14 — tier-prompts-and-locked-section-primitive
Per-feature `_free.md` / `_pro.md` / `_elite.md` prompt variants loaded by tier before API call (Free is generated-as-partial, never hidden-as-partial). `<LockedSection>` + `<LockedListItem>` + `<EliteFeatureGate>` UI primitives. ## Milestone Summary

**Key Decisions** (from PROJECT.md and per-phase SUMMARYs):

- Merit currency with dual-balance ledger (subscription + shop) — predictable unit cost; enables shop top-ups without breaking subscription cadence.
- Free tier = lifetime grant only (Free 10/month per Phase 24 retune; original spec was 5 lifetime, retuned mid-milestone) — forces upgrade decision; no weekly refill.
- Subscription Merits reset monthly, do NOT roll over — recurring engagement, prevents unbounded liability.
- Shop / top-up Merits never expire and roll over across tier changes — user trust; purchased value is permanent.
- Tier-gated prompts (`_free.md` / `_pro.md` / `_elite.md`) per feature — AI never generates locked content (hard cost discipline).
- Pre-call Merit deduction with atomic RPC + auto-refund on failure — prevents resource consumption without payment; preserves UX on AI errors.
- Stripe replaces Paddle as primary checkout — webhook-backed integrity, sub + pack parity, idempotent crediting.
- Yearly plans billed upfront, Merits granted monthly on anniversary — cash-flow win without giving away 12 months of Merits day one.
- `MERIT_SYSTEM_ENABLED` feature flag for cutover — safe rollback path during launch (caveat: Phase 23 is merit-only by intent; Phase 27 SC-3 documents the 503 brick).
- Free tier resume analysis uses single Anthropic call (`maxTokens=4000`) instead of 3 parallel — cuts input token cost ~67%; FREE_SINGLE_CALL_MAX_TOKENS is 20% of Elite (GATE-09) — Phase 15.1.
- Haiku-only model routing — all features/tiers resolve to `claude-haiku-4-5-20251001` (Quick task `260419-hku`).
- `<BlurredLockCard>` replaces `<LockedSection>`/`<LockedListItem>` sitewide — Phase 15.2.
- Phase 24 supersedes the "token configs are locked" note in original phase brief — central `pricing-config.ts` SC-12 snapshot is the canonical source.
