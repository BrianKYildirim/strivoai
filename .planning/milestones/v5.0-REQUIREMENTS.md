# Requirements: Strivo AI — v5.0 Platform Trust, Reliability & Intelligence

**Defined:** 2026-06-25
**Core Value:** Every core feature works reliably end-to-end with predictable, financially-safe unit economics — failed analyses never charge Merits, results are never fabricated, and the platform is secure by audit.

Derived from the v5.0 milestone spec (six workstreams) + `.planning/research/` (STACK / FEATURES / ARCHITECTURE / PITFALLS / SUMMARY). New security IDs continue from the historical v1.0 SEC-01..10 (so they start at SEC-11). All other categories are new (start at 01). Every requirement must hold without weakening v4.0's security, regression, environment, or deployment protections, and every workstream folds its new tests into the `verify:baseline` gate.

## v5.0 Requirements

Requirements for this milestone. Each maps to exactly one roadmap phase (see Traceability).

### Security Audit & Remediation (W1)

- [x] **SEC-11**: Every deferred SEC-01..10 obligation is located, evaluated, and closed with a recorded disposition (remediated / re-scoped / accepted-with-justification).
- [x] **SEC-12**: A current full-surface frontend + Edge Function security audit is completed across all 17 required domains (auth/session, authz/access control, RLS enforcement, user+resource ownership, cross-origin handling, input validation/output encoding, file-upload/document-processing safety, secret+env handling, sensitive-data exposure, logging/error-message safety, rate limiting/abuse, Merit+billing-operation integrity, webhook auth+replay, AI prompt/provider-response exposure, DB function permissions, dependency/supply-chain, prod-vs-staging isolation).
- [x] **SEC-13**: Every confirmed critical/high finding is remediated, with evidence demonstrating the vulnerable behavior is no longer possible; no unresolved critical/high issue remains at milestone completion.
- [x] **SEC-14**: A regression test exists for each remediated high-risk finding and is added into `verify:baseline`; remediations preserve legitimate user behavior and do not weaken existing v4.0 DB/auth/deployment protections.
- [x] **SEC-15**: A final security record is produced (scope reviewed, confirmed findings, severity+potential impact, remediation applied, verification performed, accepted residual risk + justification).

### Cross-Origin & Production Access Reliability (W2)

- [x] **CORS-01**: Cross-origin handling is centralized so every active Edge Function resolves allowed origins from one env-driven allowlist supporting all approved production/preview/development/local origins per the documented environment policy (no per-endpoint copies).
- [x] **CORS-02**: Requests from approved origins — including BOTH the apex `https://strivoai.net` and the approved `https://www.strivoai.net` — succeed on Resume Analysis, Career Compass, LinkedIn Grader, Recruiting Lens, and every other active Edge Function, with preflight (OPTIONS) handled correctly.
- [x] **CORS-03**: Unapproved origins are rejected safely, and no unrestricted wildcard is used for authenticated or credential-bearing requests.
- [x] **CORS-04**: Cross-origin headers are consistent on both successful and failed responses (incl. 401/4xx/5xx and preflight), so structured Edge Function errors remain readable by the frontend instead of being swallowed by the browser.
- [x] **CORS-05**: Every active Edge Function is audited for the single-origin/missing-header pattern and all occurrences are fixed (not only the four observed in production logs).
- [x] **CORS-06**: Automated tests cover approved origins, rejected origins, preflight behavior, and the success/failure header matrix; they enter `verify:baseline` and guard against frontend↔backend origin-config drift; production deployment configuration (apex + www) is verified.

### Shared AI Analysis Reliability Lifecycle (W3)

- [x] **LIFE-01**: A shared, persistent analysis lifecycle implementing the defined status model (`created → validating_inputs → reserving_merits → extracting_data → generating → validating_output → saving → completed | retryable_failed | failed | refunded`) covers Onboarding Resume, Resume Analysis, LinkedIn Grader, Career Compass, and Recruiting Lens; meaningful transitions are persisted so a run survives refresh, navigation, slow provider responses, frontend timeouts, and temporary failures.
- [x] **LIFE-02**: Each analysis record retains the required operational metadata: user, feature, tier, request/idempotency context, merit transaction, input version, prompt version, schema version, calculation version (where applicable), model, retry count, failure code, failure stage, and creation/start/completion/update times.
- [x] **LIFE-03**: Every analysis follows the required ordered lifecycle — authenticate+validate user → validate required inputs → create or recover the analysis record → atomically reserve Merits → extract+prepare source data → generate → parse+strictly validate the complete response → save the valid result → finalize the Merit charge → mark completed.
- [x] **LIFE-04**: On failure the lifecycle records the exact stage + internal error code, preserves the previous valid result, releases/refunds reserved Merits exactly once, never charges for missing input / invalid output / unsaved result, never allows a double charge or double refund, returns a safe specific user-facing message, and enforces Merit integrity via trusted backend+database operations (not frontend state).
- [x] **LIFE-05**: Idempotency & concurrency hold: duplicate clicks for the same active request reuse the in-progress analysis; a deliberate new run creates a new analysis + History record; two browser tabs cannot create duplicate charges for one request; successful runs charge exactly once; failed runs refund/release exactly once; retrying a transient failure cannot duplicate a saved result or Merit transaction; a replacement upload causes the newest input to be used; reusing unchanged input remains a valid intentional run where product rules allow. (Includes wiring the existing 4-arg idempotent `check_and_deduct_merits` end-to-end through `withMerits`.)
- [x] **LIFE-06**: The retry policy auto-retries ONLY genuinely transient failures (provider timeout, provider rate limit, temporary network interruption, transient database unavailability) using bounded exponential backoff with preserved retry history, and never auto-retries permanent failures (missing files, invalid input, auth/authorization failure, unsupported document, schema incompatibility, definitively malformed source data).
- [x] **LIFE-07**: All model-generated results are strictly validated before acceptance (safe formatting-wrapper removal, JSON parsing, required-field validation, type+range validation, missing-section detection, empty/generic-response detection, truncation detection, feature-specific semantic checks, safe logging of validation failures); an invalid response is never silently replaced with a fixed score, empty object, generic recommendation, or fabricated personalized result.
- [x] **LIFE-08**: Generic server errors are replaced with structured internal error categories (INPUT_MISSING, FILE_NOT_FOUND, FILE_EXTRACTION_FAILED, PROFILE_PARSE_FAILED, MERIT_RESERVATION_FAILED, MODEL_TIMEOUT, MODEL_RATE_LIMITED, MODEL_INVALID_RESPONSE, MODEL_OUTPUT_TRUNCATED, SCHEMA_VALIDATION_FAILED, DATABASE_SAVE_FAILED, MERIT_SETTLEMENT_FAILED, UNKNOWN_ANALYSIS_ERROR); users receive clear safe messages and technical details/provider payloads/stack traces/prompts/credentials/secrets are never exposed.
- [x] **LIFE-09**: Every affected feature's frontend disables duplicate submission while a request is active, shows meaningful progress stages, polls/subscribes to the persisted state, recovers an active analysis after refresh, displays a delayed result on completion, stops at a terminal state, offers Retry only for retryable failures, preserves the previous successful result when a new run fails, communicates whether Merits were reserved/charged/released/refunded, resets stale state before a deliberate new run, and maintains accurate History — no analysis remains permanently stuck.

### Feature-Specific Repairs (W4)

- [x] **FEAT-01**: Onboarding Resume Analysis resolves the no-result / "Analysis Taking Longer Than Expected" condition — upload completion + file accessibility confirmed before analysis; extraction completes before generation; correct Free-tier model/prompt/schema/endpoint/limits; slow analyses persisted+recovered (not abandoned by frontend timing); refresh/navigation does not lose the run; delayed successful results stored+displayed; genuine failures reach a specific terminal state; Merits released/refunded safely on failure; duplicate interaction cannot create duplicate analyses or charges.
- [x] **FEAT-02**: Resume Analysis preserves its current Free output quality + presentation exactly (no redesign/simplification/quality reduction), gaining only the shared reliability/persistence/validation/idempotency/Merit-safety/history/error-handling improvements; the confirmed production cross-origin failure is corrected.
- [x] **FEAT-03**: LinkedIn Grader produces profile-specific scores with the final total computed mathematically from deterministic, evidence-backed section scores (the model never invents the headline number); all fixed-score sources are eliminated (hardcoded/placeholder values, default DB values, parsing fallbacks, prompt-example anchoring, cached results, incorrect aggregation, excessive normalization, frontend placeholders, broken section weights); the rubric evaluates the relevant profile areas (Headline, About, Experience, Education, Skills, Projects, Certifications, Achievements, Completeness, Career positioning, Recruiter discoverability) and each section carries earned score, maximum score, supporting evidence, strengths, weaknesses, and actionable improvements; weak/average/strong/exceptional profiles differ meaningfully with no artificial score range.
- [x] **FEAT-04**: LinkedIn Grader works reliably across repeated analyses — a new analysis identifier on intentional start, using the newest LinkedIn document, older results preserved in History, no stale state or cached input, saving successfully before settling Merits, working for first, second, and repeated consecutive runs.
- [x] **FEAT-05**: Career Compass repairs the complete pipeline — correct retrieval of the latest resume+LinkedIn inputs; product-correct resume-only / LinkedIn-only / combined behavior; input validation before Merit reservation; compatible extraction+analysis schemas; correct Free-tier prompt/model/endpoint/limits; complete+valid generated output with malformed/truncated detection; successful persistence of Career DNA, career fields, gaps, surprise fits, and roadmaps; alignment between backend result structures, DB storage, and frontend rendering; safe handling of large results; Merit settlement only after successful result storage; a fake personalized result is never substituted after a real failure; the production cross-origin failure is corrected.
- [x] **FEAT-06**: Recruiting Lens corrects the production cross-origin failure and verifies the full analysis path under the shared standards (authentication, latest-input retrieval, Merit reservation+settlement, idempotency, output validation, persistence, refresh recovery, History, structured errors, repeated runs) while preserving the approved product experience and output quality.

### Dashboard Intelligence (W5)

- [x] **DASH-01**: "Live Career Profile" is replaced with **Recruiter First Impression** (subtitle "How your current resume and LinkedIn position you to employers") showing Current Positioning, What Stands Out, What May Create Doubt, a single Likely Recruiter Response from the fixed set (Strong shortlist potential / Interested-but-needs-clearer-positioning / Competitive-but-undifferentiated / Relevant-experience-unclear-direction / High-potential-insufficient-proof), and one primary action "Strengthen My Positioning"; Free shows ≤2 standout points + 1 concern + a basic recruiter response; Elite shows ≤3 standout points + ≤2 concerns + deeper cross-analysis using resume, LinkedIn, Career Compass, Saved Jobs, and Recruiting Lens where available; no generic feedback, unsupported claims, or long paragraphs.
- [x] **DASH-02**: The dashboard's Progress and Achievements section is deleted without removing or degrading Merits, History, readiness information, or any other protected experience.
- [x] **DASH-03**: Activity Stream is removed and replaced with **Profile Alignment** (subtitle "See whether your resume and LinkedIn tell one consistent professional story") showing an overall resume↔LinkedIn alignment score + concise interpretation, the categories Experience Consistency / Skills Alignment / Positioning Alignment / Evidence Alignment, ≤3 synchronization actions, and one primary action "Align My Profiles"; insights are specific + evidence-backed (e.g. a skill prominent on one profile only, conflicting positioning, a quantified achievement present in one profile only); Free shows overall score + basic experience/positioning alignment + ≤2 actions; Elite shows all four categories + deeper evidence comparison + ≤3 actions + role/job-specific alignment where data exists; no alignment score is generated when a profile is missing (resume-only → "Add your LinkedIn profile to compare your professional positioning."; LinkedIn-only → "Upload your resume to compare your experience, skills, and evidence.").
- [x] **DASH-04**: Dashboard data integrity — every intelligence section derives from existing stored analysis data with no new AI calls on dashboard load, no hardcoded/fabricated scores, and no placeholder insights presented as personalized findings; data freshness + missing-data behavior is predictable; derived values are deterministic where appropriate; incomplete/outdated/unavailable analysis data is handled gracefully; one section lacking data does not block the full dashboard.
- [x] **DASH-05**: The final dashboard section order is exactly: 1) Your Career OS, 2) Readiness cards, 3) Your Next 3 Moves, 4) Readiness Matrix, 5) Recruiter First Impression, 6) Career Launch Path, 7) Every Version Ranked, 8) Saved Jobs, 9) Profile Alignment; all protected areas (Career OS, readiness cards, Next 3 Moves, Readiness Matrix, Every Version Ranked, Saved Jobs, Career Launch Path, navbar, sidebar, Merits, History page, existing light/dark styling + responsive behavior) remain functionally + visually unchanged, and the separate History page is preserved.

## Out of Scope

Explicitly excluded — documented to prevent scope creep and to encode the milestone's non-negotiable guardrails.

| Exclusion | Reason |
|-----------|--------|
| Redesigning or restyling protected dashboard areas (Career OS, readiness cards, Next 3 Moves, Readiness Matrix, Every Version Ranked, Saved Jobs, Career Launch Path, navbar, sidebar, Merits, History, existing light/dark + responsive behavior) | Spec protects these — only strictly-necessary integration adjustments allowed |
| Reducing the existing quality/presentation of Resume Analysis or Recruiting Lens output | Guardrail — reliability/persistence improvements only, no quality regression |
| New AI product features beyond the six workstreams | Trust/reliability milestone, not feature expansion |
| New AI calls triggered by dashboard loading | Guardrail — dashboard intelligence must derive from stored data |
| Fake/hardcoded scores, fabricated personalized results, or fallback values that conceal failures | Non-negotiable guardrail — root-cause fixes only |
| Double charges, double refunds, or charging for failed/unsaved analyses | Non-negotiable Merit-accounting guardrail |
| Destructive Paddle removal before the verified expiration gate | Hard safety gate — could revoke/extend access incorrectly or lose required billing history |
| Weakening any v4.0 security, regression, environment, or deployment protection | Build on, do not erode, the v4.0 baseline |
| New infrastructure (external queue, Redis, new SDKs, realtime service, ORM, CORS/validation libraries) | Research confirms every capability is buildable on existing Supabase/Deno/Postgres + zod + the `_shared/` layer |
| Migrating zod 3 → zod 4 | API-breaking with no v5.0 upside; zod 3.25.76 is already vendored on both surfaces |
