# Requirements: Strivo AI — v4.0 Codebase Hardening

**Defined:** 2026-06-09
**Core Value:** Preserve all current production behavior exactly while making the system measurably cleaner, leaner, faster, and provably correct through comprehensive testing.

> **Governing constraint (applies to every requirement below):** Zero functional change. No active user-facing or internal behavior may be removed, altered, degraded, or unintentionally changed. Where a requirement involves removal (code, deps, env, DB), the change happens **only when confirmed unused/safe**; anything with an external gate (e.g. an in-flight subscription) is documented as gated rather than forced.

## v4.0 Requirements

Requirements for the Codebase Hardening milestone. Each maps to exactly one roadmap phase.

### Dead Code & Refactor Cleanup (CLEAN)

- [x] **CLEAN-01**: A dead-code / unused-export audit is run (knip / ts-prune for the React app, equivalent reachability analysis for Deno edge functions) and findings are catalogued with safe/unsafe classification
- [x] **CLEAN-02**: Modules, files, and exports confirmed dead are removed with no change to runtime behavior
- [x] **CLEAN-03**: Obsolete implementation paths are retired (e.g. the superseded Phase 50 Ollama extraction path; the retired `interview-prep-coach` function), confirmed against current routing
- [x] **CLEAN-04**: Redundant abstractions and duplicated helpers are consolidated into single canonical implementations
- [x] **CLEAN-05**: Commented-out code, stale TODOs, and structural clutter not supporting current functionality are removed
- [x] **CLEAN-06**: `npm run lint` and `npm run type-check` pass clean with no new suppressions; the 19 pre-existing type errors noted at Phase 49 close are resolved or explicitly tracked

### Repository Hygiene & Standardization (REPO)

- [x] **REPO-01**: Committed-vs-uncommitted state is reconciled — STATE.md quick-task "not committed" entries are verified against actual git history and corrected
- [x] **REPO-02**: Stale/merged branches are identified and pruned; surviving branches are documented with purpose (incl. the Phase 27 `by/env-fixes` branch)
- [x] **REPO-03**: `.gitignore` is reviewed and tidied (no tracked files that should be ignored; no ignored files that should be tracked) without altering tracked `.planning/`
- [x] **REPO-04**: A commit-message and branch-naming convention is documented for ongoing work
- [x] **REPO-05**: No secrets, large binaries, or build artifacts are tracked in the repository

> Excludes rewriting/squashing published git history (operator decision — see Out of Scope).

### Dependency Hygiene (DEP)

- [x] **DEP-01**: A full dependency inventory is produced (frontend npm + Deno edge imports) with current/latest version, consumers, and risk classification
- [x] **DEP-02**: Unused dependencies (depcheck or equivalent) are removed and verified against a clean build + passing tests
- [x] **DEP-03**: Outdated dependencies are updated, including major-version bumps, each applied behind passing validation + tests before merge
- [x] **DEP-04**: Known-risky/vulnerable dependencies (`npm audit`) are remediated, or documented with explicit accepted-risk rationale
- [x] **DEP-05**: Lockfiles (`package-lock.json`, `deno.lock`) are consistent and produce reproducible installs after all changes

### Environment Variable Audit & Organization (ENV)

- [x] **ENV-01**: Every environment variable (`VITE_*` frontend flags + Supabase edge-function secrets) is inventoried with consumer, environment, and required/optional status
- [x] **ENV-02**: Unused, redundant, or duplicated env vars are identified and removed/consolidated (verified against the env inventory and code references)
- [x] **ENV-03**: A canonical, documented env reference (`.env.example` + docs) is produced and aligned across staging / production / backend
- [x] **ENV-04**: Staging vs production configuration separation is verified explicit and correct, with no cross-environment leakage
- [x] **ENV-05**: Fail-closed validation for critical/required secrets (e.g. `APP_URL` CORS, `ANTHROPIC_API_KEY`) is confirmed present

### Database Cleanup (DB)

- [x] **DB-01**: A full inventory of schemas, tables, functions, policies, triggers, and cron jobs is produced with usage classification
- [x] **DB-02**: Unused/obsolete DB structures are identified with evidence they are not used by current functionality, automation, integrations, analytics, or future-critical workflows
- [x] **DB-03**: Confirmed-safe DB removals are executed via reversible forward migrations behind validation
- [x] **DB-04**: Legacy `usage_tracking` retirement is evaluated and executed only if fully migrated and unreferenced; otherwise documented as gated with the blocking dependency named
- [x] **DB-05**: RLS policies are audited for correctness and least-privilege with no access-behavior regression
- [x] **DB-06**: Every DB change ships as a forward-migration script with a documented rollback path

### Performance & Maintainability Refactoring (PERF)

- [x] **PERF-01**: Inefficiency hotspots are identified (redundant work, N+1 / repeated data access, unnecessary recomputation, oversized payloads)
- [x] **PERF-02**: Behavior-preserving performance refactors are applied where opportunities are clear (data-access patterns, parallelization, cache/result reuse)
- [x] **PERF-03**: Architecture/clarity refactors improve maintainability without altering any external behavior
- [x] **PERF-04**: Business-critical flow latencies (Resume Analysis, Career Compass) are measured before/after to confirm no regression (and to substantiate any claimed improvement)

### Production-Ready Testing Model (TEST)

- [x] **TEST-01**: A documented testing strategy defines the unit / integration / contract / E2E split, ownership, and coverage targets
- [x] **TEST-02**: Frontend unit/integration tests (vitest) are expanded across core components and hooks; the flaky `OutcomeOverdueBanner` mock gap is fixed so the suite is deterministic
- [x] **TEST-03**: Edge-function tests (deno) cover shared utilities, auth, usage/merit logic, and per-feature analyze handlers including failure/error paths
- [x] **TEST-04**: Playwright browser E2E covers the critical user flows — auth/session persistence, resume analysis end-to-end, and Stripe checkout (test mode)
- [x] **TEST-05**: Tests cover edge cases, failure states, permissions/tier gating, and environment-specific behavior
- [x] **TEST-06**: A regression baseline of current behavior is captured before cleanup and re-run after, proving cleanup/refactor work changed no behavior
- [x] **TEST-07**: Adversarial / prompt-injection coverage (promptfoo) is retained and extended across active AI features
- [x] **TEST-08**: Tests run via a documented command set, are repeatable locally/CI, and are wired into deploy gating where feasible

### Cross-Cutting Guardrails (NFR)

- [x] **NFR-01**: Each milestone change is verified to preserve existing production behavior (zero functional change) before merge
- [x] **NFR-02**: Risky changes (dependency major bumps, DB removals) are individually validated with tests + a rollback path before merge
- [x] **NFR-03**: Documentation is updated wherever structure, configuration, or testing changed (README, CLAUDE.md, env reference, testing strategy)

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| New product features / new AI capabilities | This is a maintenance & hardening milestone — no feature expansion |
| Rewriting / squashing / rebasing published git history | Operator decision: repo hygiene only; history rewrite is destructive on a deployed repo |
| AI output schema or scoring redesign | Only removal of dead/unused code — no behavior change to live AI outputs |
| Platform / infrastructure migration | Stack stays Supabase + Vercel + Vite/React; no new infrastructure |
| Redesign of working UI flows | Zero functional change — UI behavior is preserved, only internal cleanup |
| Re-enabling Interview Prep on production | Deferred to a dedicated future Interview Prep milestone (IP-01) |
| Paddle removal forced before legacy subs expire | Gated on the last in-flight Paddle subscription expiring; remove only if confirmed unused (see DB/CLEAN gated handling) |
