## Current Focus

🚧 **v4.0 — Codebase Hardening.** A brownfield maintenance milestone under a single hard constraint: **zero functional change**. Every phase preserves current production behavior exactly; the testing/regression model is the safety net that *proves* it. Sequencing is safety-net-first (establish the regression baseline before any destructive cleanup) and audit-before-action (know what is dead before removing it). Begin with `/gsd-plan-phase 1`.

## Overview (v4.0)

The journey: stand up a regression safety net first (Phase 1), reconcile the repository to a clean known state (Phase 2), then run a non-destructive cross-domain audit to catalog everything dead/unused/inefficient (Phase 3). Only then do the destructive and risky phases execute — each behind the baseline and the relevant test coverage: remove dead code (Phase 4) after deepening test coverage for the surfaces about to change (Phase 5), bump/prune dependencies including major versions (Phase 6), organize and document environment configuration (Phase 7), execute confirmed-safe database removals via reversible migrations (Phase 8), and finally apply behavior-preserving performance and maintainability refactors with measured before/after latencies (Phase 9). The regression baseline from Phase 1 (TEST-06) is the spine: every later phase re-runs it as its verification gate, and risky changes additionally require a per-change rollback path (NFR-02).
