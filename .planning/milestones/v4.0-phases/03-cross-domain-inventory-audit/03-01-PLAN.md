<threat_model>
**ASVS L1 — low surface (no code execution paths, no secrets handled), one real concern.**
- Threat T-3-01 (config-correctness, not security-severity but it corrupts the whole audit): a mis-scoped `knip.json` that includes `supabase/functions/**` would make knip flag every Deno file "unreferenced" (knip can't resolve `https://`/`npm:`/`jsr:` imports — RESEARCH Anti-Pattern), producing hundreds of false-positive dead-code findings that could leak into a `safe` classification → a broken prod path in Phase 4. Mitigation: `project` is scoped to `src/**` only; `supabase/functions/**` is NEVER in `entry`/`project`; tests + e2e + html + vite/vitest/playwright configs ARE listed as `entry` (tests are entries, not dead code — RESEARCH Pitfall 1).
- Threat T-3-02: the `audit:*` scripts accidentally add a devDependency (violates D-01 zero-new-deps posture). Mitigation: scripts use `npx --yes knip` and `node`/`npm` built-ins only; verify `git diff package.json` touches ONLY the `scripts` block, never `dependencies`/`devDependencies`.
- This plan writes only config + a node runner + two `.planning/audit/` Markdown files. No secret values, no prod connections, no product-code edits (zero functional change: `git diff --stat <baseline>..HEAD -- src supabase/functions` must stay empty — this plan touches neither).
- No HIGH-severity threat. The KEEP-LIST.md created here is itself a security/correctness control: it is the gate that prevents gated-but-live surfaces (Interview Prep, Paddle remnants, webhook/cron edge fns) from being mis-classed `safe`.
</threat_model>
