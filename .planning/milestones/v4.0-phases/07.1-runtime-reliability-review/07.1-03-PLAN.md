ASVS L1; block on HIGH. Dominant threat = sensitive-data exposure via logs / error bodies (RUN-05) AND accidental functional change on money paths.

- **T-07.1-01 (HIGH) — Internal detail leaked into a client error body.** compare-jobs:332 currently returns `{ error: error instanceof Error ? error.message : 'Unknown error' }` — a live leak of internal exception text to the client. **Mitigation:** replace it with the safe generic body `{ error: 'internal_error', errorCode: ERR.INTERNAL, message: 'An unexpected error occurred. - **T-07.1-02 (HIGH) — Sensitive data added to logs while "making logs useful."** Adding `{ raw: ai.text }` / `{ messages }` / a token to a `log.*` call would leak resume text/prompts/secrets. **Mitigation:** RUN-05 allow-list discipline (Plan 02 spec) — the only new log field is `errorCode` (+ `retryable`/`stage`/`reason`-code where applicable); NO deny-listed field is passed to any `log.*` call. Acceptance asserts no new `log.*` call carries a deny-listed key.
- **T-07.1-03 (HIGH) — Accidental merit/refund control-flow change (economic behavior).** Touching `withMerits`'s refund firing conditions would change which errors refund. **Mitigation:** D-03 — merit-gateway gets a safe-log-field-only edit (errorCode/reason-CODE on an EXISTING `log.*` call), NO control-flow / `isRefundableAnthropicError` / `MeritRefundable` change, behind an explicit operator checkpoint; the Phase-5 `merit-*.test.ts` corpus is the offline proof it did not move behavior.
- **T-07.1-04 (MEDIUM) — Breaking a frozen parsed wire contract (D-05).** Adding errorCode to a 401/402/429 body would break `AiCreditsContext`. **Mitigation:** errorCode goes in LOGS always; in a BODY only on the compare-jobs replaced-leaky-500 / a brand-new guard. The 401/402/429 bodies stay byte-identical (acceptance asserts).

No HIGH threat left unmitigated: the body leak is removed (T-01), logs are allow-list-only (T-02), money-path control flow is frozen with proof (T-03), parsed contracts stay byte-identical (T-04). Each is gated by an `autonomous: false` operator checkpoint before merge.
