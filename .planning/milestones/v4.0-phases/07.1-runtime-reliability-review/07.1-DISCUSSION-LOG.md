## Code vs catalog appetite

### Overall appetite

| Option | Description | Selected |
|--------|-------------|----------|
| Surgical fixes, op-gated | Land code ONLY where a critical active flow fails silently/open; everything else catalogued + routed; each batch passes an `autonomous:false` operator checkpoint. Mirrors ENV-05 D-08. | ✓ |
| Audit + doc only (code-free) | Zero src/functions diff; taxonomy + logging specced on paper; fixes written as generated-but-unapplied diffs. | |
| Broader standardization | Adopt taxonomy + log fields across ALL in-scope flows now. | |

### Fix bar

| Option | Description | Selected |
|--------|-------------|----------|
| Observed OR code-evident | Fix where EITHER a prod/preview log/advisory shows a failure OR code plainly swallows/fail-opens on an active flow (e.g. SB-05-04). Logs prioritize. | ✓ |
| Observed-in-logs only | Touch code only for log/advisory-corroborated gaps; code-evident-but-unobserved → deferred. | |
| Any code-evident gap | Fix any plainly silent/fail-open path regardless of logs. | |

### Money paths (merit charge/refund + Stripe webhook)

| Option | Description | Selected |
|--------|-------------|----------|
| Extra-conservative | Triage + catalogue; ANY control-flow/error-response change held for explicit operator-reviewed checkpoint, never auto-applied; safe logging-field additions allowed. | ✓ |
| Same surgical bar | Operator-gated checkpoint already covers them; no special carve-out. | |
| Logging-only here | No control-flow/error-response changes at all; only structured-logging additions. | |

**User's choice:** Surgical fixes (op-gated) · bar = observed OR code-evident · money paths extra-conservative.
**Notes:** Protects the v3.0/Phase-5-verified refund + idempotency invariants from accidental drift; matches the milestone's proven ENV-05 surgical-add pattern.

## Error taxonomy form

### Form of the taxonomy

| Option | Description | Selected |
|--------|-------------|----------|
| Doc spec + inline apply | Define taxonomy (errorCode strings + safe JSON shape) as a documented spec; apply INLINE per-function at fix sites; NO new `_shared` module. | ✓ |
| Shared `_shared/errors.ts` | Introduce an errorCode enum + safeErrorResponse() builder used at fix sites. | |
| Doc-spec only, no code | Taxonomy lives only as the canonical pattern in the register; no code adopts it. | |

### Where `errorCode` lives

| Option | Description | Selected |
|--------|-------------|----------|
| Logs + new paths only | errorCode ALWAYS to structured logs; in JSON body ONLY on brand-new fail-closed guard responses; existing wire contracts frozen byte-identical. | ✓ |
| Logs only; wire frozen | errorCode in logs only; all response bodies stay minimal/unchanged. | |
| Additive errorCode everywhere | Add errorCode to all error responses additively (still a wire change on parsed contracts). | |

**User's choice:** Doc spec applied inline; errorCode in logs always + on new guard responses only; existing contracts (402 `{error,resetDate,tier}`, 401 `{error:'Unauthorized'}`) frozen.
**Notes:** No error helper exists in `_shared` today — Phase 4 removed the dead `handler.ts`+`errors.ts` pair; the shared-helper version is a deferred Phase-9 candidate.
