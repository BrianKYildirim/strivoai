<threat_model>
ASVS L1; block on HIGH. Dominant threat surface for this phase = sensitive-data exposure via committed catalog lines (RUN-05 analog applied to the register).

- **T-01 (HIGH) — Secret/PII/policy-detail leakage into the committed register.** The register is a tracked file. Recording an advisory's raw payload, a JWT/key/price-ID value, a resume/LinkedIn snippet, payment data, or a verbatim log line containing user text would commit sensitive data. **Mitigation:** Phase-2 REPO-05 names-not-values discipline — record finding NAMES + affected flow + decision ONLY; capture the names-not-values banner verbatim from `ENV-INVENTORY.md`; run the secret-pattern grep guard over `RUNTIME-RELIABILITY.md` and confirm ZERO before commit (acceptance criterion below).
- **T-02 (MEDIUM) — Accidental prod write via MCP.** A write verb (`apply_migration`) on `supabase-prod-readonly` would violate the read-only policy (CLAUDE.md MCP rule 4, D-08). **Mitigation:** only `get_advisors` / `get_logs` / `list_tables` are called on prod; the access-model header records that no write tool was exercised; RUN-01 explicitly confirms read-only.

No HIGH threat left unmitigated: T-01 is closed by the names-not-values banner + pre-commit secret-grep=0 gate; T-02 by read-only-tools-only + the recorded access model.
</threat_model>
