**Current swallow site (lines 710-719) — what's there now:**

**Analog to copy (interview-prep-evaluate/index.ts:343-352) — the correct shape with `return err`:**
```typescript

    // Thrown Responses from requireAuth (401)
    if (err instanceof Response) return err;

    log.error('unhandled-error', { error: (err as Error).message, stack: (err as Error).stack });
    return new Response(
      JSON.stringify({ error: 'internal_error', message: 'An unexpected error occurred. Please try again.' }),
      { status: 500, headers: { ...corsHeaders({ type: 'user' }), 'Content-Type': 'application/json' } },
```

**Apply (surgical, behavior-preserving on success path):** add `if (err instanceof Response) return err;` as the FIRST statement of the catch (use `return err`, NOT `throw` — this function uses the `handler()` direct-invocation seam at :720-726, where `return err` propagates the Response correctly). The existing 500 body MAY gain `errorCode` (it is an internal_error body the frontend does not parse for fields — confirm at plan time it is not a frozen contract; treat additive-to-500-only as the conservative default).

**jsonResponse helper (already in-file, :68-73) — reuse, do not rebuild:**

**Logger already wired:** the file already has a `log = createLogger('interview-prep-analyze', reqId)` instance — the `errorCode` field plumbs into the existing `log.error('unhandled-error', {...})`. No new logger import needed.

## Shared Patterns

### Pattern A — The auth-Response re-throw guard (the canonical RUN-04 fix)
**Source (canonical correct shape):** `supabase/functions/analyze-skills-gap/index.ts:286-293`
**Source (the `return err` variant for `handler()`-seam functions):** `supabase/functions/interview-prep-evaluate/index.ts:343-352`
**Root cause:** `requireUserAuth` THROWS `Response(401)` (`supabase/functions/_shared/auth.ts:90`, `:99`, `:111` via `unauthorizedResponse()`), so a generic top-level catch that lacks the re-throw converts the 401 into a 500.
**Apply to:** interview-prep-analyze (`return err`), recruiting-lens (`throw err`), compare-jobs (`throw err`).
**Idiom-selection rule:** use `throw err` when the catch is inside `serve(async (req) => ...)` (skills-gap / recruiting-lens / compare-jobs); use `return err` when the catch is inside a named `handler()` invoked directly by the test seam (interview-prep-analyze / interview-prep-evaluate). Already proven in 17 functions — replicate, do not abstract (D-04).

### Pattern B — Inline errorCode taxonomy (D-04 / D-05; NO `_shared/errors.ts`)
**Source:** the inline `const ERR = {...}` above (RESEARCH Pattern 2). Existing generic-500 bodies already use `{ error: 'internal_error', message: ... }` (recruiting-lens:765, interview-prep-analyze:716) — adding `errorCode` to a NEW/replaced fail-closed body is additive; adding it to an EXISTING parsed 401/402/429 body is FORBIDDEN.
**Apply to:** all three RUN-04 fix sites (in logs always; in body only for compare-jobs' replaced safe-500 and any brand-new guard).

### Pattern C — Safe structured-log allow-list (RUN-05; no scrubber)
**Source (reason-code, never the secret):** `supabase/functions/_shared/auth.ts:89` `log.warn('auth-failure', { reason: 'missing-bearer', type: 'user' })`; `supabase/functions/_shared/merit-gateway.ts:227` `log.info('merit-transaction', { user_id, feature, transaction_id, deducted_from, remaining_balance })`.
**Logger substrate:** `supabase/functions/_shared/logger.ts:16` `createLogger(fn, reqId?)` (`warn`/`error` → `console.error`, else `console.log`; every entry carries `level/ts/msg/fn` + spread `data`).
**Allow-list (emit):** `feature`, `stage`, `userId`/`user_id` (when available), `tier`, `provider`/`model`, merit `amount`/`transaction_id`/`deducted_from`/`remaining_balance`, `retryable`, `errorCode`, `durationMs`, `reason` (a reason-CODE).
**Deny (never emit):** resume/LinkedIn text, prompts/`messages`, `ANTHROPIC_API_KEY`/any secret, payment data (card/intent/customer PII), raw provider payloads (`raw`/`data` from `invokeAnthropicText`).
**Apply to:** all three fix sites (compare-jobs needs the `console.error`→`createLogger` lift) + merit-gateway (field-add only, D-03).

### Pattern D — Frozen wire contracts (D-05 — DO NOT MUTATE these bodies)
The frontend parses these byte-for-byte; `errorCode` is FORBIDDEN in their bodies.
- **401** — `supabase/functions/_shared/auth.ts:48-53`: `{ error: 'Unauthorized' }`, status 401.
- **402 / usage-limit** — `supabase/functions/_shared/usage-checker.ts:124-138`: `{ error: 'usage_limit_reached', message, resetDate, tier }`, status 402 (parsed by `src/contexts/AiCreditsContext.tsx`).
- **429 / rate-limit** — `supabase/functions/_shared/rate-limiter.ts:162-178`: `{ error: 'rate_limit_exceeded', message, retryAfter }`, status 429, `Retry-After` header.
**Apply to:** every fix site — the swallow fix only alters the AUTH-FAILURE branch (now reaches the frozen 401); the success path and these three contracts stay byte-identical.

### Pattern E — Fail-closed config guard (RUN-03 missing-config; already present, add errorCode to the LOG only)
**Source:** `supabase/functions/_shared/anthropic.ts:646-650`: `if (!resolvedApiKey) return { ok: false, status: 500, error: 'ANTHROPIC_API_KEY not configured' };`
