<objective>
Make the existing vitest + deno suites deterministic so the regression baseline (TEST-06) can be tagged green. Two root causes block a trustworthy baseline today:

1. **TEST-02 flakiness** — `OutcomeOverdueBanner.tsx` runs an unguarded async query inside `useEffect`. When any test that transitively mounts the banner supplies an incomplete Supabase mock (missing `.lt`), the chain throws *inside the async IIFE* → an unhandled promise rejection that crashes whichever vitest worker runs concurrently. The casualty set changes run-to-run.
2. **TEST-06 RED baseline** — `_shared/tier-config.test.ts` has 3 live failures (verified at plan time): `getTimeout('pro','core')` returns 155000 not 125000; `getTimeout('pro','elite-preview')` throws; `getTimeout('pro','quiz')` does NOT throw. Root cause is real and is a STALE TEST: `getTimeout` now calls `normalizeActiveTier` which collapses `pro`→`elite` (a deployed merit-milestone behavior), so the test's pre-collapse Pro-specific assertions are wrong. The source reflects live behavior.

Purpose: A blocking gate (D-06) is only trustworthy once the suite is deterministic (D-07). This is the hard prerequisite for tagging `v4.0-baseline`.
Output: Source-level async-effect guard, a reusable mock factory, a rejection-surfacing test-setup hook, and reconciled tier-config assertions — all zero product behavior change.
</objective>
