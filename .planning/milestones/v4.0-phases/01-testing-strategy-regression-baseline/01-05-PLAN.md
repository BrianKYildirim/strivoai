<threat_model>
**Surface:** A GitHub Actions workflow that runs the test gate with real TEST-project + Stripe-test secrets. Supply-chain (third-party actions) and over-privileged tokens are the realistic threats.

**Threats considered (ASVS L1):**
- **Secrets hardcoded in the workflow (T-05-01, HIGH if violated).** All secret values MUST be `${{ secrets.* }}` references — never literals. Mitigation: acceptance criteria assert no `pk_test_`/`sk_`/`service_role`/URL/password literals in the YAML; the E2E `env:` block reads `SUPABASE_TEST_*`, `STRIPE_TEST_PUBLISHABLE_KEY`, `E2E_TEST_PASSWORD` from GitHub secrets, and the `VITE_*` build vars are mapped from those same secrets (never literals). Mitigated.
- **Preview build targeting PRODUCTION Supabase (T-05-05, HIGH if violated — RESEARCH Pitfall 5).** Playwright's `webServer` runs `npm run build && npm run preview`, and Vite bakes `VITE_*` at BUILD time. If `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`/`VITE_STRIPE_PUBLISHABLE_KEY` are absent from the `test:e2e` step env, the preview build falls back to whatever `VITE_*` is in the repo/default env — which targets PRODUCTION Supabase, running E2E (incl. user-seeding and checkout) against prod. Mitigation: the `test:e2e` step `env:` block MUST map these three `VITE_*` from the TEST-project secrets; acceptance criteria source-assert their presence. Mitigated.
- **Over-privileged workflow token (T-05-02, MEDIUM → HIGH if unaddressed).** Default `GITHUB_TOKEN` is broad. Mitigation: add an explicit least-privilege `permissions:` block (`contents: read`; only `pull-requests: write` if a status comment is added — otherwise omit). This is a required mitigation, not optional.
- **Supply-chain via unpinned actions (T-05-03, MEDIUM).** Floating action tags can be hijacked. Mitigation: pin every third-party action to a major version at minimum (`actions/checkout@v4`, `actions/setup-node@v4`, `denoland/setup-deno@v2`, `actions/upload-artifact@v4`) consistent with the existing `vercel-preview.yml`; do not use `@master`/floating refs.
- **AI stub reachable in prod via CI (T-05-04, MEDIUM).** The workflow sets `AI_TEST_MODE` only via the TEST-project deploy (Plan 03), and `VITE_*` build env points at the TEST project only — the gate never touches production deploy. Mitigation: the workflow contains no production deploy step and no `AI_TEST_MODE` for prod.

**Residual HIGH:** T-05-01, T-05-02, and T-05-05 are mitigated by acceptance criteria (env-sourced secrets + VITE_* TEST-project mapping + least-privilege permissions). The branch-protection enablement is an operator action behind a checkpoint. `autonomous: false`.
</threat_model>
