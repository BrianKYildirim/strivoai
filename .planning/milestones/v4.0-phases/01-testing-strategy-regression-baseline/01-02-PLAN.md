<threat_model>
**Surface:** Test-infra scaffolding — Playwright config, deno task list, npm scripts, `.gitignore`. Playwright config reads `VITE_*`/`SUPABASE_TEST_*`/`STRIPE_TEST_*` from the environment at runtime.

**Threats considered (ASVS L1):**
- **Secret leakage via committed config (T-02-01, HIGH if violated).** `playwright.config.ts` and `vite.config.ts` MUST read `process.env.*` for all secret/project values (`SUPABASE_TEST_URL`, `SUPABASE_TEST_ANON_KEY`, `SUPABASE_TEST_SERVICE_ROLE_KEY`, `STRIPE_TEST_PUBLISHABLE_KEY`, `E2E_TEST_PASSWORD`) — NEVER hardcode them. Mitigation: acceptance criteria assert no literal key/URL/password values appear in the committed config; secrets come from env only. Mitigated → not unmitigated HIGH.
- **Session/auth artifact leakage (T-02-02, MEDIUM).** Playwright `storageState` output (`.auth/user.json`) and `test-results/`, `playwright-report/` can contain real session tokens. Mitigation: add `.auth/`, `test-results/`, `playwright-report/`, `e2e/.cache/` to `.gitignore` so they are never committed. Per CLAUDE.md never `git add -f` and never commit `.gitignore`-ignored content; the tracked `.planning/` stays intact.
- **AI stub reachable in prod (T-02-03, MEDIUM).** `AI_TEST_MODE` is a Supabase function secret set ONLY on the TEST project (Plan 03 wiring); nothing in THIS plan ships `AI_TEST_MODE` to production. No production config is touched here.

**Residual HIGH:** none once secrets are env-sourced (acceptance criteria enforce). `autonomous: true`.
</threat_model>
