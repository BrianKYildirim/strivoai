<threat_model>
ASVS L1; block on HIGH. This is the highest-risk plan in the phase (RLS + grants).
- **Material threat (HIGH if mishandled):** an `auth_rls_initplan` rewrite or a `multiple_permissive_policies` merge
  that silently changes row visibility (broadens or narrows access). Mitigation: the `(select auth.uid())` wrap is the
  Supabase-recommended zero-observable rewrite (identical `USING`/`WITH CHECK` truth value, only the eval plan changes);
  consolidation is taken ONLY where `merged.qual` is provably `(orig1.qual) OR (orig2.qual)` for the same roles+cmd;
  each migration's `DO $$` block asserts the expected end-state and each consolidation is gated by a preview SELECT-as-role
  no-regression probe (owner sees own rows; non-owner sees 0) — the Phase-8 20260608000008 proof. BLOCK on any advisor
  count not dropping by the expected delta or any preview/prod pg_policies divergence.
- **Threat (HIGH if mishandled):** an EXECUTE/grant regression or a redundant CREATE that leaves the advisor lit + trips
  the DO-block (Phase-8 caught exactly this). Mitigation: prefer DROP-of-the-superseded-policy over a redundant CREATE;
  re-pull the live advisor list so already-cleared objects (linkedin_grades) aren't double-counted.
- **Prod-write threat (operator-gated):** Claude must NEVER write prod. Mitigation: every prod-apply task is
  `autonomous: false`; Claude applies to PREVIEW only, the operator applies prod; Claude re-verifies prod READ-ONLY via
  `supabase-prod-readonly`. SELECT-as-role runs on PREVIEW only (prod lacks SET ROLE) — prod proven by end-state parity.
- Block on any HIGH (visibility change / grant regression / unverified prod divergence). DEFER, do not force, anything
  whose OR-equivalence isn't provable.
</threat_model>
