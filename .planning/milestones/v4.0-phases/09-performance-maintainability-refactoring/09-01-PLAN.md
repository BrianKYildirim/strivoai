<objective>
Eliminate the H4 cross-boundary DOUBLE-PARSE in the `analyze-resume` parallel-merge path. Today every
HTTP-successful call is parsed twice: `executeParallelCalls` runs the full `parseAndValidateCall` at
`index.ts:406` purely to decide retry and DISCARDS the parsed `data` (keeps only `validation.ok`), returns RAW
text; then `mergeAndValidateResults` calls `parseAndValidateCall` AGAIN on the identical buffer
(`result-merger.ts:463/:487/:498`). Plumb the already-parsed validated `data` through (research Option A) and add a
`mergeValidated(parsed, tier)` merger entry that reuses the existing post-parse merge tail unchanged.

Purpose: PERF-02 behavior-preserving data-access/recompute reduction on the business-critical Resume Analysis flow.
The merge feeds Resume Analysis output, so the merged-schema contract MUST stay byte-identical — `parseAndValidateCall`'s
internal pipeline is the behavior boundary and stays intact; the ONLY change is not calling it twice on the same buffer.
Output: A deduped parse path in analyze-resume + a `mergeValidated` merger entry; `recruiting-lens-merger.ts`
untouched (it single-parses). Zero functional change proven by `npm run test:edge` + `verify:baseline`.
</objective>

<threat_model>
ASVS L1; block on HIGH. Threat surface is narrow (behavior-preserving server-side refactor of a deterministic
parse/merge utility — no auth, no RLS, no external input shape change).
- **Material threat (MEDIUM->guarded):** the dedup silently changes the merged-schema contract (a field added/dropped/
  reordered in `grading_data`, a changed `_mergeSource`, or a skipped normalize/strip/validate step), breaking the SSE
  `complete` payload the frontend parses. Mitigation: keep `parseAndValidateCall` byte-identical (only avoid the SECOND
  call on the same buffer); reuse the existing merge tail unchanged; prove with `npm run test:edge` (merger units) +
  the deterministic measurement in 09-04.
- **Threat (LOW):** retry semantics drift — a call that previously retried no longer does (or a retried call that should
  be rejected is kept). Mitigation: the retry decision STILL runs `parseAndValidateCall` once per call; only the parsed
  `data` is now carried forward instead of discarded. Assert retried-iff-invalid and kept-iff-revalidated unchanged.
- No new abstraction beyond reusing the merger's existing tail (D-04 single-helper bound). No HIGH findings expected;
  if `verify:baseline` deno leg goes red or `_mergeSource !== 'parallel-3'` warnings fire, treat as a blocking regression.
</threat_model>
