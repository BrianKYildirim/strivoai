<threat_model>
ASVS L1; block on HIGH. Threat surface is narrow (frontend read consolidation; RLS already enforces owner-scoping
server-side — the accessor cannot widen row visibility, every query keeps `.eq('user_id', userId)`).
- **Material threat (MEDIUM->guarded):** the accessor silently changes which COLUMNS or which TERMINAL a page receives
  (e.g. `.select('grading_data')` becomes `.select('*')`, or an array site becomes `.single()`), changing payload bytes
  or a downstream `data[0].X` read / throwing on 0 rows. Mitigation: parameterize `columns` + `terminal` + `orderBy`;
  the accessor returns EXACTLY each site's column set + terminal; change ONE call site at a time and re-run
  `verify:baseline` + the relevant Playwright flow after each (Pitfall 2).
- **Threat (LOW):** folding a LIST query or a divergent-shape site (analyzed_at, analysis_results, linkedin_grades,
  .not/.neq filters) into the "latest-row" accessor would change behavior. Mitigation: those are HARD OUT of scope here;
  git diff must show no edit to RecruitingLens.tsx, LinkedInGrader.tsx, PriorLinkedInSelector.tsx, DashboardHome.tsx,
  AnalysisComparisonModal.tsx, or the analysis_results read in CareerCompass.tsx.
- No new auth surface; no secret handling. No HIGH findings expected. A page rendering `undefined` or a `.single()`
  throwing where `.maybeSingle()`/array was used before is a blocking regression.
</threat_model>
