<threat_model>
**Over-permissive direction (what these fixes REMEDIATE):**
- `linkedin_grades` "Anyone can view" (`USING (true)`, role `public`): exposes every user's LinkedIn grade to any
  caller — the highest-severity finding. Owner-scoping (`auth.uid() = user_id`) closes the cross-user read.
- `function_search_path_mutable` on `increment_rate_limit`: search-path-injection vector on a SECURITY-relevant
  RPC; pinning closes it.

**Inverse direction (the availability/functional-change threat — the load-bearing risk of this whole phase):**
- Pitfall 5 / D-03 — tightening linkedin_grades SELECT breaks a live reader. **Mitigation: read-map first. Static
  evidence: FE reads are owner-scoped (`LinkedInGrader.tsx:201` comment "RLS auto-scopes to auth.uid() = user_id";
  Dashboard/AnalysisHistory/PriorLinkedInSelector all query by the user's own id); app reads are service-role
  (`lifecycle-archive-writer`, `send-feature-email`) which bypass RLS. So owner-scoping is zero-observable-change
  for every live caller. Prove via SELECT-as-role: owner still reads their rows; a non-owner authenticated context
  is now correctly denied.**
- Pitfall 2 / Open Question 1 — assuming the wrong prior state. **Mitigation: D-08 — re-confirm the LIVE policy
  via a FRESH `pg_policies` read on prod before authoring. Three outcomes: (i) prod still permissive -> apply the
  RUN-06 forward; (ii) prod already owner-scoped -> NO-OP, document, ship nothing; (iii) prod shows a third state
  -> capture it, author the fix + a faithful rollback to THAT state. The `DROP POLICY IF EXISTS` is idempotent so
  a name mismatch is a no-op — but the ROLLBACK must restore whatever the live prior policy actually is.**
- Pitfall 3 — `SET search_path = ''` on `increment_rate_limit` would make the unqualified `rate_limit_counters`
  reference fail to resolve -> a 500 on EVERY rate-limit check (a live, business-critical path). **Mitigation: pin
  with `= public` (the repo convention; matches the live `public.rate_limit_counters` location), NEVER `= ''`.**
</threat_model>
