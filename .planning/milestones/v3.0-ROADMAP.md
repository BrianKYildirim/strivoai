### Phase 51: Cost-optimized document extraction

**Goal:** Implement a production-grade document extraction pipeline for Resume and LinkedIn PDF flows that first uses a real PDF parser for embedded/selectable text, then falls back to cheaper OCR providers, and only uses Claude OCR for Elite users as a final reliability fallback. The system must reduce Free-tier AI cost while preserving Elite-tier quality.
**Requirements**: TBD (to be mapped during `/gsd-plan-phase 51`; provisional buckets: DOCX-PARSE-*, DOCX-OCR-*, DOCX-TIER-*, DOCX-CACHE-*, DOCX-AUDIT-*, DOCX-TEST-*)
**Depends on:** Phase 49
**Replaces:** Phase 50 (Ollama document extraction layer for Resume and LinkedIn PDFs)
**Plans:** 1/1 plans complete

**Success Criteria** (what must be TRUE):

1. Normal text-based Resume PDFs extract through a real embedded-text PDF parser and do not call Ollama, Mistral, Textract, or Claude OCR.
2. Scanned/image-only PDFs for Free users attempt only allowed cheap OCR providers and never call Claude OCR.
3. Scanned/image-only PDFs for Elite users attempt cheap OCR providers first and call Claude OCR only after parser and cheaper providers fail quality validation.
4. Career Compass and future analyses continue using saved latest Resume/LinkedIn analysis results and accepted extracted text/profile data without forcing re-extraction when valid saved content exists.
5. Existing Resume Analysis and LinkedIn Grader flows remain functional for text-based PDFs, scanned PDFs, and cached accepted text.
6. Only accepted raw text plus concise metadata persist; metadata records provider used, fallback path, confidence/quality status when available, and failure reason when extraction fails.
7. Unit or integration tests cover parser success, Free-user Claude block, Elite Claude fallback, cheap OCR failure fallback, provider metadata, and quality-gate rejection.
8. Documentation explains extraction order, provider flags, tier policy, expected failure behavior, and the no-sensitive-content logging rule.

**Implementation Guidance**:

* Undo or disable Phase 50 behavior where it conflicts with parser-first extraction, tier-gated Claude fallback, or deterministic provider routing.
* Replace regex/raw-byte extraction methods such as text stream regex, BT/ET parsing, and ASCII scraping as the primary success path. They may remain only as last-resort debug fallback if still useful.
* Add a real PDF text parser for embedded/selectable text extraction. Prefer a Deno/Supabase-compatible library for Edge Functions; if compatibility is poor, isolate it behind a provider interface so parsing can later move to a worker.
* Maintain support for Resume and LinkedIn document types.
* Use a clear provider interface such as `DocumentTextProvider` with `extract(input, context): ExtractionResult`.
* Enforce deterministic extraction order:
  1. Real PDF embedded-text parser.
  2. Cheap OCR provider chain: Ollama first if configured, then optional Mistral/Textract providers if configured.
  3. Claude OCR only when the caller's tier/policy permits it.
  4. Controlled Free-tier failure asking for a text-based PDF, DOCX, or pasted text when cheaper extraction fails.
* Add tier-aware extraction options; callers must pass user tier/plan or an equivalent OCR policy. Free users must never trigger Claude OCR fallback. Elite users may trigger Claude OCR only after parser and cheaper OCR providers fail quality validation.
* Keep Claude Haiku 4.5 for downstream analysis. This phase changes extraction/OCR routing, not the analysis model.
* Add a quality gate before accepting text: minimum meaningful text length, word count, printable ratio, low garbage ratio, and document-likeness. Avoid overly strict resume-only keyword checks that reject valid resumes or LinkedIn PDFs.
* Add auditable cost-routing logs without writing secrets, raw document text, or sensitive user content.
* Add feature flags/env vars for OCR providers, including enabling/disabling Ollama, Mistral, Textract, and Claude OCR fallback.
* If Ollama is unavailable, times out, or returns low-quality/hallucinated text, continue to the next allowed provider instead of failing immediately.
* Add timeouts and safe error handling for every external provider.
* Do not introduce an always-on GPU assumption; provider calls must be optional/configurable.
* Do not re-run OCR when accepted extracted text already exists for the same document hash. Preserve or add content-hash caching.
* Preserve accepted-text contracts for Resume Analysis, LinkedIn Grader, Career Compass, and future analyses.
* Use explicit result reasons such as `pdf_parser_no_text`, `ollama_unavailable`, `ocr_quality_rejected`, `free_tier_claude_ocr_blocked`, and `claude_ocr_failed`.
