## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → create-stripe-portal | Authenticated user requests a portal session URL |
| browser → profiles read | User reads own billing profile incl. stripe_customer_id |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-11 | Elevation of privilege | create-stripe-portal invocation | mitigate | The invoke sends no customer id — `create-stripe-portal` resolves the customer server-side from `ctx.userId` (Plan 01 unchanged). The button merely triggers it; a user cannot open another user's portal. |
| T-33-12 | Information disclosure | stripe_customer_id in client query | mitigate | `stripe_customer_id` is read via the user-scoped `billing-profile` query (RLS + the `enabled:!!userId` gate); the value is used only as a render-condition, never sent to a third party except Stripe's own portal session minted server-side. |
| T-33-13 | Spoofing | portal url redirect | accept | `data.url` originates from Stripe's API via the trusted edge function (signed session URL); not user-controlled. |
</threat_model>
