# Phase 33 — UI Design Contract

> Visual and interaction contract for the `/pricing`, embedded checkout modal, `/dashboard` post-upgrade reconciliation, and `/settings/billing` surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **North star (D-07):** `/pricing` must look like `/dashboard`. This phase converges the V2 pricing components OFF their `.theme-v2` scope + arbitrary CSS-var system ONTO the app-wide semantic-token vocabulary. No new visual system is introduced — this contract codifies the existing one so the executor matches it exactly.

## Visual Hierarchy

**Primary visual anchor on `/pricing`:** the accent-highlighted tier card (the current plan, or the "Most Popular" `border-primary` ring) plus its primary CTA button. The eye should land on the recommended tier first, then read outward to the adjacent tiers and down to the Top-Up Pack section. Accent (coral `primary`) is the single device that establishes this focal point — it is reserved for the highlighted tier's ring, its CTA fill, the savings badge, and price emphasis, so nothing else competes for first read.

On `/settings/billing` the focal point is the primary action affordance ("Manage Subscription" portal button for Stripe customers, or the "Upgrade" link for everyone else) sitting at the top of the billing card.

## Typography

App default is `Inter` at exactly two weights: regular (400) and bold (700). Declared roles (Dashboard catalog, RESEARCH §"Dashboard semantic-token vocabulary"):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / feature bullets | 14px (`text-sm`) | 400 (`font-normal`) | 1.5 |
| Label / secondary meta (e.g. `text-muted-foreground` captions, savings badge) | 14px (`text-sm`) | 400 (`font-normal`) | 1.5 |
| Card / tier heading | 24px (`text-2xl`) | 700 (`font-bold`) | 1.2 |
| Page display heading | 30px (`text-3xl`) | 700 (`font-bold`) | 1.2 |

Two weights only: regular (400) for all body, labels, and meta text, and bold (700, `font-bold`) for card/tier headings and the page display heading — matching Dashboard's heading convention (`text-2xl`/`text-3xl font-bold`). Price numerals render in `text-2xl`/`text-3xl font-bold` using the SANS font — **not** `font-mono` (D-07).

## Color

Tokens resolve from `src/index.css` CSS variables (HSL). Dark is the default theme; values below cite the dark theme with the light-mode equivalent noted.

| Role | Value (dark / light) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `--background` `0 0% 0%` / `0 0% 100%` → `bg-background` | Page background, dominant surface |
| Secondary (30%) | `--card` `0 0% 5%` / `0 0% 98%`, `--secondary` `0 0% 10%` / `0 0% 94%`, `--muted` `0 0% 15%` / `0 0% 92%` → `bg-card`, `bg-muted/50`, `bg-muted/30` | Tier cards, pack cards, billing cards, subdued panels |
| Accent (10%) | `--primary` `357 100% 68%` / `357 100% 55%` (coral/red) → `text-primary`, `border-primary`, `bg-primary` | See reserved-for list below |
| Destructive | `--destructive` `0 84.2% 60.2%` / `0 84.2% 50%` → `text-destructive` | Cancel/downgrade affordances and error text only |
| Default text | `--foreground` / `--muted-foreground` → `text-foreground`, `text-muted-foreground` | Primary copy / secondary copy |
| Borders | `--border` `0 0% 15%` / `0 0% 88%` → `border-border` | All card and divider borders |

Accent (`primary`) reserved for: the primary upgrade CTA button fill, the current-plan / "Most Popular" highlight ring (`border-primary`), the savings badge accent, and price emphasis. NOT for body text, NOT for every interactive element, NOT for card borders (those use `border-border`). The coral primary IS the brand accent — there is no separate accent hue; `border-[--accent-red]` maps to `border-primary` (RESEARCH PRICE-06 mapping).

## Copywriting Contract

Tier names, prices, feature bullets, and CTA labels are FROZEN content owned by `TierCardV2` `TIER_COPY` and `src/config/pricing-config.ts` (`PRICING`, `MERITS_PER_MONTH`, `PACK_CATALOG`) — preserve VERBATIM (PRICE-07, D-08). The copy below governs the NEW interaction states this phase adds.

| Element | Copy |
|---------|------|
| Primary CTA (paid tier) | Existing per-tier label from `TIER_COPY` (e.g. "Upgrade to Pro", "Upgrade to Elite") — unchanged. Opens embedded checkout modal (D-01). |
| Free-tier CTA | Existing Free label from `TIER_COPY` — navigates to `/auth` (PRICE-02), not `/auth/signup`. |
| Embedded checkout modal title | `Subscribe to {tierName}` (matches `StripeCheckoutWrapper` title prop, RESEARCH Pattern 1) |
| Post-upgrade processing toast (Dashboard) | Heading: "Upgrade processing…" — Body: "We're confirming your new plan. This usually takes a few seconds." (sonner toast, D-02) |
| Post-upgrade success (after poll resolves) | "You're now on {tierName}. Your monthly merits have been refreshed." (D-03 — merits reset to new cap) |
| Reconciliation timeout (silent) | No error toast on ~10s timeout — mirror `reconcileShopCredit` silent-on-timeout behavior. Page reflects whatever the latest read shows. (Discretion note, RESEARCH Pattern 2) |
| Manage Subscription button (Billing, Stripe customer) | Label: "Manage Subscription" — opens Stripe customer portal via `create-stripe-portal` (PRICE-05) |
| Free user (no Stripe customer) on Billing | Label: "Upgrade" → links to `/pricing` (not a portal button that would 400) (D-05) |
| Paddle-legacy user (paddle id, no `stripe_customer_id`) on Billing | Notice (no button): "Your subscription is managed through our previous billing provider. Contact support to make changes." — clear note, never a click-then-fail button (D-05) |
| Billing portal `no_customer` error fallback | If `create-stripe-portal` returns `no_customer`, show the "Upgrade" link instead of a raw error toast (D-05; CLAUDE.md: errors must be operationally useful) |
| Billing page error state (null/expired session) | Replace infinite spinner with explicit error: "We couldn't load your billing details. Please sign in again." + path back to auth (PRICE-04 / TEST-08 — `userId === null` handled explicitly, never a perpetual spinner) |
| Empty state (no purchase history rows) | Existing Billing empty-state copy preserved; if absent, "No billing history yet." |
| Destructive confirmation | Plan downgrade/cancel is handled inside the Stripe-hosted customer portal, not in-app. The current in-app "Cancel Subscription" link wrongly pointing at `/pricing` is REPLACED by the "Manage Subscription" portal button (RESEARCH Pattern 3) — no in-app destructive confirmation dialog is introduced in this phase. |

Loading affordances: CTA buttons show a spinner/disabled state while `fetchClientSecret` is in flight (reuse `useStripeCheckout.isLoading`); Billing page shows `<Loader2>` only while the query is genuinely pending with a valid `userId`, never when `userId === null`.

## Interaction Contract

| Surface | Interaction | Contract |
|---------|-------------|----------|
| `/pricing` paid CTA | Click | Open embedded Stripe modal (`StripeCheckoutWrapper`), do NOT navigate to `/checkout` (D-01) |
| `/pricing` current plan | Render | Pass `isCurrent={currentTier === tier}` to `TierCardV2` → renders current-plan highlight ring (`border-primary`). Wire `useTierAccess().tier` (PRICE-08, RESEARCH Pitfall 4) |
| `/pricing` billing interval | Toggle | `BillingIntervalToggleV2` (monthly/annual) stays mounted; savings badges shown on annual (D-08) |
| `/pricing` Top-Up Packs | Render | 4 `PackCardV2` via `PackSectionV2`; pack purchase fires existing `topup:open` event — do not break (D-08, CLAUDE.md constraint) |
| `/dashboard` `?checkout=complete` | Mount | Show "Upgrade processing…" toast + run bounded reconciliation poll (1500ms interval / 10000ms ceiling) on `profiles.subscription_tier` + merit balance; stop when tier === expected (D-02/D-03) |
| `/settings/billing` | Load | Render within 5s for a valid session; never infinite spinner for null/stale session (TEST-08) |
| `/settings/billing` Manage | Click | Invoke `create-stripe-portal`; redirect to portal; return lands on `/settings/billing` (return_url fix, D-06) — shown only when `stripe_customer_id` exists (D-05) |

Light/dark parity required on every surface above (D-08). All focus/hover/disabled states inherit from the shadcn `Button`/`Card` defaults — do not hand-roll.
