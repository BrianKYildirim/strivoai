# Phase 31 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase UI surface is narrow and non-net-new.** Phase 31 ships zero new components and zero new layout. It changes only:
1. **Behavior** of an existing component — `MeritBalanceHeaderV2` decrements optimistically on analyze-click and re-syncs on settle (no markup change; the displayed `{total} / {cap}` value updates via React Query data).
2. **Copy** — a new shared toast taxonomy module (`src/lib/merit-error-messages.ts`) consumed by 5 feature pages + 2 async poll loops via the existing `sonner` `toast.error(title, { description })` pattern.

The dominant deliverable of this contract is the **Copywriting Contract** (NFR-04 toast taxonomy). Spacing / typography / color sections inherit the existing app system unchanged — they are documented for completeness and to anchor the toast rendering, not because new tokens are introduced.

## Copywriting Contract

This is the load-bearing deliverable. All strings live in **one** module `src/lib/merit-error-messages.ts` exporting `getMeritErrorMessage(errorCode | httpStatus): { title, description }` (CONTEXT D-08 / D-09). Taxonomy axis = **error class**, shared identically across all 5 features — NOT per-feature, NOT interpolated with a feature noun (D-08). Refundable errors MUST mention merit/refund status (D-10); non-refundable errors MUST NOT mention merits (D-10).

NFR-04 hard rule: **never** "Something went wrong." Every message names the cause and the next step.

### Toast taxonomy (planner drafts exact final strings; user reviews in plan-review — these are the binding contract values)

| Error class | Trigger | Title | Description |
|-------------|---------|-------|-------------|
| Server error (5xx) | Refundable AI failure | `Analysis hit a server error` | `Our service had a hiccup — no charge. Please try again.` |
| Overload (529) | Anthropic overloaded | `Analysis service is busy` | `High demand right now — no charge. Try again in a moment.` |
| Timeout (408) | Request timed out | `Analysis timed out` | `That took too long — no charge. Please try again.` |
| Network / AbortError | Connection dropped | `Connection lost` | `We couldn't reach the analysis service — no charge. Check your connection and retry.` |
| Insufficient merits (402) | Out of merits | `You're out of Merits` | `Your balance resets on {resetDate}. Buy a top-up pack to keep going.` (interpolates reset date only; falls back to `Upgrade or buy a top-up pack to keep going.` when date unavailable) |
| Rate limit (429) | Pooled `ai-analyses-all` cap hit | `Analysis rate cap reached` | `Try again in {N}s. No charge.` |
| Validation / 4xx client | Zod / sanitizer / bad input | `We couldn't process that` | `Your input couldn't be parsed — please check it and try again.` (MUST NOT mention merits or refunds) |

**Refund-status wording rule (D-10):**
- When the deduct never settled server-side (cache-hit-style bypass or server-side refund already fired) → say **"no charge."**
- When the deduct settled and `refund_merits` ran → say **"Merits refunded."**
- The planner decides per-path which phrase applies based on whether `withMerits` deducted before failing; both phrasings are valid contract copy.

| Element | Copy |
|---------|------|
| Primary CTA | (unchanged) per-feature "Analyze" buttons — Phase 31 does not relabel them |
| Empty state heading | not applicable — Phase 31 adds no empty states |
| Empty state body | not applicable |
| Error state | see toast taxonomy table above (7 error classes) |
| Destructive confirmation | not applicable — Phase 31 has no destructive user actions (refund is automatic + server-driven) |

**Interpolation allowance:** Only `{resetDate}` (insufficient-merits) and `{N}s` (rate-limit retry window) may be interpolated. The feature noun ("your resume analysis") is explicitly NOT interpolated (D-08).
