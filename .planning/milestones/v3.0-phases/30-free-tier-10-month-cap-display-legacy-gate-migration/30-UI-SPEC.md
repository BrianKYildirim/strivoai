# Phase 30 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase 30 visual surface scope:** the `MeritBalanceHeaderV2` trigger label rewrite (D-09 / D-12). All other Phase 30 work is non-visual (DB migrations, edge function filter, hook internals — public hook signatures stay stable so no call-site UI changes). This contract therefore governs:
> 1. The header trigger label format (`{total} / {cap} merits`, single span, no bonus chip).
> 2. The low/zero balance color states already wired to `useMerits.isLow` / `isZero` (now driven by `total`, not `subscription`).
> 3. The popover body which retains its current structure (Phase 24 SC-10 layout — unchanged).

## Color

The whole-app 60/30/10 token allocation is owned by the Strivo design system (Phase 24 brand-v2). Phase 30 reuses it verbatim and does not introduce new tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` | Page background, navbar surface (theme-controlled light/dark) |
| Secondary (30%) | `hsl(var(--popover))` / `hsl(var(--card))` | Popover body background; trigger hover surface (`hover:bg-white/5`) |
| Accent (10%) | `var(--accent-red)` (coral `#FF5F67` family) | `<Gem />` icon color, "Buy merits" / "Change plan" link color inside popover |
| Destructive | `hsl(var(--destructive))` + `bg-destructive/10` + `border-destructive/30` | Trigger background, text, and border when `isZero === true` |
| Warning (amber) | `text-amber-500` + `bg-amber-500/10` + `border-amber-500/30` | Trigger background, text, and border when `isLow === true` and `isZero === false` |

**Accent reserved for:**
1. The `<Gem />` merit icon inside the trigger (`text-[--accent-red]`).
2. The "Buy merits" and "Change plan" links inside the popover body (`text-[--accent-red] hover:underline`).
3. Nothing else this phase.

**State precedence (locked):** `isZero` (destructive) > `isLow` (amber) > default (no bg/border). Source: existing `triggerStateClass` ladder in `MeritBalanceHeaderV2.tsx:36-40`.

**Display-vs-warning agreement (D-11):** the displayed number is now `total = subscription + shop` over `cap`, and the warning predicates also operate on `total / cap`. The color state therefore matches the rendered ratio (no false amber when shop credit lifts the displayed value above 20%).

**Required display examples for QA (D-09 + §Specific Ideas):**
- `78 / 75 merits` — Pro user, 75 subscription + 3 shop, over-cap (informational only — not a warning state).
- `8 / 10 merits` — Free user, near cap, **default state** (`total/cap = 0.8`, above 0.2 threshold).
- `3 / 75 merits` — Pro user, subscription depleted, shop covers it (`total/cap = 0.04`, below 0.2 → **amber `isLow`** state).
- `0 / 10 merits` — Free user fully depleted (`total = 0` → **destructive `isZero`** state).
- `2 / 10 merits` — Free user low (`total/cap = 0.2` → **amber `isLow`** state per `<= 0.2` predicate).

**Bonus chip removal (D-09 / D-17):** the conditional `+ {shop} bonus` chip rendered at `MeritBalanceHeaderV2.tsx:57-61` is deleted. The trigger renders one monolithic `{N} / {N} merits` regardless of shop balance. Bonus visibility lives entirely in the popover body's `Top-up (never expire)` row.

## Interaction Contract

Phase 30 does not introduce new interactions; it preserves Phase 24 SC-10 behavior with the trigger label rewritten.

| Interaction | Behavior |
|-------------|----------|
| Click trigger | Open Radix Popover anchored to the trigger; `align="end" sideOffset={8}` (existing). |
| Click outside / Esc | Close popover (Radix default). |
| Hover trigger (no state) | Apply `hover:bg-white/5`. |
| Hover trigger (isLow) | Amber background already present; no additional hover overlay. |
| Hover trigger (isZero) | Destructive background already present; no additional hover overlay. |
| Click "Buy merits" | Navigate to `/pricing#packs` (react-router `<Link>`). |
| Click "Change plan" | Navigate to `/pricing` (react-router `<Link>`). |
| Keyboard focus | Trigger is a native `<button type="button">` — inherits browser focus ring (or `--ring` token); no override this phase. |
| Screen reader | Trigger announces `Merit balance: {total} of {cap} merits` (D-12); popover content is read in DOM order. |
| Loading | Render `<Skeleton className="h-5 w-28" />` until `useMerits` resolves. Skeleton width matches typical rendered trigger width to avoid layout shift. |

**Hook contract preservation (non-visual, listed for completeness):**
- `useMerits` public shape unchanged: `{ total, subscription, shop, cap, tier, resetDate, isLow, isZero, isLoading, canAfford }`. `isLow` and `isZero` now compute on `total` (D-11) — no signature change.
- `usePaywallGuard` public shape unchanged (D-13): `{ canAnalyze, tier, analysisCount, limit, resetDate, isLifetimeLimit, loading, modalProps, openModal, triggerPaywall, refresh }`. No call-site edits.
- `useTierAccess` public shape unchanged (D-14): `{ tier, loading, canAccessFeature, canUseCredits, usageInfo }`. AdminTierTest override preserved.

Because the hook signatures are stable, no other UI surfaces (Upload, Dashboard, Shop, PricingTable, RecruitingLens, InterviewPrep, useFeatureGate consumers) receive visual changes in Phase 30 — only the header trigger.
