Hook contract (from 29-CONTEXT.md D-09, D-10 + 29-PATTERNS.md "useIdempotencyKey.ts"):
```
export function useIdempotencyKey(): {
  key: string;
  regenerate: () => string;
};
```

Behavior contract:
- Initial render: `key` is a fresh `crypto.randomUUID()` (RFC 4122 v4 — 36 chars including hyphens).
- A subsequent re-render WITHOUT calling `regenerate()` returns the SAME `key` (retries of the same submit reuse the UUID per D-09).
- Calling `regenerate()` rolls a new UUID, updates internal state, and returns the new UUID synchronously.
- The 4th return shape used in 29-RESEARCH.md (`useRef`-based) and the `useState`-based shape in 29-PATTERNS.md are both acceptable. Planner-decision: use the `useState`-based shape from 29-PATTERNS.md because it matches `useCreatePaymentIntent.ts` (the closest in-tree analog by shape) and is easier to test with `renderHook` + `act` from React Testing Library.

Imports pattern (from `src/hooks/useCreatePaymentIntent.ts:12-15`):
- `import { useCallback, useState } from 'react';`
- Named export `export function useIdempotencyKey()`.
- No default export.

Test scaffold pattern (from `src/hooks/useCreatePaymentIntent.test.ts:1-30`):
- `import { describe, it, expect, vi, beforeEach } from 'vitest';`
- `import { renderHook, act } from '@testing-library/react';`
- `import { useIdempotencyKey } from './useIdempotencyKey';`
- `crypto.randomUUID` is built into jsdom (Node ≥19) — no mocking needed.
