# Phase 37 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui via existing `components.json` |
| Preset | `style: default`, `baseColor: slate`, `cssVariables: true`, aliases `@/components`, `@/components/ui`, `@/lib/utils` |
| Component library | Radix UI primitives through existing shadcn components |
| Icon library | `lucide-react`; use icons in buttons for actions where an icon exists |
| Font | `Inter`, system UI fallback; do not introduce new phase fonts |

Phase 37 is an operational product UI phase. Preserve the existing dashboard density, shadcn cards/forms/tabs/dialogs, Tailwind semantic tokens, `BlurredLockCard`, `PriorAnalysisSelector`, and `PriorLinkedInSelector`. Do not create marketing-style hero layouts, decorative backgrounds, or a new design system.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge/icon pairing, compact metadata separators |
| sm | 8px | Field label gaps, compact card rows, button icon gaps |
| md | 16px | Default form control gaps, card internal spacing on mobile |
| lg | 24px | Card padding on desktop, form-to-result section spacing |
| xl | 32px | Major feature blocks such as input form to saved work |
| 2xl | 48px | Result group breaks and tutorial modal body rhythm |
| 3xl | 64px | Page-level spacing only when separating full page regions |

Exceptions: icon-only controls and compact saved-tile click targets must maintain at least 44px height. Dense metadata rows may use 12px horizontal gaps only when text remains readable and does not wrap awkwardly. Keep card radius at the existing shadcn/Tailwind radius (`rounded-lg`, resolving from `--radius`) and use `rounded-boxy` only inside existing `.theme-v2` scope.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.35 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Use exactly these four phase sizes for new UI copy. Existing page-level headings may keep their current classes, but new fallback cards, saved tiles, tutorial content, selector labels, alerts, and result metadata must not add larger display type. Letter spacing must remain `0` except where existing global heading styles already apply.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` (`#000000` dark, `#ffffff` light) | Page background and unframed dashboard surfaces |
| Secondary (30%) | `hsl(var(--card))`, `hsl(var(--secondary))`, `hsl(var(--muted))` | Cards, saved tiles, form panels, tab backgrounds, locked skeleton surfaces |
| Accent (10%) | `hsl(var(--primary))` / `hsl(var(--accent))` coral | Primary CTAs, active tab indicators, selected prior focus/ring, score emphasis, copy-success/check states |
| Destructive | `hsl(var(--destructive))` | Destructive or blocking error states only |

Accent reserved for: primary run CTAs (`Analyze Resume`, `Grade LinkedIn`, `Generate Career Compass`, `Analyze Job`), selected tab/selector focus states, score or completion emphasis, tutorial primary action, and copy-success affordances. Secondary actions such as `View tutorial`, `Choose another source`, `Back to form`, and `Copy` use `outline`, `secondary`, or ghost styling unless they are the only action in an error recovery surface.

Warnings use amber utility classes already present in the app (`text-amber-*`, `border-amber-*`, `bg-amber-*/10`) for partial or stale analysis states. Success uses emerald utility classes already present in result cards. Do not hardcode new brand colors.

## Phase Interaction Contracts

### Cross-Feature Rules

| Contract | Requirement |
|----------|-------------|
| Priors | Use existing always-visible selectors when priors exist. Default to the most recent prior. Selection repopulates the current submission only and does not persist a last-used preference. |
| Deep links | `?id=` hydration owns the page state. Keep existing `skipCacheRestore` behavior so automatic cache/current-cycle restore never overwrites a deep-linked result. |
| Cache hits | Cache hits render through the same successful result surfaces as fresh analyses. Do not add a large cache badge. Do not write partial or failed results into cache. |
| Merit safety | Cache lookup happens before merit deduction through the existing `withMerits` precheck-cache contract. UI copy must not imply a merit was spent before the backend confirms it. |
| Loading | Use existing skeletons, disabled submit buttons, and progress states. Keep button labels stable during loading with a spinner icon plus concise verb phrase such as `Analyzing...`. |
| Errors | Toasts are acceptable for transient errors. Result-load failures need an in-page recovery state with an operational next step. |

### Visual Hierarchy And Focal Points

| Surface | Focal-point contract |
|---------|----------------------|
| Resume Analysis | Result score and `Priority Improvements` are primary. Prior selectors and cache metadata remain secondary and must not visually compete with the improvement cards. |
| LinkedIn Grader | Selected source filename/date is primary before submit. After grading, result cards and Ready-to-Paste improvements become primary; source replacement stays a secondary control. |
| Career Compass | Partial warning is primary when present. Active tab content is the next focal point; per-tab fallback cards sit inside content and must not dominate healthy sections. |
| Recruiting Lens | New-analysis form is primary, saved tiles are secondary. Within results, company/role context and match score lead; saved-tile metadata remains compact support content. |

### Resume Analysis

| Surface | Contract |
|---------|----------|
| Removed output | Do not render `Priority Actions` for any tier, including old persisted payloads that still contain `priorityActions` or `quickActions`. |
| Retained output | Render `Priority Improvements` for every tier. Free shows 1 visible item plus locked skeletons; Pro and Elite show full available output. |
| Defensive old data | Ignore obsolete fields silently unless needed for developer logging. Never show an orphan heading or empty section. |
| Cache behavior | Exact-input cache hits route to the normal result page with no extra user decision. |

### LinkedIn Grader

| Surface | Contract |
|---------|----------|
| Source selection | Onboarding PDF and prior LinkedIn grades are peer sources. Default to the most recent by timestamp and keep source replaceable. |
| Replace source | Show the selected PDF filename/date before submit. When replacing the persistent onboarding source, use explicit copy so users understand the saved source changes. |
| Removed output | Do not render `What's Working For You` / `profileInsights` for any tier. Old data must not crash or show an orphan section. |
| Retained output | Keep `Key Strengths` visible for all tiers. |
| Ready-to-Paste | Free shows exactly 1 visible Ready-to-Paste Improvement plus 4 presentational locked placeholders using `BlurredLockCard`; no hidden generated content. Pro shows 4-7 visible improvements with no locked placeholders below. Elite preserves highest-tier/full output. |
| Copy buttons | Keep existing card style, before/after format, and copy affordances. Copy success uses a check icon and subdued success state. |
| Cache behavior | Cache key includes `prior_grade_id`; UI should not expose the key but must keep selected source visible before submission. |

### Career Compass

| Surface | Contract |
|---------|----------|
| Partial global warning | Old or partial cached/persisted results show one top-level amber warning above tabs. The warning states the report is partial and repairable. |
| Per-tab fallback | Each missing section renders a fallback card inside that tab. No tab may be blank. |
| Recovery path | `Re-run for full report` sends users back to the Career Compass form with available inputs prefilled. It must not immediately spend merits or invoke AI. |
| Paid strictness | New Pro/Elite successful results require all six core sections: Best-Fit Roles, Surprise Fits, Fields, Roles, Readiness, Roadmap. Missing paid sections fail validation instead of being normalized as acceptable output. |
| Free parity | Free keeps real Career DNA, 3+2 Best-Fit Roles, 2+2 Surprise Fits, 3+2 Fields, 3+2 Roles, Readiness with locked gap/assessment skeletons, and fully fake locked Roadmap skeleton. |
| Tabs | Use existing shadcn tabs. Keep tab triggers stable in width and height; missing-data fallback appears inside content, not as disabled or hidden tabs. |
| Cache behavior | Cache all four subpaths only after output correctness passes. Partial legacy reports may be displayed defensively but never written as new cache entries. |

### Recruiting Lens

| Surface | Contract |
|---------|----------|
| Form priority | `/recruiting-lens` remains primarily a new-analysis form. Saved work appears below the form, never above it. |
| Required inputs | Company name, role title, and job description are mandatory. Submit is disabled until all three contain non-whitespace text. Labels are explicit: `Company name`, `Role title`, `Job description`. |
| Priors | Default to the most recent Resume Analysis and most recent LinkedIn source. Selectors remain visible and replaceable when priors exist. |
| Tutorial timing | Tutorial opens when the user begins the first job-analysis submission flow, before the first submission opportunity. It must not open on page load. It is skippable and dismissal persists in localStorage. |
| Tutorial content | Operational walkthrough only: company, role, JD, resume context, LinkedIn context, analyze. Use existing `Dialog` or modal pattern plus Framer Motion only if it matches current app motion. |
| Manual tutorial | A compact `View tutorial` button remains available after dismissal. It uses outline/ghost styling and does not compete with the primary CTA. |
| Saved tiles | Tiles below the form show company, role, match score, date, and compact status/context metadata. They are scannable summaries, not full report previews. |
| Saved tile click | Clicking a tile hydrates `/recruiting-lens?id=<run_id>` and shows the result in place. No separate read-only route. |
| Cache-hit saved state | Cache hits update or refresh the existing saved tile for the same company/role/JD cache key rather than duplicating it. Activity History still records the interaction. |
| Async fallback | If async fallback remains, UI must show a trackable pending/completed/failed state. If removed, UI must not present a background-processing promise. |

## Accessibility And Responsive Contracts

| Area | Contract |
|------|----------|
| Labels | Every new input has a visible label and programmatic association. Place helper copy below the field, not in placeholder-only text. |
| Disabled submit | Disabled state must be paired with visible missing-field cues so keyboard users know why submission is unavailable. |
| Tutorial dialog | Focus moves into the dialog, returns to the triggering control, and Escape closes unless a blocking backend operation is underway. |
| Saved tiles | Tiles are keyboard actionable (`button` or link semantics), have clear focus rings, and expose company + role + score in the accessible name or content. |
| Locked cards | Locked placeholders remain presentational and must not expose fake generated content as real recommendations to assistive tech. |
| Mobile | Forms stack in one column. Saved tile metadata wraps to two compact rows rather than overflowing. Tab labels must remain readable without horizontal text clipping. |
| Motion | Motion is subtle and respects existing app patterns. Do not add looping motion to operational surfaces. |
