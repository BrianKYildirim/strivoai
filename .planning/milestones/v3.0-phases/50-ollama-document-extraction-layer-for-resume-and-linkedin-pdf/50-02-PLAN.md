STRIDE register:
- Spoofing: none introduced; no auth path changes occur in this plan.
- Tampering: A migration that rewrites existing rows could alter user source material. Mitigation: only `ADD COLUMN IF NOT EXISTS`, comments, and nullable partial indexes; no UPDATE/backfill statements.
- Repudiation: Missing metadata would make provider debugging opaque. Mitigation: add concise metadata columns for accepted extraction runs while leaving legacy NULL rows explicit.

- Denial of service: Full-table indexes on nullable text could add unnecessary write cost. Mitigation: use partial index on `profiles.linkedin_pdf_text_hash` where not null; do not index jsonb metadata in Phase 50.
- Elevation of privilege: none introduced; RLS policies are not changed.

Block-on severity: high. Any backfill, deletion, RLS modification, or verbose payload storage is a blocker.
</threat_model>
