<decision_coverage>
- D-01: The browser facade preserves current client-side pdfjs extraction as the first upload attempt.
- D-02: Scanned/insufficient pdfjs output routes to backend fallback where Ollama runs before Claude OCR.
- D-05: Resume Upload, LinkedInGrader, and Onboarding use one shared frontend extraction facade.
- D-06: Frontend upload flows call the shared extraction layer and backend fallback.
- D-11: Normal UI keeps existing upload/analyzing states and does not expose provider metadata by default.
- D-17: Resume upload passes resumeId for accepted server persistence and LinkedIn uses the existing profile PDF source path.
- D-19: Extraction failure returns a specific operational error and writes no low-quality LinkedIn replacement source.
- D-21: Frontend population happens on upload/source replacement, not broad historical backfill.
</decision_coverage>

<threat_model>
Scope: browser PDF extraction facade and primary upload call sites.

STRIDE register:
- Spoofing: Frontend request bodies could attempt to select provider infrastructure. Mitigation: the helper must never send Ollama base URL, model, auth headers, or provider order; backend secrets own provider config.
- Tampering: Failed LinkedIn extraction could overwrite existing profile source. Mitigation: LinkedInGrader keeps replacement persistence after successful `grade-linkedin`; failed extraction/analyze writes nothing.
- Repudiation: User-facing UI should not show provider internals as normal state. Mitigation: provider metadata remains response/support data; normal UI keeps existing upload/analyzing copy unless a specific extraction failure must be shown.
- Information disclosure: Base64 page images are large and sensitive. Mitigation: strip data URL prefix for backend fallback where useful, cap pages/width, and do not log image payloads or full extracted text.
- Denial of service: Rendering too many pages can hang upload. Mitigation: helper uses bounded page caps from research, e.g. resume 8 pages and LinkedIn 12 pages, with explicit operational error if no images can be rendered.
- Elevation of privilege: resumeId is supplied only after authenticated resume insert; backend still enforces user_id.

Block-on severity: high. Frontend-supplied provider config, source overwrite before successful LinkedIn grade, or provider metadata badges in normal UI is a blocker.
</threat_model>
