<decision_coverage>
- D-07: The accepted extraction metadata returned by `extractDocumentFromPdf` is carried into profile replacement writes, including `textHash`.
- D-09: The persisted frontend metadata shape is concise and excludes prompts, images, raw provider responses, transcripts, and structured sections.
- D-11: Provider metadata remains persisted support data only; no normal Upload, LinkedInGrader, Profile, Onboarding, or Career Compass UI labels expose provider names.
- D-17: LinkedIn accepted text continues to write through `profiles.linkedin_pdf_content` and related profile source fields.
- D-20: Every accepted LinkedIn PDF replacement writes `linkedin_pdf_text_hash` and `linkedin_pdf_extraction_metadata`.
- D-21: Missing metadata on legacy rows is populated only when the user next replaces a LinkedIn PDF source.
</decision_coverage>

<threat_model>
Scope: browser-owned LinkedIn PDF extraction metadata and authenticated profile update payloads.

STRIDE register:
- Spoofing: A user could try to write metadata to another profile. Mitigation: preserve existing `.eq('id', user.id)` / `.eq('id', userId)` filters and do not add service-role or anonymous write paths.
- Tampering: Failed extraction or failed downstream analysis could overwrite good LinkedIn source metadata. Mitigation: write hash/metadata only in the same accepted-text update that already writes `linkedin_pdf_content`; keep LinkedInGrader's successful `grade-linkedin` gate unchanged.
- Repudiation: Support needs a concise record of accepted provider path. Mitigation: persist provider, attempted providers, quality status, document type, text hash, extracted timestamp, and optional fallback reason.
- Information disclosure: Persisted metadata could accidentally include prompts, page images, raw responses, transcripts, or extracted structured sections. Mitigation: add a single frontend serializer that allowlists fields and source assertions that reject disallowed keys in profile update payloads.
- Denial of service: Re-running extraction just to compute metadata would add latency. Mitigation: reuse the metadata already returned by `extractDocumentFromPdf`; do not add extra network calls.
- Elevation of privilege: Frontend must not choose provider infrastructure or bypass backend provider secrets. Mitigation: this plan does not add provider config to request bodies; frontend only persists accepted result metadata for the authenticated user's own profile.

Block-on severity: high. Cross-user profile writes, source overwrite after failed extraction, broad backfill, provider config in frontend, or normal UI provider labels are blockers.
</threat_model>
