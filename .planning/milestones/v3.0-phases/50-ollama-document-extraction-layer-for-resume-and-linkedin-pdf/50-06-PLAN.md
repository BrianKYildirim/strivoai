<threat_model>
Scope: secondary frontend callsite migration and source-level drift guard.

STRIDE register:
- Spoofing: same frontend provider-config risk as Plan 05. Mitigation: secondary pages use `extractDocumentFromPdf` and do not send provider config.
- Tampering: Career/Profile LinkedIn content could be overwritten by failed extraction. Mitigation: writes happen only with accepted text returned by helper; failed extraction preserves existing profile content.
- Repudiation: provider metadata should remain support data, not primary UI. Mitigation: tests assert no provider labels are rendered in normal secondary UI.
- Information disclosure: secondary pages must not log full extracted LinkedIn/profile text or base64 page images. Mitigation: keep existing logging limited to lengths/errors or remove noisy logs when touching call sites.
- Denial of service: secondary pages inherit helper page caps and backend timeout.
- Elevation of privilege: none introduced; profile writes remain `.eq('id', user.id)` from existing authenticated user context.

Block-on severity: high. Independent LinkedIn extraction systems, failed-source overwrites, or frontend provider config exposure is a blocker.
</threat_model>
