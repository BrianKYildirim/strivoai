<threat_model>
Scope: authenticated edge function extraction and database persistence.

STRIDE register:
- Spoofing: Callers could submit another user's resumeId. Mitigation: resume persistence must keep the existing `.eq('user_id', userContext.userId)` filter.
- Tampering: Failed extraction could overwrite good resume/LinkedIn text. Mitigation: persistence helper writes only when `ExtractionResult.ok === true` and accepted text is non-empty; all-fail returns an operational error and persists nothing.
- Repudiation: Provider/fallback path must be visible to support. Mitigation: concise metadata is persisted with provider, attempted providers, quality status, document type, text hash, extractedAt, and fallback reason.
- Information disclosure: Full extracted text or base64 images could leak to logs. Mitigation: log lengths/reason codes only; do not log full text/images/prompts.
- Denial of service: Adding Ollama before Claude can exceed request budgets. Mitigation: reuse Plan 03 timeout behavior and keep `invokeWithTimeout` compatibility from existing frontend callers.
- Elevation of privilege: Internal/backend callers must not bypass user ownership when writing. Mitigation: persistence helper requires userId for user-owned writes and separates resume/profile targets.

Block-on severity: high. Cross-user writes, persistence on failed extraction, breaking `ocr-pdf` OPTIONS/auth/rate limit behavior, or removing Claude fallback is a blocker.
</threat_model>
