<decision_coverage>
- D-04: Deterministic quality gates reject poor Ollama/provider output without a Claude validation call.
- D-05: Shared extraction types support one resume/LinkedIn extraction layer instead of split systems.
- D-07: ExtractionResult and ExtractionMetadata return accepted raw text plus required metadata fields.
- D-08: extractedTextHash uses SHA-256 over canonicalized accepted text through cache-fingerprint.ts.
- D-09: Metadata contracts exclude prompts, transcripts, verbose logs, raw responses, and image payloads.
- D-10: Types and helpers intentionally expose raw accepted text only, not structured resume/LinkedIn sections.
- D-19: Rejected quality results cannot produce accepted text for persistence/cache paths.
- D-20: Metadata includes concise support fields: provider, attempts, quality, fallback reason, and timestamp.
</decision_coverage>

<threat_model>
Scope: shared extraction result types, deterministic quality gates, and canonical text hashing.

STRIDE register:
- Spoofing: Provider identity in metadata could be forged by loose string types. Mitigation: define `ExtractionProvider = 'pdfjs' | 'ollama' | 'claude_ocr'` and force all later callers through that union.
- Tampering: Low-quality or file-metadata-only output could be persisted as user text. Mitigation: D-04 deterministic quality gates must reject too-short, symbol-heavy, repetitive, and missing-signal text before any accept() result exists.
- Repudiation: Support cannot tell which provider was accepted. Mitigation: metadata contract requires provider, attemptedProviders, qualityStatus, documentType, textHash, extractedAt, and concise fallbackReason.
- Information disclosure: Verbose provider transcripts, prompts, images, or full responses could leak into user rows. Mitigation: metadata type intentionally contains concise operational fields only; tests should assert no prompt/images/messages/response-style fields are produced by helper fixtures.
- Denial of service: Expensive validation could block extraction. Mitigation: gates are synchronous string heuristics only; no Claude validation call is allowed for Ollama quality per D-04.
- Elevation of privilege: none introduced in this plan; no auth or database writes occur.

Block-on severity: high. Any path that returns `ok: true` for empty/noisy/repetitive text or stores verbose provider payloads is a blocker.
</threat_model>
