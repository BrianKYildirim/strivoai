<threat_model>
Scope: server-side Ollama HTTP integration and provider orchestration.

STRIDE register:
- Spoofing: A caller could try to select an attacker-controlled Ollama host. Mitigation: `OLLAMA_BASE_URL`, model, timeout, auth header name, and auth secret are read only from Supabase secrets; request bodies never accept provider URLs or auth headers.
- Tampering: Provider output could be accepted despite low quality. Mitigation: the provider loop gates pdfjs/Ollama/Claude text through `assessExtractionQuality` before returning `ok: true`.
- Repudiation: Fallback reasons could be lost. Mitigation: each provider rejection appends a concise reason to provider attempts and top-level metadata.
- Information disclosure: Image payloads, prompts, or raw model responses could be logged. Mitigation: log only reason codes/status/lengths; do not log base64 images, full text, prompts, or raw Ollama responses.
- Denial of service: Ollama timeout plus Claude fallback could exceed gateway budgets. Mitigation: bounded `AbortController` timeout from `OLLAMA_TIMEOUT_MS` with default around 35000 ms and no unbounded retries.
- Elevation of privilege: none introduced; this helper does not bypass auth or write data.

Block-on severity: high. Frontend-supplied host/model/header, unbounded timeout, raw PDF sent to official Ollama vision, or no Claude fallback is a blocker.
</threat_model>
