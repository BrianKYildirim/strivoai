<objective>
Restore the production homepage by re-adding the `Zap` icon to the `lucide-react` import in `src/components/Navbar.tsx` and `src/components/TopBar.tsx`. Phase 48 (commit 58cbe85, Pro→Elite refactor) removed `Zap` from both import lines while leaving five legitimate `<Zap />` JSX usages in place (credit counter + "Upgrade Plan" link), causing `ReferenceError: Zap is not defined` at render → the `HomepageErrorBoundary` fallback on strivoai.net for logged-in users.

This plan also establishes the authoritative type-check gate the project lacked: `vite build` (esbuild) never type-checks and ESLint disables `no-undef` for TS, so only `tsc --noEmit` catches this class of error — yet there is no `type-check` script and `tsc` currently fails to even parse `tsconfig.app.json` (line 5 `ignoreDeprecations: "6.0"` is rejected as TS5103 by the installed TypeScript 5.9.3). The plan resolves that config snag and pins an exact, working verification invocation.

Purpose: Eliminate a live production crash with the minimal, correct change, and close the systemic verification gap that let the regression ship.
Output: Two restored imports, a corrected tsconfig value, a `type-check` npm script, and a proven-clean homepage/dashboard render path.
</objective>
