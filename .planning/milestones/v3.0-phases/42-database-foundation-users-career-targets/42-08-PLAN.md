<threat_model>
- **T-42-CUTOVER** — Atomic `saved_jobs` → `applications` cutover must not lose data. Mitigation: pre-migration count captured via SQL helper, embedded `DO $$` verification asserts `(SELECT count(*) FROM applications WHERE status='saved')` ≥ pre-migration `saved_jobs` count (captured at migration start via temp table); single transaction; DROP TABLE saved_jobs only after backfill succeeds; down-migration fenced as comment at top.
- **T-42-RLS** — Cross-user reads on 4 new tables. Mitigation: applications user-scoped FULL CRUD policies; outcomes via parent-join `application_id IN (SELECT id FROM applications WHERE user_id = auth.uid())`; job_descriptions SELECT-own only + service-role writes; benchmarks documented aggregate-read exception with `sample_size>=5` CHECK enforcing de-anonymization barrier at write time. Verification: DO $$ asserts policy counts (applications=4, outcomes=4, job_descriptions=1, benchmarks=1 SELECT-only).
- **T-42-BENCHMARKS** — `benchmarks` permissive SELECT to authenticated is a documented exception. Mitigation: CHECK `sample_size >= 5` at row level; documented in migration COMMENT ON TABLE; aggregate-only columns (no individual identifiers).
</threat_model>
