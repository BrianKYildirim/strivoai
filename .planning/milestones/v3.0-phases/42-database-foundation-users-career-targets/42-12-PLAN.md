<threat_model>
- **T-42-STORAGE** — ai-archives bucket per-user folder enforcement. Mitigation: 3 RLS policies on storage.objects (INSERT/SELECT/DELETE) all use `bucket_id='ai-archives' AND auth.uid()::text = (storage.foldername(name))[1]`; cross-user probe verified manually (Plan 42-13 fall-through reader tests).
- **T-42-DESTRUCTIVE** — run_lifecycle_sweep() deletes Storage objects (via Plan 42-13 reader/writer) AND nulls DB columns. Mitigation: delete-from-DB only happens AFTER archive_path is SET (transactional within sweep); job_descriptions table explicitly EXCLUDED from sweep; structured log per action; archive_path can be cross-referenced post-incident.
- **T-42-PHASE37** — Cache hit-rate regression risk on analysis_cache sweep. Mitigation: TTL guard `created_at < now() - 30d AND last_hit_at < now() - 7d` (SPEC-locked); Plan 42-13 includes cache-hit-rate regression rerun task asserting ≤5% absolute drop.
- **T-42-RLS** — Sweep function bypasses RLS by design. Mitigation: SECURITY DEFINER + REVOKE EXECUTE FROM PUBLIC; only pg_cron + service role can invoke; function body restricted to documented retention table behavior.
- **T-42-CRON** — Backfill in migration transaction may exceed statement timeout. Mitigation: chunked LIMIT 1000 outer loop pattern (per RESEARCH §Pitfall 8); operator runbook documents post-deploy operator-step alternative if dataset >10K rows.
</threat_model>
