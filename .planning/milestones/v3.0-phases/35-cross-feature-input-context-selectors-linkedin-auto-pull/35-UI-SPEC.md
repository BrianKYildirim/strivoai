# Phase 35 — UI Design Contract

> Visual and interaction contract for Phase 35: Cross-Feature Input Context (Selectors + LinkedIn Auto-Pull). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase introduces two reusable shadcn-`<Select>`-based pickers (`<PriorAnalysisSelector>` for resumes, `<PriorLinkedInSelector>` for LinkedIn sources), wires LinkedIn auto-pull into LinkedInGrader (LIG), defaults Recruiting Lens (RCL) to most-recent priors, and unifies empty-state cards across RCL / Interview Prep (IP) / Career Compass (CC).

**No net-new visual primitives.** Every surface in this phase composes existing shadcn primitives (`<Select>`, `<Card>`, `<Button>`, `<Skeleton>`, `<Badge>`) and existing semantic tokens. The contract below codifies copy, layout order, state machine, and exception handling — not new tokens.

Declared values (all multiples of 4, sourced from Tailwind defaults already in use across LIG/RCL/CC/IP):

| ----- | --------------------------------- | ------------------------------------------------------------------------------------- |
| xs    | 4px (`gap-1`, `p-1`)              | Icon-to-label gap inside `<Select>` items                                             |
| sm    | 8px (`gap-2`, `p-2`, `mt-2`)      | Compact element spacing inside selector items; gap between dropdown label and trigger |
| md    | 16px (`p-4`, `gap-4`, `mb-4`)     | Default form-element vertical rhythm; empty-state card inner padding                  |
| lg    | 24px (`p-6`, `mb-6`, `space-y-6`) | Selector block → manual input block separation; vertical rhythm between form sections |
| xl    | 32px (`p-8`, `mb-8`)              | Form-area outer padding inside page `<Card>` containers                               |
| 2xl   | 48px (`mb-12`)                    | Page-section breaks (used by host pages — not introduced here)                        |
| 3xl   | 64px (`py-16`)                    | Page-level top/bottom padding (host-page concern)                                     |

**Selector-specific spacing contract:**

* Selector label ↔ trigger: `mb-2` (8px)
* Selector trigger ↔ manual input below: `space-y-6` parent (24px) — selector is one item in a vertical stack, not a wrapper
* Dropdown item internal layout: `gap-2` (8px) between identifier, date, and score chip; `py-2 px-2` cell padding (matches `<SelectItem>` default)
* Empty-state card: `p-4` inner (16px), `space-y-2` between icon, heading, body, button (8px); card sits in the same vertical slot the selector would have occupied (no layout shift)

**Exceptions:** None. Every spacing decision uses the existing Tailwind scale.

## Selector Anatomy (normative)

A selector is one form row. Layout top-to-bottom:

```
[Label]  ← text-sm font-medium, mb-2
[SelectTrigger]  ← full width, h-10 (shadcn default), shows selected item's primary identifier + date
  └ on click → [SelectContent] (popover)
       [SelectItem × N]  ← one row per prior
         ├ left:  [identifier (file_name | linkedin filename | "LinkedIn profile {date}")] (text-sm font-semibold, truncated to 32 chars with ellipsis if longer — match RCL:641-643 convention)
         ├ mid:   [analyzed_at | created_at as "MMM d, yyyy"]  (text-xs text-muted-foreground)
         └ right: [score chip "{N}/100" OR "—"]                (text-xs, bg-primary/10 text-primary rounded px-2 py-0.5)
```

**Selector item — score chip rules:**

* Resume row: always shows `{overall_score}/100` (from `resumes.overall_score`)
* LinkedIn graded row: always shows `{overall_score}/100` (from `linkedin_grades.overall_score`)
* LinkedIn onboarding-PDF row: shows `—` (em-dash) in score slot — `profiles.linkedin_pdf_*` was never graded standalone per D-02

**Selector trigger collapsed display** (when an item is selected — which is the steady state since auto-default fires):

* Shows ONLY the primary identifier + date (`{file_name} · MMM d, yyyy`)
* Score chip is NOT shown in the trigger — only in the expanded list — to keep the trigger calm and consistent across selected-vs-not-selected states

**Truncation:** Identifiers longer than 32 chars get `slice(0, 32) + '...'`. Reuse the helper pattern from `RecruitingLens.tsx:641-643`.

**Loading state:** While priors fetch, render `<PriorSelectorSkeleton>` in the trigger's slot (full-width `<Skeleton>`, `h-10 rounded-md`). Do NOT show an empty disabled `<Select>` — that reads as "no priors exist" and is wrong.

**Default selection:** On first render with `priors.length >= 1`, the selector's `value` is set to `priors[0].id` (most-recent). No user click required.

**Selection invisibility (per D-07, aligned with Phase 29 D-13/D-14):** Once a prior is selected (either auto-default or explicit pick), the form input below it is populated from that prior's stored content. **No "Loaded from prior" badge, no "Using cached input" notice, no visual diff** — the form looks identical to a user who pasted/uploaded the same content fresh. Selection is a UX nicety, not a status.

## Empty-State Anatomy (normative)

When no priors exist for a required input, `<PriorSelectorEmptyState>` renders in place of the selector. Layout:

```
<Card className="bg-secondary/50 border border-border/50">
  <CardContent className="p-4 text-center space-y-2">
    [Icon: AlertCircle, w-8 h-8 text-muted-foreground mx-auto]
    [Heading: text-sm font-semibold text-foreground]
    [Body:    text-xs text-muted-foreground]
    [Button:  variant={blocking ? 'default' : 'outline'}, size='sm', mt-3]
  </CardContent>
</Card>
```

This shape is **already shipped** at `RecruitingLens.tsx:656-672` — Phase 35 lifts it into a reusable component and applies it across all four consumers.

**Blocking vs. non-blocking (per D-08/D-09):**

* **Blocking** (`blocking={true}`): Empty-state replaces the entire form. Submit button is not rendered. Used for missing **resume** in RCL/IP/CC. Button uses `variant="default"` (primary coral fill — pulls the user's eye to the upstream action).
* **Non-blocking** (`blocking={false}`): Empty-state replaces the LinkedIn selector slot only; rest of the form (resume selector, JD textarea, submit) renders normally. Used for missing **LinkedIn** in RCL. Button uses `variant="outline"` (border-only — secondary call to enrich, not block).

### Toast / error copy (selector-specific)

| Trigger                                                                                                    | Toast                                                                                                                                        |
| ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Selector prior-fetch fails (network)                                                                       | Silent — selector falls back to empty-state. Do NOT show a toast. The user's form is still usable via manual paste/upload. Log warn for ops. |
| LinkedIn PDF replacement post-grade UPDATE fails (per D-12)                                                | Silent — log warn. User already got their grade; next visit falls back to the prior `profiles.linkedin_pdf_*` row.                           |
| User explicitly picks a prior and the read of that prior's `extracted_text` / `linkedin_pdf_content` fails | `Couldn't load that analysis. Try another or paste your resume below.` — `sonner` `toast.error`, 4s                                          |

### Destructive confirmations

Phase 35 has **no destructive actions**. The selector never deletes a prior; the LIG replacement overwrites `profiles.linkedin_pdf_*` (a "replacement" not a "delete") only after a successful grade — that overwrite is intentional, expected, and matches the user's mental model (they uploaded a new PDF and it succeeded). No confirmation modal is needed.

## Interaction Contract

### Selector lifecycle

| Event                            | Frame  | Behavior                                                                                                                                                                      |
| -------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Page mount (no `?id=` deep-link) | 0ms    | Selector enters loading state (`<PriorSelectorSkeleton>` in trigger slot); priors-fetch query fires in parallel with profile fetch (host-page concern).                       |
| Priors-fetch resolves with N ≥ 1 | varies | Skeleton swaps to `<SelectTrigger>` with `priors[0]` selected; host form input is populated from `priors[0]` content. No transition animation needed beyond shadcn's default. |
| Priors-fetch resolves with N = 0 | varies | Skeleton swaps to `<PriorSelectorEmptyState>` (blocking or non-blocking per the table above).                                                                                 |
| Priors-fetch errors              | varies | Same as N = 0 (empty-state) — degrade silently per "Toast / error copy" rules.                                                                                                |
| User opens `<SelectTrigger>`     | click  | Radix popover opens with `<SelectContent>`. All N items rendered (no virtualization; max 10 per `AnalysisComparisonModal` precedent + 1 LinkedIn-onboarding row = max 11).    |
| User picks a different item      | click  | `onChange(newPrior)` fires; form input below repopulates from new prior's content; popover closes. **No toast, no badge, no animation.**                                      |
| Page mount with `?id=` deep-link | 0ms    | Selector is **not rendered** (deep-link owns state). Host page mirrors the `skipCacheRestore` pattern from `LinkedInGrader.tsx:202-203` and `CareerCompass.tsx:207-216`.      |

### LinkedInGrader auto-pull (CTX-01)

| Event                                                         | Behavior                                                                                                                                                                                                                                         |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| LIG mount, no `?id=`, `profiles.linkedin_pdf_content` present | Pre-fill `profileContent` state; set `inputMode = 'paste'`; textarea renders pre-populated and editable. **No banner**, no "Loaded from onboarding" badge — the textarea just has content.                                                       |
| LIG mount, no `?id=`, `profiles.linkedin_pdf_content` absent  | Existing empty-input behavior — user must paste or upload. No selector, no empty-state card (LIG has its own input flow).                                                                                                                        |
| User uploads a replacement PDF in LIG, parse succeeds         | Local state updates; no DB write yet.                                                                                                                                                                                                            |
| User clicks Analyze, `grade-linkedin` returns 200             | Frontend renders grade. **After** `jsonResponse()` returns, fire-and-forget `UPDATE profiles SET linkedin_pdf_content, linkedin_pdf_filename, linkedin_pdf_updated_at = now()` (see D-12). | `grade-linkedin` fails (any reason)                           | No `profiles` UPDATE. Onboarding PDF stays canonical.                                                                                                                                                                                            |
| `profiles` UPDATE fails transiently                           | Log warn (`console.warn('[LinkedInGrader] linkedin_pdf replacement UPDATE failed', err)`); no toast; no UI degradation.                                                                                                                          |

## Accessibility Contract

| Concern                    | Treatment                                                                                                                                                                                                               |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Selector label association | `<Label htmlFor>` linked to `<SelectTrigger id>` (shadcn `<Select>` handles ARIA via Radix; ensure `aria-label` or `<Label>` is present — Radix requires one)                                                           |
| Keyboard navigation        | Inherited from Radix `<Select>` (Space/Enter to open; Arrow keys to navigate; Esc to close). No custom keyboard handlers.                                                                                               |
| Focus visible              | Inherited `ring-ring` focus indicator from shadcn `<SelectTrigger>`. Do NOT remove `focus-visible:ring-*` classes.                                                                                                      |
| Empty-state CTA focus      | `<Button>` shadcn primitive provides focus ring. Place focus order: heading is read first via `aria-labelledby` (semantic `<CardHeader>` not required — the heading element is sufficient), then body, then CTA button. |
| Score chip color contrast  | `bg-primary/10 text-primary` — verify WCAG AA in both light and dark. If the 10% alpha tint fails AA in light mode, fall back to `bg-primary/15 text-primary` (still semantic, slightly more opaque).                   |
| Loading skeleton           | `<Skeleton>` already has `aria-hidden="true"` via shadcn defaults. Add `aria-live="polite"` to the parent slot so screen-readers announce when content loads.                                                           |
| LIG textarea auto-fill     | Pre-filled `<Textarea>` is a normal text input — no special ARIA. Do NOT autofocus the textarea on mount (that hijacks scroll on long pages).                                                                           |
