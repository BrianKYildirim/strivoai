<threat_model>
Surface: `grade-linkedin` system prompt (the text sent to Claude alongside user-supplied PDF profile content). No new auth surface.

Threats addressed by this plan:
- **Prompt-injection via PDF content (ASVS V5 / LLM01):** The profile text is user-controlled and may contain injection phrases or column-mangled sidebar text. The `_shared/prompt-sanitizer.ts` seam already strips high-confidence injection phrases before ingestion (unchanged by this plan). This plan hardens the SYSTEM prompt so the model (a) never treats sidebar/contact/footer artifacts as scored evidence (D-09..D-12), (b) never fabricates facts/metrics/tech even if the input suggests them (D-14/D-15), and (c) never emits an overall total the server would otherwise have to reconcile (D-02/D-20). These reduce the blast radius of a crafted profile that tries to inflate its own score.
- **Score fabrication via banned claims (integrity):** the prompt forbids unsupported platform-behavior / recruiter-visibility claims (D-16), keeping impact statements qualitative and defensible.

Note: the prompt is not a security boundary by itself — the schema/semanticCheck (Plan 01) is the enforcing gate. This plan is defense-in-depth at the generation layer. Block-on-high: do not remove the existing sanitizer call or the "server owns the total" instruction.
</threat_model>
