`maxScore` as clamp ceiling and total input — 08.3-REVIEW.md CR-01) is confirmed
closed by direct source read, not commit-message trust:

| Check | Evidence |
|-------|----------|
| maxScore pinned to catalogue | `schema.ts:55-57` adds `LINKEDIN_MAX_BY_NAME` (server-owned ceiling map); `schema.ts:171-177` superRefine hard-rejects any section whose `maxScore !== def.baseMax` — a wrong maxScore is a parse failure taking the existing retry-once path, never a silently accepted ceiling |
| No inflated-total path | Schema `.transform` (schema.ts:127-128) clamps `score` to `[0, catalogueMax]` where `catalogueMax = LINKEDIN_MAX_BY_NAME.get(s.name) ?? 0` — model maxScore no longer participates in the clamp; unknown section names clamp to 0 AND fail superRefine |
| No negative-total path | `Math.max(0, s.score)` floor retained; the negative-maxScore vector (`Math.min(-5, …) === -5`) is dead because the ceiling is the catalogue value, never the model's |
| Semantic equality still holds | `injectLinkedInRawScore` (validation.ts:86-100) mirrors the exact same catalogue clamp + `Math.round` BEFORE parse, so `linkedInSemanticCheck`'s `rawScore === normalizeFromSections(sections)` equality reflects catalogue-clamped integer scores by construction |
| WR-01 (integer scores) | `Math.round(...)` in both the schema transform (schema.ts:128) and the injector (validation.ts:95) |
| WR-02 (positional order) | superRefine now compares index-by-index against `LINKEDIN_SECTIONS` (schema.ts:158-167), subsuming the old name-set check — missing/renamed/duplicated/reordered sections all fail |
| index.ts touch in 251d755e | Comment-only (verified via `git show` — clamp-documentation wording), no behavior change outside schema.ts/validation.ts |
