# Phase 08.1 Plan 02: LinkedIn Grader 4-Section Shape Gate + Baseline Gate Summary

Added an explicit `isV5Grade` discriminator to `LinkedInGrader.tsx` that detects the new Phase-08.1 4-section grade shape (exactly 4 evidence-anchored sections named Headline/About/Experience/Education), wired it into `isRenderableGrade` so it is not dead code, and proved the full blocking `npm run verify:baseline` gate is green with the Plan-01 backend narrowing integrated — no render rewrite, no legacy backfill (D-05).

## What Was Built

- **Task 1 — `isV5Grade` discriminator (d12d8848):** Added `isV5Grade(grading_data): boolean` next to `isV4Grade`, keyed on `sectionBreakdown.length === 4` AND the section-name set being exactly `{Headline, About, Experience, Education}` (case-sensitive, mirroring `schema.ts` `LINKEDIN_SECTIONS`) AND the first section carrying `typeof applicable === 'boolean' && typeof evidence === 'string'`. A module-local `NEW_LINKEDIN_SECTION_NAMES` tuple backs the name check. Referenced it in `isRenderableGrade` (`isV3Grade || isV4Grade || isV5Grade`) so the new shape is explicitly recognized and the symbol is not dead. Documented in a code comment that this shape structurally OVERLAPS `isV4Grade` (a 4-section grade satisfies both) — expected, since isV5Grade is the explicit future-proof detector, not a mutually-exclusive gate; legacy v4 11-section records deliberately do NOT match (`length !== 4`) and keep rendering 11 cards. Updated the stale "v4 = 11" shape comments (the `LinkedInSection` interface doc, the `sectionBreakdown` inline note, the section-breakdown render comment, and the D-05 depth-gating comment) to name the third coexisting new-4-section shape without implying any legacy record is recomputed.
- **Task 2 — Full `verify:baseline` gate (green):** Ran all three legs with the Plan-01 4-section backend present in the working tree. Vitest **527 passed / 0 failed** (86 files); `test:edge` deno **1121 passed / 0 failed / 12 ignored**; Playwright **6 passed / 1 skipped** (the Stripe `4242` card-fill test is the standing quarantine skip, not a regression). No LinkedIn frontend test needed retargeting — as RESEARCH predicted, the LinkedIn `*.test.tsx` suites (output-parity, phase22 contract, PDF source, prior selectors) are shape-agnostic and passed unchanged. No test was loosened.

## Verification

- **`isV5Grade` correctly gates:** a new 4-section grade (`length === 4` + the 4 retained names + evidence fields) returns `true`; a legacy v4 11-section record returns `false` on the `length !== 4` guard (so it keeps rendering its original 11 cards — no collapse); a legacy v3 record (no `applicable`/`evidence`) returns `false` from isV5Grade but still passes `isRenderableGrade` via `isV3Grade`. D-05's "old shape renders old, new shape renders new, no backfill" invariant holds.
