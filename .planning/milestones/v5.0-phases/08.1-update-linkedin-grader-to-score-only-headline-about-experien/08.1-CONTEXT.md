# Phase 08.1: Update LinkedIn Grader to score only Headline, About, Experience, and Education - Context

**Gathered:** 2026-07-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Narrow the LinkedIn Grader's **Section-by-Section Breakdown** from the current 11 scored sections
down to **4 core scored sections: Headline, About, Experience, Education**. The overall score, band,
projected gains, comparisons (Compare to Previous), and semantic validation must all derive **solely**
from those four sections. The other 7 sections from the Phase 4 rubric (Skills, Projects,
Certifications, Achievements, Completeness, Career Positioning, Recruiter Discoverability) are removed
as independently scored cards and **removed from the prompt/schema entirely** (see D-01 below) — they
do not contribute to the overall score or projected gains.

This is a **scope reduction of an already-completed rubric redesign** (Phase 4's 11-section
context-aware-max system), not a new feature. Existing grading criteria/scoring logic for the 4
retained sections, existing design/layout/feedback structure/progress bars, and all surrounding page
functionality (Key Strengths, Next Best Action, priority improvements, copy, Compare to Previous,
analysis lifecycle/persistence/history/merits) must be preserved.

**Requirements:** Inherits FEAT-03 (deterministic evidence-based LinkedIn scoring, no fixed-score
sources) and VER-03 (weak/avg/strong/exceptional differentiation proof) from Phase 4 — this phase
re-scopes their target rubric to 4 sections instead of 11. No new requirement IDs; this phase is an
urgent roadmap insertion after Phase 8.

**Depends on:** Phase 8 (Paddle Retirement — complete).

</domain>

<decisions>
## Implementation Decisions

### 1. Non-core sections — drop entirely, 4-section prompt/schema only
- **D-01:** The 7 non-scored sections (Skills, Projects, Certifications, Achievements, Completeness,
  Career Positioning, Recruiter Discoverability) are **removed from the prompt and schema entirely** —
  the model is not asked to evaluate them at all. This is cheaper/faster (fewer output tokens) than
  keeping them as "internal diagnostics only."
- **Supersedes** the roadmap entry's permissive "their insights may remain as internal diagnostics
  only" language — user's explicit choice is the stricter of the two allowed options: full removal,
  not partial retention.

### 2. Top Fixes / Key Strengths / Next Best Action — scoped to the 4 sections only
- **D-02:** `topFixes`, `keyStrengths`, and `nextBestAction` must draw **only** from the 4 scored
  sections (Headline, About, Experience, Education). They must not reference Skills, Projects,
  Certifications, Achievements, Completeness, Career Positioning, or Recruiter Discoverability, since
  those sections no longer exist in the model's output at all (per D-01).
- Rationale: tightest coupling to what the user sees as cards — every fix/strength ties back to a
  visible score. Consistent with D-01 (no diagnostic-only data exists to reference).

### 3. Score bands — keep existing cutoffs unchanged
- **D-03:** The current recalibrated bands (Weak <50 / Average 50-69 / Strong 70-84 / Exceptional
  85-100, `LINKEDIN_SCORE_BANDS` in `schema.ts`) are **preserved as-is** — no re-calibration pass for
  the narrower 4-section rubric.
- Rationale: user's explicit choice, matching the roadmap's literal "preserve existing grading
  criteria/scoring logic" language. Lowest risk of UX drift. If differentiation later proves poor
  under the 4-section total, that is a follow-up concern, not part of this phase.

### 4. Point allocation for the 4 retained sections — keep relative weights, renormalized
- **D-04:** Keep today's `baseMax` relative weights for the 4 retained sections (Experience 18 /
  Headline 11 / About 11 / Education 4 in the current 11-section table) — Experience stays heaviest,
  Education stays lightest, in the same proportions. The existing `normalizeFromSections` math
  (`round(100 × Σ score_applicable / Σ max_applicable)`) already handles this correctly once the
  section catalogue is restricted to just these 4 — **no reweighting**, only restricting which
  sections exist.
- Rationale: user's explicit choice, most literal reading of "preserve existing grading criteria/
  scoring logic for the four retained sections." Requires zero new weighting rationale.

### 5. History / legacy grade rendering — dual-shape gate, no backfill
- **D-05:** Existing stored LinkedIn grades with 11-section `grading_data` (the Phase 4 "v4" shape)
  continue to render as-is (11 cards) in History / `?id=` rehydration / Compare to Previous. New
  grades produced after this phase render as 4 cards. **No backfill or collapse** of old 11-section
  data to a 4-section view.
- Implementation direction: extend the existing `isV3Grade` / `isV4Grade` shape-gate pattern in
  `LinkedInGrader.tsx` (L90-112) with a new shape check (e.g. `isV5Grade` for the 4-section shape,
  keyed on `sectionBreakdown.length === 4` and the 4 retained names) rather than mutating stored data.
- Rationale: user's explicit choice — matches the pattern already proven for v3-vs-v4 legacy handling.
  No data loss; old results stay viewable in their original shape; recomputing a 4-section total from
  11-section data would produce a **different** number than what was originally shown, which would be
  misleading.

### Claude's Discretion
- The exact discriminator logic for the new 4-section shape gate (field checks, naming — e.g.
  `isV5Grade`) — the invariant is "old grades render in their original shape, new grades render in the
  new shape," not a specific function name.
- Whether `sectionSchema.length(11)` in `linkedInGradeSchema` becomes `.length(4)` or is generalized —
  the invariant is the model must return exactly the 4 mandated sections, no more, no fewer (same
  strict no-masking contract Phase 4 established — a missing section is a hard parse failure, never
  silently coerced).
- Prompt rewrite specifics (`prompts.ts`) for the 4-section rubric — evidence-anchored band
  descriptors per section carry over from Phase 4's determinism work (D-02 in Phase 4 CONTEXT.md);
  this phase does not reopen that determinism design, only the section count.
- Whether `LINKEDIN_SECTION_NAMES` / `LINKEDIN_SECTIONS` in `schema.ts` is edited in place (removing
  the 7 non-core rows) or restructured — the invariant is the exported section catalogue reflects only
  the 4 retained sections.

</decisions>

<specifics>
## Specific Ideas

- This phase is explicitly a **reduction**, not a redesign — Phase 4's determinism work (evidence-
  anchored bands, stable cache key, no follow-up context, honest-low-score-for-absent-sections) all
  carries forward unchanged for the 4 retained sections. Do not reopen those decisions.
- The 7 removed sections are not "hidden" data still computed behind the scenes (per D-01) — they are
  fully removed from what the model is asked to produce. This is a genuine cost/latency reduction, not
  just a UI hide.
- Historical grades (v3 pre-Phase-4, v4 Phase-4 11-section) must remain viewable exactly as originally
  shown — never recompute a legacy record's total under the new rubric (per D-05).

</specifics>
