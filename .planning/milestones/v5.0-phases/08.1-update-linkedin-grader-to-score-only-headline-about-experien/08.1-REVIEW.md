## Warnings

### WR-01: User-facing loading-step copy still advertises removed Skills/Completeness sections

**File:** `src/pages/LinkedInGrader.tsx:207-214, 664-670, 822, 862-880`
**Issue:** This phase (D-01) removed Skills, Completeness, and 5 other sections from the model prompt and schema entirely — the grader genuinely no longer evaluates them. However, the two loading-step label lists still shown to the user during every "Grade my profile" run were not updated:
- `analysisSteps` (L207-214): `'Checking skills & endorsements...'`, `'Calculating profile completeness...'`
- `linkedInSteps` (L664-670, passed into `<UniversalAnalyzing steps={linkedInSteps} />`): `{ id: 'skills', label: 'Checking skills & endorsements', ... }`

Both arrays are actively rendered (button spinner label at L822, step list at L862, and the `UniversalAnalyzing` progress UI at L674-681) on every single analysis. Users will see the grader claim to check "skills & endorsements" and "calculate profile completeness" for a feature that, per this very phase's explicit design (D-01/D-02), no longer scores or reports on either. This is a genuine product-facing regression introduced by the scope reduction, not a pre-existing issue — the plan/summary make no mention of updating this copy, and it slipped through because the frontend plan (08.1-02) scoped its `read_first`/diff review to the shape-gate area (L90-113) rather than the full file.
**Fix:** Update both arrays to reference only the 4 retained sections, e.g.:
```ts
const analysisSteps = [
  'Reading your LinkedIn profile...',
  'Analyzing headline strength...',
  'Evaluating experience quality...',
  'Reviewing your About section...',
  'Checking education details...',
  'Generating personalized fixes...'
];
// ...
const linkedInSteps = [
  { id: 'read', label: 'Reading your LinkedIn profile', icon: <FileText className="w-5 h-5" /> },
  { id: 'headline', label: 'Analyzing headline strength', icon: <Target className="w-5 h-5" /> },
  { id: 'experience', label: 'Evaluating experience quality', icon: <Brain className="w-5 h-5" /> },
  { id: 'about', label: 'Reviewing your About section', icon: <Award className="w-5 h-5" /> },
  { id: 'fixes', label: 'Generating personalized fixes', icon: <Sparkles className="w-5 h-5" /> },
];
```

### IN-02: `sections()`/fixture helper interface still named `V2Section`

**File:** `supabase/functions/grade-linkedin/validation.test.ts:39`
**Issue:** The local helper interface is named `V2Section`, a naming holdover with no clear referent in the current (Phase 08.1) 4-section design — it's unclear whether "V2" means anything meaningful post-narrowing, and it could confuse a future reader trying to map it to the `isV3Grade`/`isV4Grade`/`isV5Grade` shape-versioning vocabulary used in `LinkedInGrader.tsx`, which uses an unrelated numbering scheme for a different concept (legacy render shapes vs. this test's fixture-builder shape).
**Fix:** Rename to something scoped to its actual purpose, e.g. `SectionFixture` or `LinkedInSectionInput`, to avoid confusion with the frontend's v3/v4/v5 grade-shape terminology.
