# Phase 08.1 Plan 01: LinkedIn Grader 11→4 Section Scoring Core Summary

Narrowed the LinkedIn Grader's scoring core from 11 sections to the 4 mandated ones (Experience, Headline, About, Education) in the single source of truth (`schema.ts`), rewrote the model prompt to match, and reconciled the four Deno test fixtures that hardcoded the 11-section shape — the grade-linkedin edge suite is green on the 4-section catalogue.

## What Was Built

- **Task 1 — `schema.ts` catalogue (5e064cab):** `LINKEDIN_SECTIONS` restricted to exactly 4 rows — Experience(18,core), Headline(11,core), About(11,core), Education(4,contextual). `sectionBreakdown.length(11)` → `.length(4)` in lockstep (Pitfall 3 — a stale `.length` would 500 every real grade). `superRefine`, `LINKEDIN_SECTION_NAMES`, `normalizeFromSections`, and `LINKEDIN_SCORE_BANDS` untouched (D-03/D-04); only the header + weighting-rationale comments reworded to describe the 4-section sum-44 catalogue.
- **Task 2 — `prompts.ts` rubric (7260b954):** `## SCORING ARCHITECTURE (11 sections)` → `(4 sections)`; the 4 retained band-descriptor blocks kept byte-identical (D-04); the 7 removed sections' band blocks + OUTPUT-SCHEMA example objects deleted (D-01); `Include ALL 11 sections` → `ALL 4 sections`; the `applicable:false` in-prompt example retargeted off the now-gone 'Projects' onto Education (D-02 hygiene); header/doc comments reworded. `buildUserMessage` arity unchanged (2); no calibration anchors / follow-up block introduced.
- **Task 3 — Deno fixtures (af42256a):** `validation.test.ts` (length 4 / sum 44 / slice(0,3) too-few / D-01 Projects→Education / makeGrade rename / retitles); `prompts.test.ts` (`SECTION_NAMES` reduced to the 4 retained + "all 11"→"all 4"); `distribution.test.ts` (four-band score maps recomputed over 4 sections → 25/59/77/93 with adjacent gaps 34/18/16 and none in 48-58; D-01 Projects→Education); `runtime-validation-convergence.test.ts` (UNEVEN_SCORES + NON_APPLICABLE Projects→Education, 11-section labels → 4-section).
