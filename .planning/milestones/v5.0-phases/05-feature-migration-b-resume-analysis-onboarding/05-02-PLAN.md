<objective>
Give the high-traffic Resume Analysis streaming path a persistent lifecycle record + idempotency key WITHOUT any quality or latency regression (FEAT-02, preserve-exactly). This is the one deep-design spot the research flagged: the LOCKED request/response executor cannot wrap an SSE stream, so a thin streaming-aware wrapper orchestrates the same lifecycle RPCs + withMerits seam + resume validation seam DIRECTLY in the exact order the executor enforces, while the TransformStream token path stays byte-identical. It also closes the confirmed idempotency gap at analyze-resume:728 (today every resume deduction is non-idempotent) and disables duplicate active submission on the frontend.

Purpose: FEAT-02 — streaming path gains financial safety (idempotent charge, refund-exactly-once-pre-saving, settle-on-saved), run_id-backed refresh/navigation recovery, and a mid-stream-overload → retryable_failed path (subsuming the dead 529→queue fallback), with SUCCESS output byte-identical.
Output: A dormancy-capable streaming wrapper + frontend attemptNonce/submit-lock/run_id recovery. Ships dormant (byte-identical legacy while ANALYSIS_LIFECYCLE_RESUME / VITE_FEATURE_ANALYSIS_LIFECYCLE are OFF).
</objective>
