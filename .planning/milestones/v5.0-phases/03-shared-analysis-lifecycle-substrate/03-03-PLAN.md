  <files>supabase/functions/_shared/llm-validation.ts, supabase/functions/_shared/llm-validation.test.ts</files>
  <behavior>
    - validateModelOutput(rawText, zodSchema, opts) returns a discriminated union: {ok:true; value} | {ok:false; code: AnalysisErrorCode; detail: string}.
    - Wrapper removal: markdown-fenced / prose-wrapped JSON is unwrapped via json-repair before parsing.
    - Truncation: an unterminated / clipped JSON body → {ok:false; code:'MODEL_OUTPUT_TRUNCATED'} (never a partial-but-accepted object).
    - Empty/generic: empty string, "{}", or an all-null/all-default object → {ok:false; code:'MODEL_INVALID_RESPONSE'}.
    - Schema failure: zod.safeParse failure (missing required field, wrong type, out-of-range) → {ok:false; code:'SCHEMA_VALIDATION_FAILED'} carrying a SAFE detail (field path only, never the raw model body).
    - Semantic hook: an optional superRefine/opts.semanticCheck runs feature-specific checks; failure → SCHEMA_VALIDATION_FAILED.
    - NO MASKING: on every failure path the function returns a typed error — it NEVER returns {ok:true} with a fabricated / fixed / empty / generic value (Pitfall 9). A static test asserts the source contains no default-value substitution on the failure branches.
    - Safe logging: validation failures log a reason code + field path, never the raw model output/prompt.
  </behavior>
