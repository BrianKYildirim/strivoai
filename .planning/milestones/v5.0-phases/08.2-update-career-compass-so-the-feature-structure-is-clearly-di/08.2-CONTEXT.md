# Phase 08.2: Update Career Compass so the feature structure is clearly differentiated between Free and Elite users - Context

**Gathered:** 2026-07-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Restructure Career Compass so Free and Elite feature sets are clearly and explicitly differentiated:

- **Free:** Career DNA, Career Fields, Recommended Industry Roles, Surprise Fits
- **Elite adds:** Skills Gap Analysis, Personalized 12-Month Roadmap, Career Comparison (fit score, why it matches, what user has, what is missing, main barriers, actions needed)
- **Remove entirely:** Resume Improvements (backend prompt + schema + frontend types, not just UI hiding)

This is a restructure of an already-live feature (Career Compass shipped dormant→live in Phase 6). Salary (Compensation Intelligence) and Strategy (Smart Application Strategy) tabs are explicitly **out of scope** — they are not part of the requested structure and are left untouched.

</domain>

<decisions>
## Implementation Decisions

### Tab/section fate
- **D-01:** Salary (`CompensationIntelligence`) and Strategy (`SmartApplicationStrategy`) tabs are **kept exactly as-is, untouched** — not part of this restructure, not folded into Career Comparison. They remain elite-only tabs alongside the newly restructured sections.
- **D-02:** Keep the current page layout pattern: Free items (Career DNA, Career Fields/Best Fit Roles, Surprise Fits) stay as always-visible top-of-page cards exactly as today; Elite items (Career Comparison, 12-Month Roadmap, new Skills Gap Analysis) live as tabs, alongside the existing Salary/Strategy tabs.

### Career Comparison & 12-Month Roadmap (rename & extend existing)
- **D-03:** The existing **Readiness tab becomes "Career Comparison"** — extend, don't rebuild. Keep `RoleReadinessBreakdown`'s existing fields (`overallScore` → fit score, `strengths` → what user has, `gaps` → what's missing, `readinessVerdict`) and add new fields to the schema/prompt/types for `whyMatch`, `mainBarriers`, and `actionsNeeded` to satisfy the full requested spec (fit score, why it matches, what user has, what is missing, main barriers, actions needed).
- **D-04:** The existing **Roadmap tab becomes "Personalized 12-Month Roadmap"** — same underlying `roadmap`/`roleRoadmaps` data and components, relabeled/reframed around a 12-month arc (copy/title change; confirm during planning whether prompt should be adjusted to explicitly bound roadmap phases to 12 months or if existing phase structure already fits).
- Component renames: `ReadinessTab` → reflect "Career Comparison" naming (rename component/tab label — planner to decide exact file rename vs. label-only change); `RoadmapTab` → reflect "12-Month Roadmap" naming similarly.

### New Skills Gap Analysis section
- **D-05:** Build as a **simple prioritized list** — one card/section listing each skill gap with a priority badge (High/Medium/Low) and recommended action. Reuse the existing `SkillGap[]` shape (`{skill, priority, action}`) already defined in `career-validation.ts`/`types.ts` and already generated by the backend (just never rendered) — no new backend fields needed for this section specifically.
- This is a **new tab** in Career Compass, distinct from the unrelated standalone `SkillsGapAnalysis.tsx` page/feature (different feature, different edge function `analyze-skills-gap` — do not conflate or merge).

### Resume Improvements removal (full backend removal)
- **D-06:** Full removal, following the Phase 08.1 LinkedIn Grader precedent (D-01 there): drop `resumeImprovements` from the prompt rubric text (`analyze-career/index.ts` ~L1694), the JSON schema example (~L1699), the Zod schema (`_shared/career-validation.ts`), and the `ResumeImprovement`/`resumeImprovements` type definitions (`career-compass/types.ts:44-48,86`). The model must never be asked to generate this content.
- **D-07:** Apply the same tier-gating-in-prompt pattern already proven for `compensationIntelligence` (the existing `isElite` ternary at `index.ts:1699`) to the new Elite-only additions where practical — i.e., Free-tier backend calls should not pay generation cost for Elite-exclusive content where it can be cleanly separated. Planner should assess how much of Career Comparison's extended fields (`whyMatch`/`mainBarriers`/`actionsNeeded`) and Skills Gap Analysis can be gated this way vs. what must remain generated for all tiers because Free-tier UI doesn't currently show them but the underlying data (e.g., `skillGaps`) may still be needed elsewhere.

### Legacy stored data
- **D-08:** **Defensive rendering, not dual-shape.** Unlike the 08.1 LinkedIn precedent (which kept a full dual-shape v3/v4 render path), Career Compass should render new components conditionally based on field presence: if an old stored analysis lacks `whyMatch`/`mainBarriers`/`actionsNeeded` on `roleReadinessBreakdown`, simply omit those rows/fields rather than preserving an entirely separate old layout. No backfill/migration of historical rows.
- Old stored analyses that still have `resumeImprovements` populated should simply not render it anywhere (already true today — no component reads it) — no special handling needed there beyond deleting the type.

### Claude's Discretion
- Exact component/file rename strategy for `ReadinessTab`→Career Comparison and `RoadmapTab`→12-Month Roadmap (rename files vs. rename only labels/props) — pick whichever keeps the diff smallest and consistent with existing naming conventions.
- Whether the 12-month roadmap prompt needs new copy to explicitly frame content in 12-month terms, or if existing phase-based roadmap structure already satisfies "Personalized 12-Month Roadmap" framing — assess against current prompt output during planning/research.
- Precise placement/styling of the new Skills Gap Analysis tab relative to other elite tabs (Skills Gap, Career Comparison, 12-Month Roadmap, Salary, Strategy) — pick an order that reads naturally.

</decisions>
