<objective>
Remove `resumeImprovements` entirely from Career Compass's backend generation surface (prompt rubric text, JSON skeletons, offline test mock, server-side tier whitelist) and add three new Career-Comparison fields (`whyMatch`, `mainBarriers`, `actionsNeeded`) to `roleReadinessBreakdown` in every live Pro/Elite prompt-construction call site, per CONTEXT.md D-03/D-06.

Purpose: D-06 requires full backend removal (not UI hiding) so the model is never asked to generate Resume Improvements content. D-03 requires the existing Readiness/"Career Comparison" data contract to carry the full requested spec (fit score, why it matches, what user has, what's missing, main barriers, actions needed) — `overallScore`/`strengths`/`gaps`/`readinessVerdict` already exist; `whyMatch`/`mainBarriers`/`actionsNeeded` are new.

Research confirms there are TWO live call sites that independently define this shape: (1) `_shared/career-prompts.ts` `_buildProJsonSkeleton()` via `loadPromptVariant('career', tier, ...)` — the primary parallel-call path; (2) `analyze-career/index.ts`'s "legacy path" (~L1645-1701, commented MIG-05 but still reachable for ordinary cache-miss paid-tier requests) — CONTEXT.md's own line references point here. Both must change identically. `buildFreePriorAnalysesPrompt()` and `handleMultiRoleComparison()` are explicitly OUT of scope for this plan (see Open Questions 2/3 resolution in RESEARCH.md — Free tier already correct; multi-role compare intentionally left unextended, covered defensively by frontend conditional rendering in plan 08.2-05).

Output: Backend prompt/schema/whitelist/mock-fixture all describe the same new Career Comparison shape, with `resumeImprovements` gone.
</objective>
