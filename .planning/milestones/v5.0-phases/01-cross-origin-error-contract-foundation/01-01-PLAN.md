<objective>
Rewrite the centralized CORS chokepoint so every Edge Function resolves allowed origins from one env-driven `ALLOWED_ORIGINS` allowlist (replacing the single-origin `APP_URL` source), reflects an approved request `Origin` with `Vary: Origin`, omits `Access-Control-Allow-Origin` (fail-closed) for unapproved origins, and exposes two new construction primitives — `withCors` (guarantees CORS on every exit, including thrown Responses/Errors and preflight) and `jsonError` (additive, frontend-readable error envelope). Also fix the one response path that lacks CORS today: `auth.ts`'s `unauthorizedResponse()`. This is the interface the function rollout (Wave 2) and the audit (Wave 3) consume.

Purpose: Fixes both confirmed defects at their single source — Bug 1 (single static `APP_URL` origin blocks `www.strivoai.net`) and Bug 2 (CORS-less 401s the browser swallows) — without touching any of the ~80 inline `corsHeaders` call sites, by keeping the exported surface stable and overlaying correct CORS via `withCors` at each entrypoint in later plans.
Output: A request-aware `_shared/cors.ts`, a table-driven `_shared/cors.test.ts`, a CORS-tagged `_shared/auth.ts` 401, and the `ALLOWED_ORIGINS` env documentation.
</objective>

export type CorsType = 'user' | 'internal' | 'webhook';

// Backward-compatible shim: existing { type, extraHeaders } first arg PRESERVED; NEW optional req second arg.
// When req is provided AND its Origin is on the allowlist -> include Access-Control-Allow-Origin: <that exact origin>.
// When req absent OR Origin not allowlisted -> OMIT Access-Control-Allow-Origin (still returns Allow-Headers/Methods/Vary for 'user').
// internal/webhook -> {} unchanged.
export function corsHeaders(opts: { type: CorsType; extraHeaders?: string }, req?: Request): Record<string, string>;
export function handleOptionsRequest(opts: { type: CorsType; extraHeaders?: string }, req?: Request): Response;

// NEW: wraps a function handler; guarantees CORS on every exit.
export function withCors(
  req: Request,
  type: CorsType,
  handler: () => Promise<Response> | Response,
  opts?: { extraHeaders?: string },
): Promise<Response>;

// NEW: additive, frontend-readable error envelope. body = { error, ...extra }. Top-level `error` is always a string.
export function jsonError(
  req: Request,
  status: number,
  error: string,
  extra?: { message?: string; resetDate?: string; tier?: string; code?: string; retryable?: boolean },
): Response;
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Edge Function | Untrusted cross-origin request; the server's CORS response headers decide whether the browser exposes the body. |
| Env/secret store → cors.ts | ALLOWED_ORIGINS value is operator-set per environment; code trusts it as the allowlist. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | corsCore origin reflection | mitigate | Echo Origin ONLY on exact-string allowlist membership; omit ACAO otherwise (no reflect-all). |
| T-01-02 | Elevation of Privilege | ACAO on authenticated endpoints | mitigate | Never emit `Access-Control-Allow-Origin: *`; exact-origin echo only; no ACAC (no cookies). |
| T-01-03 | Tampering | CDN/browser cache keyed without Origin | mitigate | Emit `Vary: Origin` on every origin-dependent response (success, error, preflight). |
| T-01-04 | Information disclosure | jsonError / 401 body | mitigate | Keep `{ error: 'Unauthorized' }`; withCors Error→500 uses a generic message; additive code/retryable only, no internal detail/stack. |
| T-01-05 | Repudiation / debug-DoS | opaque CORS errors hiding real failures | mitigate | CORS on every error path so the real 401/402/429 surfaces (root-cause, not masking). |
| T-01-SC | Tampering | dependencies | accept | No package installs — in-repo Deno std only (REQUIREMENTS Out of Scope: no CORS libs). |
</threat_model>
