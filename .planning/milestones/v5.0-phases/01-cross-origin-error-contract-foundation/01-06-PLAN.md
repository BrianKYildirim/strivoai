export function withCors(req: Request, type: CorsType, handler: () => Promise<Response> | Response, opts?: { extraHeaders?: string }): Promise<Response>;
// withCors short-circuits OPTIONS -> origin-aware preflight; overlays CORS on the handler's success/error Response.
// For an allowlisted Origin, ACAO === that exact Origin.
</interfaces>

<why_these_differ>
Unlike the other 18 user functions, these three are invoked in their unit tests as the BARE handler (handleCreateCheckoutSession(req, deps)), bypassing the serve-level wrapper. After 01-01, the handlers' inline req-less corsHeaders calls emit NO ACAO, so the existing `assertEquals(res.headers.get('Access-Control-Allow-Origin'), APP_URL)` lines would fail. The fix (RESEARCH Open Question #3, applied narrowly here): wrap the serve entrypoint with withCors for prod, and update the ACAO-asserting test cases to drive the handler through withCors with an allowlisted Origin — testing the real prod path. Do NOT thread req into handler internals (avoids churn across many response sites).
</why_these_differ>
</context>
